# Changelog

本发布单元的所有重要公开变更均记录于此。

> 0.1.0 起为 SteamHarness 发布线（包名 `steamharness` / `@steamharness/cli`，MIT）；此前条目属于更早的发布线，仅作历史参考。

## 历史发布线 0.1.1 - 2026-07-29

### 变更

- 变更 CLI 改为独立版本和独立 tag 发布，并通过 peer dependency 声明兼容的 Core 范围。

## 历史发布线 0.1.2 - 2026-07-30

### 破坏性变更

- 项目打包只读取根目录 `.steamharnessignore`，其它忽略文件不再生效。
  迁移：在 `.steamharnessignore` 中显式排除凭据、依赖目录和临时文件。

### 新增

- 新增 `workspace pack`、`upload`、`publish` 和 `download` 支持 Kanban 静态项目，无损传输二进制资源。

## 历史发布线 0.1.3 - 2026-08-07

### 新特性

- **全局 `--locale` 开关**：切换本地与 Workspace 输出，并传递给 Server 和 Workflow runtime。
- **`--entrypoint` 参数**：本地与远程命令均可指定入口，省略时使用默认入口。参见 [CLI](../docs/cli/steamharness.mdx)。

### 破坏性变更

- 项目组打包与下载排除 PersistentValue 数据和 CLI 登录凭据，并逐包校验 SHA-256。
  迁移：自引用、锁不一致或内容被修改的响应会被拒绝，需重新生成依赖锁。

### 新增

- 新增 全局 `--locale <zh-CN|en>` 切换输出语言，项目可用 `workflow.getRuntimeLocale()` 读取。
- 新增 本地 `run`、`json`、`resolve-params` 与远程 `run`、`debug-node` 支持 `--entrypoint <id>`。
- 新增 `structure` 校验并输出按入口、时区、时间窗口或 Cron 声明的计划建议。
- 新增 Workspace 命令按精确依赖锁交付和恢复 Kanban 项目组，不传输宿主数据。

### 变更

- 变更 发布日志同步维护中英文内容，Docs 按当前文档语言展示对应版本。

## 历史发布线 0.1.4 - 2026-08-24

### 新特性

- **按平台下载发行版**：`workspace download` 发送当前平台并把 `latest` 解析为该系统最新兼容版本。
- **按版本选择发行目标**：`workspace upload/publish` 可为不可变版本选择 Server runtime 与 Desktop 下载目标。

### 破坏性变更

- Desktop 本地运行事件环境变量改为 `STEAMHARNESS_DESKTOP_RUNTIME_EVENTS`。
  迁移：旧 `STEAMHARNESS_APP_RUNTIME_EVENTS` 不再生效，替换为新变量名。

## 历史发布线 0.1.5 - 2026-08-26

### 修复

- 修复 日期版 Alpha Core 按项目声明的 caret 范围兼容同一 minor 的更高 patch，避免兼容升级被误判不支持。

## 历史发布线 0.2.0 - 2026-08-26

### 破坏性变更

- CLI 升级到 0.2.0 并精确绑定 Core 0.2，执行前校验 CLI 与项目的精确 Core 声明。
  迁移：只允许相同 `major.minor` 兼容线，该线上的任意 patch 可直接运行。
- 本地运行按项目 `dataStorage.mode` 配置明确的本地/服务器存储上下文。
  迁移：缺少声明或非法跨位置访问会直接失败，需在项目中补齐 `dataStorage.mode`。

## 历史发布线 0.2.3 - 2026-09-01

### 新特性

- **本地 MCP 入口**：`steamharness mcp <workflow-dir>` 把每个 entrypoint 暴露为标准 stdio MCP tool。
- **关联项目访问**：`--related-project` 显式启用双方已确认的关联项目 KV 访问。
- **MCP 生命周期上报**：由 Desktop 无窗口启动器托管时，CLI 经独立 IPC 上报完整快照。参见 [CLI](../docs/cli/steamharness.mdx)。

### 破坏性变更

- 移除 `--grant-data-access` 与 Kanban `dataSources` 授权流程。
  迁移：项目组依赖改由双方确认的 `steamHarness.projectInfo.relatedProjects` 生成。
- `workspace upload --create` 要求 package 预先声明顶层 UUID 与 `dataStorage.mode`。
  迁移：不再由 Server 分配或回写项目 ID。

### 新增

- 新增 `steamharness mcp <workflow-dir>`，把每个 entrypoint 暴露为标准 stdio MCP tool。
- 新增 本地运行支持可重复的 `--related-project <alias>=<绝对项目目录>`。

### 变更

- 变更 本地 `kv.*` 与 `persistentValue.*` 直接绑定当前项目，不再经过全局作用域。
- 变更 Desktop 无窗口启动器托管 MCP 时，CLI 经独立 IPC 上报同一 runId 的生命周期快照。
- 变更 stdio stdout 只承载 JSON-RPC，原始 input、CLI args、report、stdout 与 stderr 保留在快照中。

### 修复

- 修复 MCP 表单 elicitation 返回非法内容或传输、恢复失败时终止等待中的运行并记录诊断。
- 修复 OpenAI Responses 内部 runner 不再把 AI SDK 可选参数兼容性 warning 写入 `stderr`。
- 修复 `steamharness structure` 在静态分析前校验完整 `projectInfo` 合同，不支持字段返回退出码 `1`。

## 历史发布线 0.2.4 - 2026-09-05

### 新特性

- **关联项目的知识库与入口**：`--related-project` 现在可读目标项目知识库并调用其授权入口。
- **软链接调用修复**：pnpm 等软链安装下 `steamharness structure .` 不再空跑并以退出码 0 假通过。
- **状态页显示真实服务器**：`workspace status` 新增 `effective` 字段，说明命令实际会用哪台服务器。

### 破坏性变更

- CLI 不再有 `--web-runtime` / `--no-web-runtime`，`web` 发行目标随中继与 Web 入口一并删除。
  迁移：浏览器里的运行由 Desktop 首页的 Web 构建承担；继续传这两个选项会明确报错而非静默忽略。
- 服务端位置的关联项目目标只交出 KV，知识库与入口调用会以明确错误说明本机无法抵达。
  迁移：把目标项目改为 `local` 位置，或把需要的能力放到本地可运行的入口。
- 本地关联项目只在配置了持久值目录时开放知识库，且与目标子运行共用同一个目录。
  迁移：显式传入 `--persistent-value-store-dir` 或设置 `STEAMHARNESS_PERSISTENT_VALUE_STORE_DIR`。

### 新增

- 新增 CLI 识别视频 output item，普通文本输出显示成片链接，JSON 输出保留结构化描述对象。
- 新增 `--videos` 读取默认对话的视频文件引用，并识别常用视频路径的 MIME。
- 新增 CLI 运行时支持带音频控件的 file 参数和音频文件引用。
- 新增 `workspace status` 输出 `effective`，说明实际使用的服务器、凭据来源和取值优先级。
- 新增 关联项目可读目标项目的知识库，按 `grantToRelatedProject` 的 `knowledge` 声明逐 key 授权。
- 新增 关联项目可调用目标项目授权的入口，参数即该入口 `createInput` 解析的命令行参数。
- 新增 `structure` 保留 Workflow entrypoint 的可选 `group` 展示元数据。

### 变更

- 变更 项目组 `workspace upload` 改为返回 `202` 与 `jobId` 并轮询部署状态，不再同步等待构建。
- 变更 依赖的 `steamharness` 升到 dev 通道版本，系统 AI 的模型属性改由 Server 的模型目录提供。
- 变更 模型 effort 档位按模型声明的支持范围收敛，上下文用量分母取模型真实窗口。
- 变更 宿主传来的图片附件引用经工作流文件存储解析后再进入模型，读不出时明确失败。
- 变更 远程运行使用版本入队时固化的 Runner 制品和镜像 digest，不被后续上传覆盖。

### 修复

- 修复 经软链接调用时 CLI 不再空跑，比较 `process.argv[1]` 的原始形式与解析后的真实路径。
- 修复 关联项目的存储根与目标子运行现在指向同一个目录，不再一边写一边看不见。
- 修复 关联项目入口调用失败时抛出该入口自己的错误信息，不再被当成空结果。
- 修复 关联项目入口调用不再只对 `local` 目标可用，`server` 位置的入口照常读写服务端。
## 0.1.1 - 2026-10-18

### 变更

- 以 SteamHarness 包名重新发布：`steamharness` 从 0.1.0 起独立版本线，
  不与更早的发布线保持兼容。
- 发布改由 GitHub Release 触发，使用 npm Trusted Publishing（OIDC）完成，不再需要长期令牌。
- 运行时依赖改为 peer 声明 `^0.1.0`，安装时给出明确的兼容范围。

## 0.1.2 - 2026-10-27

- 【变更】最低 Core 依赖提升至 `steamharness@0.1.2`，新建项目使用配套的 CLI 与 Core 版本。

- 【修复】宿主可单独传递系统 AI 认证，普通项目与小助手的首次连接、账号刷新和退出使用同一校验；兼容旧宿主的连接格式，避免 Studio 给旧版项目 CLI 传入仅限小助手的字段而导致启动退出。

- 【修复】Studio 内置小助手使用固定的本机应用身份，不再要求每个用户注册个人项目或重新申请 ID。检查成功后自动隐藏提示；会话、记忆和配置保存在本机，不再查询或发布普通项目的云端配置。服务器 AI 继续使用账号授权，普通项目和关联数据的注册与权限检查保持有效。

- 【修复】应用重新检查会读取最新关联声明与存储模式，不再被已移除关联的旧错误阻塞；服务重启后的旧状态及子页面消息不会覆盖当前检查结果。看板检查期间暂停预览和页面方法，页面恢复不会提前加载；完整检查较慢时不再误报断线。本地存储应用也可确认申请新 ID，工作流和会话可沿用执行器识别的类型，内置助手保留系统管理的身份。

- 【改进】看板、工作流和会话在打开时统一检查当前应用与关联项目的服务器注册、导入及关联声明，无需先运行或发消息。应用检查清单提前展示进度和待处理项，全部通过后自动隐藏整个检查区，发现问题时重新显示；本地功能保持可用，重新检查不自动重放操作。

- 【改进】未注册项目需确认重新申请服务器签发的新应用 ID，并安全写回本地清单；新旧历史和数据隔离，不上传源码或继承旧授权。三类项目统一处理，上传仅在显式 --create 时为单个项目申请新 ID，项目组不隐式改 ID。

- 【修复】项目模板可按实际安装的 SDK API 匹配未修改的源码，兼容已发布版本与当前源码的命名差异；保留用户修改，项目检查返回具体脚本校验诊断，避免安装成功后只看到笼统的校验失败。

- 【修复】本地关联调用缺少导入时显示导入引导，导入后需重新检查并手动重试。看板数据与更新检查使用已核验的导入目录，支持项目组以外的目录；显式绑定失效时不改用同 UUID 的其他副本。

- 【改进】看板、工作流和会话的关联项目引导先核验本地导入状态，未导入时只提示导入，已导入后再提示服务器访问或数据授权。关联问题使用紧凑提示与可展开的连接详情，和当前项目缺失提示区分；导入变化实时更新，重新检查会复核目录 UUID，不自动修改项目或授权。

- 【改进】看板、工作流和会话的服务器引导仅保留“重新申请应用 ID”和“重新检查”，移除上传源码、账号 / 服务器入口，以及切换服务器的操作提示。

- 【修复】项目配置添加或编辑模型时，当前选中的 AI 来源使用主题强调色高亮，未选中项保持普通背景，悬停及切换后与实际表单一致。

- 【修复】看板、工作流和会话支持确认后重新申请服务器签发的新应用 ID 并替换本地 ID，不上传源码；`both` 模式实际访问服务器失败时准确显示对应项目及关联授权引导，保留本地操作能力，恢复不重放运行或排队输入。

- 【修复】默认 Server 地址随 dev、alpha、main 渠道选择，dev 使用 localhost:7126；空登录地址正确回退，显式连接继续优先。

- 【修复】通过运行快照启动和恢复的项目继续遵守源码系统 AI 限制与官方模板字段锁定，不能通过传入旧快照绕过。

- 【新增】配置列表按项目角色过滤并展示能力、权限及正在使用的状态；访客只编辑开放值，模式随配置只读显示，权限变化保留编辑草稿。

- 【改进】Conversation 与小助手的文件、文件夹引用改为图标加名称的紧凑标签，横向排列并自动换行，完整路径在悬停时显示；已发送标签与正文显示在同一个用户消息气泡中。

- 【修复】Studio 中的 Conversation 与小助手文件卡片复用当前资源管理器文件图标主题的真实图标、字体和文件名映射，随图标主题及明暗主题切换刷新，拖放与选择文件显示一致。

- 【改进】Conversation 文件卡片按常见文档、代码、媒体及压缩包类型显示图标；Studio 中点击文件打开编辑器或文档预览，点击文件夹打开系统文件管理器，输入区与历史消息保持一致。

- 【修复】Conversation 与 Studio 小助手切换配置模型后保留历史回复及当轮模型名称，下一轮使用新模型；持久会话重连失败不再覆盖已完成回复，并恢复此前因此被错误隐藏的完成结果。

- 【修复】Conversation 左下角的文件选择与拖放共用导入逻辑，均支持文件和文件夹；Studio 保留原路径，浏览器保留目录结构，导入不再受附件类型声明限制。

- 【改进】Studio 小助手、Workflow、Conversation 和 Kanban 的多窗口按应用共用配置，自动同步配置修改与当前选择；会话及运行状态继续独立，同时保存时检查共享版本。

- 【改进】Conversation 与 Studio 小助手将“配置模型”入口移入缺少模型的错误提示区域，与消息操作图标分开；窄栏自动换行，点击直达模型配置并保留输入草稿。

- 【新增】Conversation 支持拖入 VS Code、桌面及其他位置的文件或文件夹，以可移除路径卡片展示并传给 Core Agent；草稿、排队和重试保留引用，浏览器文件夹导入保留层级与空目录。

- 【改进】配置列表突出标记“正在使用”的配置，其他配置提供明确的“使用此配置”按钮；切换中禁用重复操作，失败保留原选择，外部切换同步使用状态并保留草稿。

- 【修复】页面缩放或分栏产生小数像素宽度时，用户消息索引的显隐与左侧留白使用一致断点，避免错误隐藏和样式空档。

- 【修复】本地配置读取旧发布模板时保留源码中的系统 AI 限制，隐藏模型字段也不会开放第三方配置。

- 【改进】用户消息索引仅在宽屏显示；页面宽度不超过 680px 时隐藏索引、总数和悬停预览，不再占用左侧空间，恢复宽度后自动显示。

- 【新增】Studio 与 CLI Web 遵循项目的系统 AI 限制，隐藏第三方入口；配置保存、导入和小助手操作使用同一校验。

- 【新增】Conversation 可收起中间文字、思考与工具过程，成功保留最终回复、计划和资源卡片，失败只保留红色错误原因；模型名称与当轮用量后的按钮可独立展开或收起，不另占一行，自动收起由项目代码配置，Core Agent 默认开启。

- 【修复】小助手及 Conversation 回答标题显示当轮模型名称，避免把配置条目 ID 当作模型；发送预览和持久会话后续轮次保持一致，并从历史参数恢复旧消息名称，切换配置后不改写已保存名称。

- 【新增】长会话左侧显示浅色用户消息索引，每条消息对应一个短标记；悬停或键盘聚焦可预览内容与序号，点击可跳转，查看历史时保留阅读位置。窄栏显示消息总数，并支持长列表滚动和附件消息预览。

- 【修复】Studio 新建小助手标签时进入独立的新对话，保留原标签的运行和草稿；各标签恢复自己选中的对话。

- 【改进】AI 模型添加与编辑改为独立弹窗，来源使用分段切换；系统 AI 只选择 Provider 与模型并自动命名。配置项及模型列表增加边界分组，没有发布入口时隐藏单独的配置值标签。

- 【改进】用户消息的时间与复制操作移到气泡左侧，悬停或键盘聚焦时显示；移除底部占位并收紧与项目回复的间距，略微加深气泡背景，窄屏与触屏仍可使用操作。

- 【改进】Studio 与 CLI Web 未配置 Agent 模型时，输入框显示可点击的“配置模型”，直接打开当前配置的 AI 模型区域；失败消息也提供入口，保存后恢复模型选择，并保留输入与配置草稿。

- 【改进】分叉会话确认弹窗补充历史范围、新会话打开方式和原会话保留说明。

- 【修复】参数加载保留切换会话时的修改与重置，同步已清除的值，审批结束和服务重启后正确刷新。动态参数首次加载中或失败时仍可发送并由服务端校验；模型目录为空时拒绝沿用旧选择。

- 【改进】Conversation 参数按会话缓存，静态参数无需加载；连续修改合并解析，后续刷新保留选项、输入和 Slash 菜单，运行中暂停后台解析。配置和登录变化时失效缓存，发送仍重新校验，并修复过期请求和连接失败导致加载不结束的问题。
