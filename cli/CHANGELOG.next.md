- 【新增】多 Agent 批次强退重开后先中断旧执行树并等待明确恢复；用户待发消息与业务队列分离，仅成功用户轮次释放，后台报告不再推进队列。

- 【变更】Studio 模型参数仅使用设置模型并隐藏项目 AI；独立 CLI Web 自动回退项目配置，配置入口、默认值及实际请求保持一致，移除项目引用设置模型。

- 【修复】强退后有界关闭运行 worker 并释放会话锁；队列只在前一轮成功后自动继续，失败、取消和超时保留待发消息，新输入可先运行成功后再推进队列。

- 【修复】记忆面板改为连续列表和按需详情，固定开关尺寸并区分未配置、故障与授权状态，窄布局下仍可返回列表。


- 【新增】在 Studio 中点击 Agent 回复或计划中的本地文件链接、行内代码路径和正文绝对路径，可在编辑区打开文件；支持相对路径、文件 URI 和行列定位，并修复托管文件链接的点击处理。

- 【修复】项目信息中的嵌入配置页样式不再影响子弹窗，恢复添加／编辑模型弹窗正文与底部按钮的留白。

- 【新增】项目信息按 Core 有效能力展示全局／当前范围记忆，支持紧凑详情、编辑和遗忘；账号管理凭据仅保留在宿主，worker 使用受限授权。

- 【修复】技能预览的返回栏固定在独立文档滚动区外，修复滚动时正文穿过导航栏的问题，并保持加载、重试和返回列表可用。

- 【修复】技能页展示真实项目技能与 Core 内置技能及数量，支持搜索、点击预览完整 SKILL.md 和 Markdown 源码；不再把技能发现工具当作技能，预览与返回保持固定面板尺寸。

- 【修复】CLI Web 项目信息面板实时同步工具清单与权限，保留搜索和编辑焦点；修复配置加载失败后仍显示加载中、关闭主面板后子编辑窗口未关闭的问题。统一卡片、选中态和深浅主题，窄屏使用顶部标签导航并保持面板尺寸稳定。

- 【改进】在 Studio 中导出对话、单条消息或工作流记录时，使用原生保存窗口，文件写入成功后在右下角通知保存位置；取消保存不再提示成功，写入失败显示错误。

- 【改进】CLI Web 将 AI 用量、项目配置、工具、技能与数据库统一收进“项目信息”；采用固定尺寸、侧栏导航与独立滚动的设置面板，统一优化各分栏展示，并保留配置草稿、工具搜索与模型设置快捷入口。技能保持只读，无权限开关。

- 【修复】Studio 本地统计忽略已移除独立项目清单或已转为聚合子入口的旧导入登记；按项目声明读取本地历史，不再依赖部署数据库配置，真实的读取错误仍标为不可用。

- 【改进】CLI Web 将工具与技能拆分为独立分页；工具保留权限设置，技能使用只读指南卡片展示，不再显示启用和自动批准开关。Conversation 与 Workflow 共用此界面。

- 【修复】CLI Web 向项目运行进程传递经过校验的 `STEAMHARNESS_PROJECT_CONFIG` 数据库映射，确保父子配置在页面检查与 Workflow 执行时使用同一组 ID。

- 【破坏性变更】项目身份、名称、版本和声明统一使用独立的 `steamharness.json`，移除 `package.json.id` 和 `steamHarness` 的读取与写回。聚合项目显式登记子入口，由子目录配置提供图标、声明、数据库别名与计划；未登记配置不生效，上传下载保留父子结构。

- 【改进】CLI Web 数据库页仅展示关联信息与图标操作，浏览跳转至宿主；申请、审批和授权维护改由 Studio、Server Web 或 CLI 命令完成，普通 Web 提示暂不支持数据预览。

- 【改进】本地 Conversation 可直接使用 Core Agent 继承的参数契约，结构报告、动态模型选项与执行输入保持一致，支持隐藏和固定参数。

- 【改进】Web 运行错误不再直接铺开上游 HTML 错误页，改为简短的 HTTP 状态和处理提示；原始错误默认收起在技术详情中，适用于 Conversation 与 Workflow。

- 【改进】数据库管理移入“项目信息”的数据库页，移除标题栏数据库按钮。数据库卡片标明共享入口；关联配置留在项目信息，申请与权限在宿主维护。

- 【改进】Conversation 顶部的“新对话”按钮改用清晰的加号图标，突出新增操作。

- 【改进】聚合项目默认展示主入口，顶部项目窗口按钮改为纯图标；面板以紧凑卡片展示入口、类型、默认／当前标记和运行状态，通过图标在浏览器新页面或 Studio 新标签打开。移除分屏打开，当前入口也可重复新开标签，各标签保留独立视图并共享运行宿主。入口图标与配色独立配置，版本只属于根项目。

- 【变更】数据库管理直接保存别名与获批数据库 ID，申请及权限维护归宿主；支持添加多个引用，获批申请展示 ID，打包与上传保留引用。

- 【修复】数据库绑定提示提供“查看关联数据库”按钮，可直接处理关联引用；小助手与 Conversation 共用管理入口，检查状态显示可读文案。修复审批编号覆盖响应编号导致管理界面一直等待的问题。

- 【改进】用户模型菜单按内置／自定义分组，在独立模型参数中直接展示选项与底部“添加模型”入口；模型与 effort 可独立选择，保留项目自由分组、重置及来源限制。

- 【修复】没有可用用户模型时，模型入口显示“配置模型”及设置引导，点击直接打开模型设置；添加模型后恢复选择列表。

- 【修复】加载中及任务运行时，组合模型菜单仍可进入用户模型管理；模型 ID `inherit` 不再被当作权限继承标记。密钥脱敏保留项目输出中同名的自定义 `userSettings` 数据。看板预览刷新后重新检查当前关联导入，保留有效的缺失导入提示并忽略已解决的旧错误。

- 【新增】接收宿主用户模型并展示可选列表与“管理模型”入口，保留原项目模型配置 API；在安全边界采用设置更新，密钥不进入页面、普通历史或导出，恢复时只为相同模型端点补充密钥。
- 【修复】多入口并发绑定数据库不再相互覆盖；数据库申请不能夹带其他消费者的绑定引用。纠正 Kanban 数据库 API 示例。

- 【破坏性变更】检查、运行、Web 与 MCP 支持入口选择。Web 窗口切换保留各入口草稿和后台任务，数据库通过宿主申请、审批和绑定。移除关联项目、依赖锁和组合发布命令。

- 【改进】参数支持 `userSetting: { key: "agent.permissionPolicy", mode: "fixed" | "default" }`：固定跟随时只显示系统当前权限并打开用户设置；可覆盖时保留三个权限选项，以系统值为默认，重置后继续跟随。继承状态与项目覆盖分别保存，现有任务保持原权限。

- 【新增】CLI Web 接收 Studio 用户权限初始快照和能力握手后的更新；持久会话保留当前及后台任务的启动设置，在空闲安全边界采用新值。继承参数、历史、待处理输入及请求标识在重挂载和恢复时保留，独立 CLI 暂不持久化此设置。

- 项目部署配置统一放在根 config.json，集中维护数据库别名和 ID，各入口在 steamharness.json 中仅声明使用的数据库别名；STEAMHARNESS_PROJECT_CONFIG 可覆盖部署值。迁移只改一处 ID，权限继续由宿主维护，发行不写入环境覆盖值。
