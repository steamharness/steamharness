# 文档技能使用约定

先读 `humanize-it/SKILL.md`。本目录的上游文件按提交固定，来源和许可声明见 `UPSTREAM.json`。上游文件保持原样，项目适配集中写在这里。

上游 Python 脚本保留原始行尾空格；`.gitattributes` 只对这些脚本豁免该项检查。文档测试逐文件校验 Git blob 哈希，防止载荷漂移。

## 选择策略

| 内容 | 执行方式 |
| --- | --- |
| 用户手册、教程、产品说明 | 根据当前功能重新组织草稿，再用 `humanizer-zh` 核对信息、条件、顺序和表达 |
| 内部技术论证、架构说明 | 在符合适用范围时使用 `technical-writing`，保留事实依据 |
| 仍有模板句和重复表达的中文 | 按 `humanize-chinese` 的指南复查；其离线检测只作参考 |
| 英文镜像 | 保持同一信息架构、示例和限制，按自然英语重新表达，逐项对照中文 |

`technical-writing` 明确不适用于外部帮助文档和纯 API reference。对外页面不使用它的内部评审结构。技术术语、代码、数据、命令、URL 和 API 合约不做同义词替换；新增示例必须能从当前实现或实际运行中验证。

## 改写与审阅

1. 列出本页的读者任务、有效事实、前提和限制；查当前实现，修正已经过时的说明。
2. 按用途、操作和结果重写。操作步骤和参数表保留其结构，不为去除模板腔而拆散必要顺序。
3. 对照旧页和实现核对信息；拆页记录新位置，保留旧 URL 和原锚点入口。
4. 按主技能的五个维度评估：模板化表达 30%、自然度 25%、信息完整 20%、风格一致 15%、可读性 10%。80 分通过；退步回退，连续三轮无提升时换适用策略，最多 42 轮。
5. 记录实际使用的技能、轮次、编辑审阅分数和主要变化。分数是编辑判断，不是作者身份检测、独立人工评价或功能测试结果。

文档正文不展示改写过程或分数。没有验证的功能不能通过补充语气变成已验证事实。

## 历史版命令

`humanize-chinese` 固定在 `18516887e788fc9e03e10ff330c61fae4be0f676`。该提交的 README 声明 MIT；之后的版本加入非商业限制，未经许可检查不得升级。

从技能目录运行：

```sh
python3 humanize-chinese/scripts/humanize.py --help
python3 humanize-chinese/scripts/detect_cn.py /tmp/prose.txt -j
```

这个版本没有新版的 `replace`、`write`、`watermark`、`--scene novel` 或 `--scene auto`。不要照抄其他版本的命令。检测前提取中文正文，排除代码、表格、路径和标识符；结果只帮助定位表达问题，不能成为删改事实的理由。
