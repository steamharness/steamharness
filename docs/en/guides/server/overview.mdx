# Manage projects and data in Server Web

Server Web is SteamHarness's browser management console for projects, versions, members, and data. Project code executes locally in Studio or the CLI.

## Project workbench

1. Sign in, then search projects by name or filter by entry type.
2. Open a project to inspect entries, configuration, versions, and members.
3. Download a version, install dependencies locally, and run it.

A project can contain several entry types; a filter matches any included type. Uploaded archives need nonempty `entries` and a valid `defaultEntry`. Names and presentation come from project declarations.

## Projects and data

| Task | Location |
| --- | --- |
| Members, group ownership, and access requests | [Project management](/en/guides/server/project-management) |
| Upload drafts, publish, or download | [Workspace CLI](/en/cli/server-workspace) |
| Create databases, grant access, migrate models, and edit rows | Relational resource details in the database directory |
| Manage documents, search, revisions, and attachments | Knowledge resource details in the database directory |

Relational and knowledge resources are created, granted, and bound separately. Server maintains relational bindings by account, project, entry, and alias. Knowledge resources also use the root configuration's alias mapping. Membership alone grants no data access.

Kanban previews run in permission-constrained static iframes using short-lived capabilities rather than inherited account credentials. Use a local host for executable project operations.

## Accounts and settings

Settings include profiles, API keys, and themes. Authorized accounts can also manage users, groups, invitations, and audits. Menus reflect capabilities, and the service checks every operation again.

Opening a resource-management link from signed-in Studio reuses its account without another password prompt. The one-use handoff lasts one minute and contains no long-lived token. Revoking the original credential or disabling the account also invalidates browser access.

Project-list or release-notice failures can be retried in their respective areas while retaining sign-in. Only session expiry requires another login.

### Change an avatar

1. Choose an image in **Settings → Profile**.
2. Move or resize the square crop; use **Reset crop** when needed.
3. Confirm cropping, then select **Save profile** to upload.

Preview scales to the dialog, but export does not upscale the original. The client compresses the square avatar and converts GIFs to still images. Canceling retains the old avatar; failed processing can be retried. Profile avatars support a larger preview, closed with Esc, the close button, or the overlay, restoring focus.

Older avatars use a centered crop to avoid distortion. Settings and management subpages preserve other sidebar entries while expanding and highlighting the active group.

## Display

The console supports light, dark, system themes, and narrow layouts. Tables scroll within their area; mobile navigation uses a drawer. The upper-right refresh button updates the current page.

UI times use the browser timezone and `YYYY-MM-DD HH:mm:ss`; APIs retain ISO timestamps. Upload failures report the stage and preserve existing drafts and releases.
