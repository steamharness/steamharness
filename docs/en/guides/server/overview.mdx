# Manage projects and data with Server Web

Server Web is the browser administration client for SteamHarness Server. After signing in, you can find Workflow, Conversation, and Kanban projects, manage source versions, and manage project data. Local CLI or Studio performs project execution.

## Project workspace

Project lists display type sets and match any entry type. Details expose entries, entry configurations, versions and membership. Independent database management provides requests, approval, shared grants and data browsing.

Uploaded packages must register nonempty `steamharness.json.entries` and a valid `defaultEntry`. Names and display platforms belong to projectInfo. Database aliases and IDs belong to root config.json; package entries list the aliases they use.

## Projects and data

- Use [Workspace CLI](/en/cli/server-workspace) to create, upload, publish, and download projects.
- Configure membership and group ownership in [Project management](/en/guides/server/project-management), and grants on the database page.
- Knowledge supports document creation, editing, deletion, search, and line reads; KV and PersistentValue store project or conversation data.
- Database spaces require request, approval and binding, separate from source and membership requests.
- Kanban keeps static previews, configuration, and the data Bridge. A preview uses a short-lived capability bound to a project, user, and version; its iframe does not inherit account credentials.

## Accounts and settings

Server Web supports password sign-in, device authorization, member invitations, project and group roles, API keys, audit logs, and theme settings. Server validates account, project, and data permissions; credentials appear only in redacted form in the console and audit records.

Settings → Memory manages private global, project and directory memories with scope/source filters, search, server pagination, full details, versioned edits, forgetting, clearing, automatic saving and failed-job retry. Revoked project access exposes only locked counts and deletion. No embedding is required; see [Account memory](/en/guides/server/account-memory) for service configuration.

Choose an avatar in Settings → Profile or user management to crop with a fixed 1:1 square selection. Move or resize the selection; Reset selection restores the largest centered square. Source images have no file size, dimension, or aspect ratio restriction. The preview fits the dialog proportionally and enlarges small images for easier cropping; exported images are never upscaled. After confirmation, the browser compresses the square avatar; Save profile uploads the result. Canceling retains the previous avatar, and processing failures can be retried. GIF images become static avatars. Profile settings, account menus, user lists, memberships, audit entries and profile details use consistent 1:1 avatars with rounded corners. Existing images are centered and cropped to fill without stretching. Click the avatar preview in user management or the avatar inside a profile dialog to view a larger image that fits the viewport. Close it with the close button, backdrop or Escape; keyboard focus returns to the avatar.

Settings and Admin Center expand submenus in the main sidebar. Selecting a page keeps Project Workbench and the other entries available. Admin Center only shows entries the current account can access; opening a page directly expands its group and highlights the current page.

Upload failures show the processing stage and reason without replacing saved drafts or historical versions. Server does not install dependencies, build, or load uploaded project code.

## Display

The console supports mobile layouts, light, dark, and system themes. Times use the browser time zone and full timestamps use `YYYY-MM-DD HH:mm:ss`; APIs retain ISO timestamps.

Each administration page has one top-right refresh action. Mobile navigation opens in a drawer, and tables scroll inside their own region.
