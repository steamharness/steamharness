# Project management

Project managers use Server Web to manage members, invitations, source access, and related projects. Server stores project metadata, permissions, and version snapshots; it never executes uploaded project code.

## Project avatars

Project lists, details, and settings display avatars from `projectCard.icon`, `iconColor`, and `iconBackgroundColor`. New projects without an avatar use their project type's icon with randomly generated, saved foreground and background colors. Their contrast ratio is at least 4.5:1. Refreshing the page or reconnecting an existing project does not generate new colors.

Older projects without avatar metadata use their project type's default icon and colors. `iconUrl` remains readable for compatibility, while these views consistently use the icon and colors.

Click a project list avatar to open its details, or a standalone detail avatar to preview it. User avatars in member and uploader lists open the currently visible profile information. The account menu avatar opens its menu, while the personal profile avatar selects an upload. Dialogs support keyboard dismissal and return focus to their trigger.

## Members and invitations

Member roles are `owner`, `manager`, `writer`, and `viewer`. A role controls settings, membership, versions, and data actions; source-download permission is checked independently from data permission.

Invitation links are single-use and short-lived. An invited user sets a password on the acceptance page. Revoking an invitation invalidates its link immediately. Server does not send email for a project.

## Source and versions

Upload jobs unpack archives and perform static checks. A failure preserves the existing draft and historical versions. Publishing creates an immutable version snapshot and updates `latest`; a duplicate version returns `409` without replacing an existing version.

Source downloads require the project's separate download permission. Version archives exclude KV, PersistentValue, SQLite, environment files, and CLI credentials.

## Related projects

A related project declaration contains an alias, target project UUID, and read/write grants for target data. Both declarations must point to each other; rules support `none`, `all`, and `prefixes`. Revocation takes effect immediately and does not delegate permissions recursively.

A related write checks consumer data-write permission and target write grants. Source downloads and project management remain separate permissions.

## Project groups and audit

Project-group publication statically validates archives and hashes, then locks dependencies to exact versions. Downloads check source permission per project and return skip reasons.

Account, permission, API key, device sign-in, upload, publication, and data administration are audited. Reading audit logs requires `audit.read`, and credential fields are always redacted.

## Project configurations

Edit fields directly and save changes together. Use the reset icon to restore a default or clear a field without a default; no separate enable checkbox is needed.

All three project types expose fields, named profiles and complete import/export. Studio and local CLI share local storage; Server values are per project and account. Studio Control can query and manage configurations even when the panel is closed. See [Project configurations](/en/concepts/project-configuration) for the JSON actions, version checks and execution snapshot rules.

File configuration fields choose and upload files to project file storage on the Server. Saving applies the references using the existing project file write permissions.

Configuration authors use the separate **Publication and permissions** tab to select profiles, a default, value inclusion and field/JSON Pointer editing rules. Only the original owner or existing administrators may save official drafts. The recipient preview shows the filtered version; personal configuration imports never change official rules. Published source shares and downloads use that same immutable template and its attachment copies. See [Project configurations](/en/concepts/project-configuration).
