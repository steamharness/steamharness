# Verify projects and changes

Test input, output, and failure paths first, then verify host interfaces and external services. Use isolated sample data and record which checks actually ran.

## Check your project

Run from the project root:

```sh
pnpm exec steamharness check .
pnpm exec steamharness structure .
pnpm exec steamharness run .
pnpm exec steamharness json .
```

Verify each Workflow, Bot, and Kanban entry in an aggregate. Structure checks do not execute user code. After a successful run, confirm that the page or caller received the expected result.

<span id="add-tests-for-new-code"></span>

## Test layers

| Layer | Coverage |
| --- | --- |
| Pure logic | Parameter parsing, conversion, calculations, and error conditions |
| Executor | Entry selection, parameters, output, waiting input, and cancellation |
| Resources | Grants, bindings, revision conflicts, disconnection, and storage failures |
| Host | Real rendering, output order, queues, recovery, and both UI languages |

Use a deterministic test Provider and fixed file fixtures first. Real models, databases, external processes, and visible windows need a separate validation environment and explicit enablement.

## Add meaningful tests

- Nodes and executors: normal results, invalid input, cancellation, and recovery.
- Configuration and data: revision conflicts, revoked access, and retained drafts after failure.
- Pages: loading, empty, failure, disabled, and key interaction states.
- Asynchronous conversations: match completion by request or message ID, not the last array item.

## Suggested example files

| File | Purpose |
| --- | --- |
| `__fixtures__/smoke.json` | Inputs, conversation ID, expected output, and required nodes |
| `__snapshots__/structure.json` | A compact entry, parameter, node, and branch structure |
| `__tests__/` | Project logic and tool tests |

Examples needing live services should state prerequisites and a separate command. Retain reasons for skipped cases; static validation does not establish live service behavior.

## Change SteamHarness source

Run the relevant package checks from the open-source repository root:

| Area | Checks |
| --- | --- |
| SDK | `corepack pnpm -C harness typecheck`, `corepack pnpm -C harness test`, `corepack pnpm -C harness build` |
| CLI | `corepack pnpm -C cli typecheck`, `corepack pnpm -C cli test` |
| Server and Web | `corepack pnpm -C server typecheck:all`, `corepack pnpm -C server test`, `corepack pnpm -C server build:all` |
| Studio extension | `npm --prefix studio run check`, `npm --prefix studio run build:extension` |
| Documentation content | `node docs/scripts/validate-docs.mjs`, `node --test docs/scripts/__tests__/*.test.mjs` |

Server integration tests use isolated PostgreSQL containers; check Docker before running them. Shared interface changes also require checking the SDK, CLI, Server, or Studio consumers. The content-consuming workspace builds the documentation site.
