# Server 0.1.8

2026-08-26 · Tag `server/v0.1.8` · 当前设备

<span id="server-0-1-8" className="release-version-anchor"></span>
<span id="server.0.1.8" className="release-version-anchor"></span>

#### New Features

- **Standalone Alpha deployment**: shares PostgreSQL and the OSS bucket with stable while isolating code, processes, logs, and caches, running on port `7140`. See [Deployment](/en/guides/server/deployment). {/* note: entry-1 */}
- **Version resolution by release target**: every version pins Server, macOS, and Windows targets, and runs and schedules only resolve online versions with a compatible runtime. {/* note: entry-2 */}
- **Project display metadata**: default name, localized name, manual declaration, and display platform. See [Project management](/en/guides/server/project-management). {/* note: entry-3 */}

#### Breaking Changes

- Server only runs projects and serves server data when `dataStorage.mode` is `server` or `both`. {/* note: entry-4 */}
  Migration: `local` and undeclared projects must become `server` or `both`, otherwise every entry point returns a structured `409`.
- Core and CLI move to exact `0.2.0` dependencies and PersistentValue APIs must carry `projectId`. {/* note: entry-5 */}
  Migration: non-global namespaces, entries, and sources must set `projectName` to the project ID.
- Server removes Supabase entirely; accounts, sessions, and invitations move to native PostgreSQL. {/* note: entry-6 */}
  Migration: account data has to be migrated once into Server's own PostgreSQL database.
- Desktop login and run sources standardize on `desktop`, and the old `app` source is no longer accepted. {/* note: entry-7 */}
  Migration: change the caller's source identifier to `desktop`.

#### Added

- Added atomic cloud project creation receiving the UUID and full `projectInfo`, letting Desktop bind or restore by the same UUID. {/* note: entry-8 */}
- Added default name, localized name, manual declaration, and display platform, served through the project list and `PUT /api/projects/{id}/project-info`. {/* note: entry-9 */}
- Added Server, macOS, and Windows release targets pinned per version, with local-only versions skipping dependency install and runtime builds. {/* note: entry-10 */}
- Added source and project group downloads validated per macOS/Windows target and resolving `latest` per platform. {/* note: entry-11 */}
- Added an Alpha deployment path sharing the database and bucket with stable while isolating code, processes, logs, and local caches. {/* note: entry-12 */}

#### Changed

- Changed Desktop installers, the update feed, and bundled project resources to Aliyun OSS. {/* note: entry-13 */}
- Changed Alpha Server to disable schedule polling by default; plan management and run-now still work. {/* note: entry-14 */}
- Changed compatibility checks to require an exact Core declaration and compare only the `major.minor` line. {/* note: entry-15 */}
- Changed production credentials to come from protected GitLab CI/CD variables, keeping development `.env` files local only. {/* note: entry-16 */}

#### Fixed

- Fixed recovery falling back to `/var/run/docker.sock` when no Docker socket path is configured, so Alpha can start PostgreSQL. {/* note: entry-17 */}
- Fixed bundled project indexes not forcing client revalidation, with versioned bundles now on long-lived immutable caches. {/* note: entry-18 */}

#### Removed

- Removed the local download service that Server used to start, recover, and configure. {/* note: entry-19 */}
