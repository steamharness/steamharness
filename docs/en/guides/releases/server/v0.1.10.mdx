# Server 0.1.10

2026-09-05 · Tag `server/v0.1.10` · 当前设备

<span id="server-0-1-10" className="release-version-anchor"></span>
<span id="server.0.1.10" className="release-version-anchor"></span>

#### New Features

- **Local execution mode**: `pnpm dev` and `pnpm start:local` run cloud Workflows on the host without a Runner or container build. See [Deployment](/en/guides/server/deployment). {/* note: entry-1 */}
- **Cross-service related project calls**: run containers read a target project's knowledge base and invoke its entrypoints as the calling user. See [Project management](/en/guides/server/project-management). {/* note: entry-2 */}
- **Project KV entry deletion**: `DELETE /api/projects/:name/kv/entry` removes a single project KV entry by scope and key. {/* note: entry-3 */}

#### Breaking Changes

- The public Embed HTTP endpoints and the `server-live` relay unit are removed, along with the `embed.manage` permission. {/* note: entry-4 */}
  Migration: browser runs move to the Desktop home Web build, and the console only manages cloud projects.
- The Server execution surface drops local dependency install, builds, Node subprocesses, and local fallback. {/* note: entry-5 */}
  Migration: project versions must be built and run by a remote Runner against a fixed Core, runtime protocol, architecture, and OCI digest.
- `listProjects` no longer accepts `origin`, and project summaries no longer return `embedEnabled` or `embedPublicUrl`. {/* note: entry-6 */}
  Migration: callers rely on the default project list fields instead of an Embed toggle.
- Anonymous `/web` visits redirect to login and back, and `?next=` only accepts route names rather than arbitrary paths. {/* note: entry-7 */}
  Migration: never put an absolute path in `next`, which is rejected to avoid an open redirect.

#### Added

- Added a persistent Runner pool with nodes, leases, task ordering events, artifacts, and a runtime capability control plane. {/* note: entry-8 */}
- Added nodes registering, renewing, and claiming tasks over outbound HTTPS, so project containers never get database or admin credentials. {/* note: entry-9 */}
- Added runtime KV, PersistentValue, related project, and file APIs whose tokens bind to project, user, task, and expiry. {/* note: entry-10 */}
- Added renaming and deletion for run records, restricted to project admins and the run's initiator. {/* note: entry-11 */}
- Added display names and stable `cardId` values for run records so embedded cards stop being recreated on scroll. {/* note: entry-12 */}
- Added an optional local object storage driver writing artifacts and avatars to disk via `STEAMHARNESS_STORAGE_DRIVER=local`. {/* note: entry-13 */}
- Added startup without any OSS credentials, with avatars served read-only from `/storage/avatars`. {/* note: entry-14 */}
- Added the wflive relay on ECS, with Stable and Alpha listening on 7150 and 7151 respectively. {/* note: entry-15 */}
- Added a `delete` operation to `POST /api/project-storage` returning `{ removed: false }` for missing entries. {/* note: entry-16 */}
- Added the `kv.manage` permission, granted to the Developer role while Operator and Viewer stay read-only. {/* note: entry-17 */}
- Added optional grouping metadata on the Workflow entrypoint structure for partitioned public Embeds. {/* note: entry-18 */}

#### Changed

- Changed `server:start` to keep source mode and dev ports while disabling backend listening and Web hot reload. {/* note: entry-19 */}
- Changed related project knowledge base and entrypoint calls to require explicit grants from the target project, checked per key. {/* note: entry-20 */}
- Changed entrypoint calls to run once as the initiating user, with the called project gaining no related access itself. {/* note: entry-21 */}
- Changed `STEAMHARNESS_OSS_ENDPOINT` to accept a same-region internal endpoint while signing URLs with the public endpoint. {/* note: entry-22 */}

#### Fixed

- Fixed Runner artifact uploads being cut off by the OSS client's 60 second timeout, now budgeted at 5 minutes. {/* note: entry-23 */}
- Fixed local execution accessing Server as the initiating user by issuing a run-scoped key valid for 6 hours. {/* note: entry-24 */}
- Fixed the local execution subprocess environment to be allowlisted, keeping database, OSS, and LLM secrets away from project code. {/* note: entry-25 */}
- Fixed nested runs of related projects being unable to reach further, returning `503` when the originating run cannot be verified. {/* note: entry-26 */}
- Fixed related project knowledge base writes being validated per document key instead of per whole modification. {/* note: entry-27 */}
- Fixed `/related/run` returning nested failures with their status and error codes instead of collapsing them into request errors. {/* note: entry-28 */}
- Fixed related project entrypoint lists sampling `latest` to match what `runEntrypoint` actually executes. {/* note: entry-29 */}

#### Removed

- Removed `GET/PUT /api/projects/{projectId}/embed` and every `/embed/**` route. {/* note: entry-30 */}
- Removed the `wfembed` host and `STEAMHARNESS_EMBED_PUBLIC_BASE_URL`; `project_embed_configs` stays expand-only. {/* note: entry-31 */}
- Removed the Server Web `/web` entry page with its runnable version list and `next=web` redirect. {/* note: entry-32 */}
- Removed the `server-live` release unit, the `/api/desktop/v1/*` and `/api/web-runs/*` routes, and the `web` release target. {/* note: entry-33 */}
