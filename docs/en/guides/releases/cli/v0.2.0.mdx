#### New Features

- **Bot project memory**: Project configuration exposes default-on memory and retains saved entries when disabled {/* note: entry-1 */}
- **Compiled project releases**: Build, validate and run compiled entries with separate launch snapshots {/* note: entry-2 */}
- **Native Kanban conversations**: Embed local native chats with streaming replies, drafts, queues and approvals {/* note: entry-3 */}

#### Breaking Changes

- Final sealed releases encode internals in v2 `structure.json` while retaining readable project and entry summaries. {/* note: entry-4 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Minify declarations, configuration definitions, and JSON assets without changing string content or number literals. {/* note: entry-5 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Snapshots and uploads/downloads share the decoder and integrity checks. Rebuild older releases from source. {/* note: entry-6 */}
  Migration: Rebuild old releases from source and use the v2 decoder for sealed structures.
- Project types, structure reports, templates and the Web host now use Bot. {/* note: entry-7 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Conversation protocols remain, with stable request identities across initial, resumed and subsequent turns. {/* note: entry-8 */}
  Migration: Use Bot in project types/templates and retain stable request identities in embedded conversation messages.
- Move identity, name, version and declarations to `steamharness.json`; stop reading or writing `package.json.id` and `steamHarness`. {/* note: entry-9 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Register aggregate child entries explicitly; each child configuration supplies its icons, declarations and schedules. {/* note: entry-10 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Unregistered configurations stay inactive; uploads and downloads preserve the parent/child structure. {/* note: entry-11 */}
  Migration: Move legacy package.json project fields to steamharness.json and register aggregate child entries explicitly.
- Select registered entries in check, run, Web and MCP; Web switching preserves each entry’s drafts and background tasks. {/* note: entry-12 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Remove related projects, dependency locks and combined publishing commands. {/* note: entry-13 */}
  Migration: Use aggregate entries/defaultEntry and per-entry commands instead of related-project, dependency-lock and combined-release flows.
