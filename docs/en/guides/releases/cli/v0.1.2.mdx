#### Pi Durable

- [Fixed] Keep automatic retry records at the affected response's interruption point, followed by resumed content. Completing a run or reopening history no longer appends Retry below the complete answer; details still expand in place. {/* note: entry-1 */}
- Move the complete durable Agent task panel into Studio Trace. Remove the CLI Web sidebar, entry and width state while retaining transcripts, queues and forks. The host bridge carries deduplicated task snapshots, plan approval boundaries and explicit conversation controls, validates owners and returns action errors. {/* note: entry-2 */}
- [Fixed] Show the latest plan document and its approval state in the task sidebar even when the model does not call `update_plan`. Keep the correct plan through revisions, execution and reopening using approval boundaries; execution steps remain separately persisted and editable. {/* note: entry-3 */}
- [Fixed] Hide answer footer actions while sending, running, awaiting plan approval or user input, or stopping. Show Trace, copy, retry and export once the answer has finished, keeping actions available for finished historical answers. Retain original and revised plans, decisions and execution output across resumed reports and durable snapshots. Reopening durable history restores the complete plan from saved snapshots without rerunning models or tools. {/* note: entry-4 */}
- [Fixed] Display durable usage per answer turn with call, input, output and cache details, keeping other forks out of the original answer. The composer ring uses the open conversation's latest standard outputs after follow-ups, forks, compaction and resets, and labels nonzero occupancy below one percent explicitly. {/* note: entry-5 */}
- Show Conversation messages, attachments and delivery status immediately on send, or a pending queue item while busy. Save conversations and resolve parameters in the background, preserve new drafts across acknowledgements, and retain failed sends for retries under their original request identity. {/* note: entry-6 */}
- [Fixed] Keep queued message controls in place and loading icons spinning while saving, sending now or withdrawing, with immediate per-message feedback. Newly submitted messages can request withdrawal before confirmation, and failed actions retain the input and a retry action without duplicate submissions. {/* note: entry-7 */}
- Preserve a failed durable owner report and its original error even when the primary answer has completed. Update Core's streaming block and failure settlement behavior so a failed answer does not leave tasks appearing active or resume them on reopening. {/* note: entry-8 */}
- [Improved] Split Tasks into equal-height conversation/active-task and completed-task regions with independent scrolling, and mark the open conversation. Show all loaded history and expand arguments, results and errors beside the selected task, with an action to open its conversation. {/* note: entry-9 */}
- [Improved] Resize the task sidebar from its left edge or keyboard, double-click to reset, and retain its width. Preserve conversation reading space and the full-width narrow view. Settled tasks display their terminal outcome even if historical snapshots retain an abort mark. {/* note: entry-10 */}
- [Improved] Collapse Tasks to the right and group context and stop commands in a labeled actions menu. Show stop commands only for applicable active work, excluding independent forks. {/* note: entry-11 */}
- [Improved] Remove the composer turn selector: messages queue while busy and run directly while idle. Durable queued messages have a Send now icon. Confirm before creating and opening a fork, and fix navigation when its state frame has not rendered yet. {/* note: entry-12 */}
- [Fixed] Show submitted arguments for active and completed tools in task details, including nested Code Mode calls. Update Core to prevent missing or misidentified tool output and reuse of previous approvals in ordinary Agent mode when call IDs repeat across turns. {/* note: entry-13 */}
- [Fixed] Update the durable Agent Core feature dependency to capture commands at submission, reject predeclared catalog drift on recovery, and protect source/destination backup ownership while retaining the existing conversation and task sidebar UI. {/* note: entry-14 */}
- Added task definition versions, checkpoints, wake times and Code Mode scripts to durable task details. The Records view shows extensions, tool catalogs, execution targets and storage status using the existing Studio / VS Code style and four-view layout. {/* note: entry-15 */}
- Fix export and compaction after a durable foreground finishes. Preserve recovery commands during slow tool initialization, resume saved queued inputs, and restore fork history and source links after a lost receipt. Isolate command confirmations by owner and target conversation, ignore JSON key order when deduplicating commands, and keep full session frames out of persistent trace history. {/* note: entry-16 */}
- Added a Studio / VS Code styled durable Agent sidebar with Tasks, Plan, Records, and Usage views, a narrow-panel return action, queued-input withdrawal, steering, message forks, context reset, and scoped stop controls. {/* note: entry-17 */}
- Persistent Agents now use bidirectional worker commands, stable request identities, unconfirmed-command recovery, and full snapshots. Foreground/background/connectivity states are separate, pages select conversations independently, slow connections retain the latest snapshot, and answers remain inline without duplication. {/* note: entry-18 */}
- Release completed Conversation tasks even if saving their final state fails. Stop and join workers and cancel parked approvals when saving the stop intent fails, preventing continued execution or stalled shutdown. {/* note: entry-19 */}
- CLI Web / Studio recover Conversations that declare recovery using their original run, messages, arguments and approvals. Show Recovering in the existing status line, retry unexpected worker exit up to three times, and continue the same run on Retry. Host closure preserves checkpoints; explicit Stop durably cancels tasks and conversation deletion removes Agent storage. {/* note: entry-20 */}

#### New Features

- **Project template module**: Workflow, Conversation, and Kanban starters plus four local examples, for creating projects from Studio Start. {/* note: entry-21 */}
- **Standard message input**: Conversation always uses the standard input, with attachments under `conversation.attachments`. {/* note: entry-22 */}

- **File transfer commands**: `workspace file-upload/file-download/file-delete` move project images and files, up to 50 MiB each. {/* note: entry-24 */}
