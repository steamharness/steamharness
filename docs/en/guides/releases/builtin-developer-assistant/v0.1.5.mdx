# 开发者小助手 0.1.5

2026-09-01 · Tag `builtin-developer-assistant/v0.1.5` · 内置项目更新

<span id="builtin-developer-assistant-0-1-5" className="release-version-anchor"></span>
<span id="builtin-developer-assistant.0.1.5" className="release-version-anchor"></span>

#### New Features

- **Desktop Control standard MCP**: the assistant permanently mounts that MCP to operate themes, language, updates, projects, and KV. {/* note: entry-1 */}
- **OpenAI Responses support**: reuses OpenCode's multi-turn text, images, model validation, and streaming output, emitted as `opencode-answer`. {/* note: entry-2 */}
- **OpenCode Permission quick parameter**: quick parameters switch between `read-only`, `workspace`, and the default `auto`. {/* note: entry-3 */}

#### Breaking Changes

- The generator stops emitting global KV, `.workflow` storage scopes, and Kanban `dataSources` in favor of current-project, conversation, and related-project APIs. {/* note: entry-4 */}
  Migration: rewrite existing `context.kv`, `persistentValue`, and `dataSources` calls to the current-project, conversation, or `projectInfo.relatedProjects` APIs.
- Assistant workspace manifests accept only schema v2 and general related-resource types; legacy manifests and older Desktops without one are dropped. {/* note: entry-5 */}
  Migration: convert legacy project manifests to schema v2 and upgrade the host to a Desktop declaring `minDesktopVersion`.

#### Added

- Added an OpenCode Permission quick parameter switching between `read-only`, `workspace`, and `auto`, forwarded to every run. {/* note: entry-6 */}
- Added OpenAI Responses support reusing multi-turn text, images, model validation, and streaming output into `opencode-answer`. {/* note: entry-7 */}
- Added a permanent Desktop Control MCP mount covering theme, language, launch at login, updates, local projects, project info, and KV. {/* note: entry-8 */}
- Added Dock opening tools for the Home, local project, or ordinary folder bound to the run, on the right or bottom. {/* note: entry-9 */}
- Added batch KV reads and writes of up to 100 project entries plus knowledge queries and mutations, returning per-item results. {/* note: entry-10 */}
- Added refreshing reasoning levels through the OpenCode resolver on model changes, with extra `max` / `ultra` levels for `gpt-5.6-*`. {/* note: entry-11 */}

#### Changed

- Changed the minimum host to Desktop `0.1.23` now that the Desktop Control MCP is permanently mounted. {/* note: entry-12 */}
- Changed OpenAI reasoning levels to display as `Effort` in quick parameters and combine with the model in the composer summary. {/* note: entry-13 */}
- Changed the project manifest to adopt the general `projectInfo.relatedProjects` relationship contract. {/* note: entry-14 */}
- Changed OpenCode to reach Desktop Control only through the parent Workflow's controlled proxy, with consequential writes approved by default. {/* note: entry-15 */}

#### Fixed

- Fixed continued editing and completion misreported from stale CLI results when a Skill or reference cannot be read completely. {/* note: entry-16 */}
- Fixed ordinary folders degraded by obsolete manifests or structural validation now being migrated in authorized stages. {/* note: entry-17 */}
- Fixed source migration, host recognition, code-root authorization, and KV authorization being reported as one completion state. {/* note: entry-18 */}

#### Removed

- Removed global KV, `.workflow` storage scope, and Kanban `dataSources` output from the generator. {/* note: entry-19 */}
- Removed conversion of legacy project manifests and support for older Desktops without a manifest. {/* note: entry-20 */}
