# Developer Assistant unreleased

#### New Features

- **Studio VS Code host**: the default host becomes Studio VS Code with an independent working directory and Studio Control's standard MCP. {/* note: draft-90 */}
- **Asking mid-plan**: in plan mode the assistant uses Core's `ask_user` tool to ask one or more questions in a single turn. {/* note: draft-91 */}

#### Breaking Changes

- Breaking: the assistant now uses defineBot while preserving workspace, skills, Studio Control and permission capabilities; generator guidance and examples use the Core Bot contract. {/* note: draft-23 */}
  Migration: Update the affected project declarations or clients to the contract described above before upgrading.
- Breaking: project identity, name, version and declarations now use independent `steamharness.json` files. Removed reads and writes of `package.json.id` and `steamHarness`. Aggregates explicitly register child entries whose configuration defines icons, declarations and schedules. Unregistered configurations stay inactive, and transfers preserve the parent and child structure. {/* note: draft-53 */}
  Migration: Update the affected project declarations or clients to the contract described above before upgrading.
- Breaking: the generator, templates and API references use aggregate entries. Calls use context.entries. Related-project declarations and combined publication locks are removed. {/* note: draft-60 */}
  Migration: Update the affected project declarations or clients to the contract described above before upgrading.
- Conversation hides the composer by default while awaiting an answer or plan approval, and turns off `/plan` and its footer notice once the plan is accepted. {/* note: draft-92 */}
  Migration: projects that keep the composer declare it explicitly in the generic `userInput` configuration.
- Conversation removes its enable setting and custom main fields, moves attachments to `conversation.attachments`, and rejects retired configurations during validation. {/* note: draft-93 */}
  Migration: declare attachments through `conversation.attachments` and keep only Auxiliary, Quick, Mode, and Slash parameters.
