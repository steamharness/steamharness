# Core 0.2.0

2026-11-18 · Tag `steamharness/v0.2.0` · npm

#### New Features

- **Bot project memory**: Bots keep project memory on by default, save lasting facts and look them up on each turn {/* note: entry-1 */}
- **Local runtime persistence**: Run history and Agent checkpoints default to local SQLite, keeping remote reads off the reply path {/* note: entry-2 */}
- **Cancellable sleep**: The built-in `sleep({ seconds })` stores its deadline and waits only the remaining time after recovery {/* note: entry-3 */}

#### Breaking Changes

- Use versioned Brotli + Base64 release structures while retaining readable project and entry summaries. {/* note: entry-4 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Use the shared SDK decoder for entries, parameters and models; reject corrupt, oversized or old-format payloads. {/* note: entry-5 */}
  Migration: Rebuild old releases from source and use the shared structure decoder for entries, parameters and models.
- Replace Conversation projects with Core Agent Bots declared through defineBot. {/* note: entry-6 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Standardize input, output and durable sessions, with input preparation, persistent completion receipts and tool policies requiring approval in every mode. {/* note: entry-7 */}
  Migration: Migrate Conversation declarations to defineBot and adopt the Bot input/output and durable-session contracts.
- Remove KV, PersistentValue and local KV APIs. Conversations and run records default to local SQLite with explicit Server storage available. {/* note: entry-8 */}
  Migration: Adopt runtime persistence; old KV/SQLite data is not migrated automatically, so preserve and migrate required records first.
- Move identity, name, version and declarations to `steamharness.json`; stop reading or writing `package.json.id` and `steamHarness`. {/* note: entry-9 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Register aggregate child entries explicitly; each child configuration supplies its icons, declarations and schedules. {/* note: entry-10 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Unregistered configurations stay inactive; uploads and downloads preserve the parent/child structure. {/* note: entry-11 */}
  Migration: Move legacy package.json project fields to steamharness.json and register aggregate child entries explicitly.
- Move projects to root projectId with entries/defaultEntry, allowing multiple same-type entries with isolated configuration and execution. {/* note: entry-12 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Preserve identity and cancellation across entry calls and revalidate permissions. {/* note: entry-13 */}
  Migration: Declare projectId, entries and defaultEntry in the root manifest and target configuration/calls by entry.

## Legacy release (2026-08-26)

#### Breaking Changes

- Projects must declare `steamHarness.projectInfo.dataStorage.mode`, which constrains where KV, PersistentValue, and knowledge may live. {/* note: entry-167 */}
  Migration: add `dataStorage.mode`; the `server` location requires sign-in and a same-UUID project binding.
- Removed `context.kv` and `context.persistentValue` in favor of `context.storage.<location>.*`. {/* note: entry-168 */}
  Migration: rewrite local access as `context.storage.local.*` and server access as `context.storage.server.*`; the old properties only throw a migration error at runtime.
- Knowledge helpers now require an explicit storage-location context instead of implicitly reusing the current domain. {/* note: entry-169 */}
  Migration: pass `context` or the target storage location explicitly when calling a knowledge helper.

#### Changed

- Changed projects to require an exact SemVer in `devDependencies.steamharness`, with hosts comparing only the `major.minor` line. {/* note: entry-170 */}
- Changed any patch or dated Alpha on that line to run directly, while a major or minor change requires a host upgrade before user modules load. {/* note: entry-171 */}
