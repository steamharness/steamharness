# Core 0.2.4

2026-09-05 · Tag `steamharness/v0.2.4` · npm

<span id="steamharness-0-2-4" className="release-version-anchor"></span>
<span id="steamharness.0.2.4" className="release-version-anchor"></span>

#### New Features

- **Agent capability layer**: built on the pi agent SDK, adding `workflow.createAgent(...)`, `createAgentNode(...)`, and a conversation executor. {/* note: entry-1 */}
- **Cross-turn conversation recovery**: the pi `AgentMessage[]` is stored under `agent.transcript.<sessionKey>` and seeded back into `initialState.messages` on the next turn. {/* note: entry-2 */}
- **Related project knowledge and entrypoint calls**: `relatedProjects.get(alias)` opens the target's knowledge base and entrypoints, authorized per key. {/* note: entry-3 */}

#### Added

- Added `contentType: "video"` to the output protocol, preserving video descriptors and streamed output-item types. {/* note: entry-4 */}
- Added `workflow.createAgent(...)`, a programmatically driven agent runtime. {/* note: entry-5 */}
- Added `workflow.createAgentNode(...)`, an agent node for any workflow. {/* note: entry-6 */}
- Added `workflow.defineAgentConversationExecutor(...)`, which produces a complete conversation executor in one call. {/* note: entry-7 */}
- Added conversation configuration, token usage, tools, params, and OpenAI gateway wiring inside that executor. {/* note: entry-8 */}
- Added the `createAgentConversationProject(...)` and `createAgentProjectParams(...)` split form for projects that must pass structure validation. {/* note: entry-9 */}
- Added agent input fields `prompt`, `images`, `workdir`, `provider`, `model`, and `baseUrl`. {/* note: entry-10 */}
- Added agent input fields `effort`, `agent`, `permissionPolicy`, `contextWindow`, `compact`, and the approval resume payloads. {/* note: entry-11 */}
- Added `effort` levels from `off` to `max`, with `ultra` meaning `max`, converging to what the model supports. {/* note: entry-12 */}
- Added `agent` as `build` or `plan`, where a plan turn's text renders as a single Plan row and asks for approval at the end of the turn. {/* note: entry-13 */}
- Added plan approval reusing the `decision` radio plus optional `instructions`, continuing in the same session as a build agent once approved. {/* note: entry-14 */}
- Added `permissionPolicy` as `read-only`, `workspace`, or `auto`, none of which prompts for a built-in tool. {/* note: entry-15 */}
- Added a neutral `metadata.kind` family for output items: `agent-part`, `agent-notice`, `agent-error`, and `agent-answer`. {/* note: entry-16 */}
- Added `contextUsage: { used, total }` to the output payload, which hosts render as the composer's used and total row plus a compaction entry point. {/* note: entry-17 */}
- Added `--context-window` to override the context-usage denominator. {/* note: entry-18 */}
- Added tool approval through `context.toolPermissions` and plan approval through `context.userInput`. {/* note: entry-19 */}
- Added token usage reported once through `context.tokenUsage.report(...)`, with nothing left for the project to implement. {/* note: entry-20 */}
- Added the `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` dependencies, shipped with the host's `steamharness` install. {/* note: entry-21 */}
- Added `AgentNodeOptions.createTools` returning `{ tools, close?() }`, where `close` runs when the turn ends. {/* note: entry-22 */}
- Added `AgentNodeOptions.createTools(context)` assembling tools beyond the seven built-ins, with programmatic runtimes using `AgentRuntimeOptions.extraTools`. {/* note: entry-23 */}
- Added `AgentInput.systemPrompt` supplying the system prompt per run and `AgentInput.images` traveling to the model with the prompt. {/* note: entry-24 */}
- Added `workflow.connectMcpServer(...)` to start and handshake a stdio MCP server and list the tools it exposes. {/* note: entry-25 */}
- Added `workflow.createMcpTools(...)` turning MCP tools into agent tools, keeping the `<serverId>_<toolName>` names. {/* note: entry-26 */}
- Added `workflow.normalizeMcpServers(...)` validating server definitions before anything is spawned. {/* note: entry-27 */}
- Added capability-bearing variables inheritable only by name, with `allowedInheritedEnvKeys` listing them and `inheritEnvironment` requesting them. {/* note: entry-28 */}
- Added `workflow.createProjectCapabilityTools({ context })` rendering a capability as native agent tools. {/* note: entry-29 */}
- Added `workflow.createProjectCapabilityServer(toolId, { context })` rendering the same capability as an MCP server. {/* note: entry-30 */}
- Added `workflow.runProjectCapabilityAction(toolId, context, args)` running one action by tool id for approval resumes. {/* note: entry-31 */}
- Added `workflow.listProjectCapabilityToolIds({ globalMemory? })` listing what a run will offer. {/* note: entry-32 */}
- Added `workflow.isProjectCapabilityAvailable(toolId)` reporting whether a capability can serve in this process. {/* note: entry-33 */}
- Added four built-in workflow capability tools — knowledge documents, KV, cross-session memory, and host configuration — keeping the tool ids of the built-in OpenCode project. {/* note: entry-34 */}
- Added `workflow.createSkillTools({ directories, approve? })` offering skills as a tool the model reads on demand. {/* note: entry-35 */}
- Added `workflow.runSkillAction(directories, args)` rerunning the same action by name for an approval resume. {/* note: entry-36 */}
- Added `deleteValue(key)` to the KV and PersistentValue namespaces, reporting whether an existing entry was actually removed. {/* note: entry-37 */}
- Added the `ask_user` built-in tool for plan-mode agents, letting the model ask mid-turn with choices, multi-select, and free text. {/* note: entry-38 */}
- Added `step` on a parameter definition, splitting a multi-question request into steps that keep one question's fields together. {/* note: entry-39 */}
- Added knowledge helpers on `relatedProjects.get(alias)`, reading and writing the target project's documents. {/* note: entry-40 */}
- Added `listEntrypoints()` and `runEntrypoint(id, args)` to list and invoke the target project's granted entrypoints. {/* note: entry-41 */}
- Added the `knowledge: { read, write }` and `entrypoints` grant fields, where declaring neither grants neither. {/* note: entry-42 */}
- Added `modelAttributes` letting a custom provider declare `contextWindow`, `maxTokens`, `cost`, and `thinkingLevelMap`. {/* note: entry-43 */}
- Added static `group: { id, title, order? }` display metadata on Workflow entrypoints, preserved in structure reports. {/* note: entry-44 */}
- Added `type: "file", control: "audio"` to parameter contracts, with duration and byte limits. {/* note: entry-45 */}
- Added video attachments and common video MIME inference to the Conversation default input contract. {/* note: entry-46 */}

#### Changed

- Changed an agent conversation to write its text where it was spoken, each run of text becoming its own `agent-part` row. {/* note: entry-47 */}
- Changed host-driven runs to stay unchanged, with the `conversation.openai.outputItemId` item produced only in them. {/* note: entry-48 */}
- Changed a turn's output items to order by where each one finished, putting tools and reasoning first and the answer where it was written. {/* note: entry-49 */}
- Changed tool approval to pause a run only in plan mode, since a build turn executes an already approved plan without asking again. {/* note: entry-50 */}
- Changed run report errors to carry an excerpt of the upstream HTTP response body, so a status phrase no longer hides the real reason. {/* note: entry-51 */}

#### Fixed

- Fixed the agent conversation context having never been implemented: every user message was a new process and the model only saw that one sentence. {/* note: entry-52 */}
- Fixed a restored transcript past the model window failing the whole request, by compacting on demand before the model is called. {/* note: entry-53 */}
- Fixed cancelled or interrupted turns leaving unanswered tool calls that providers refuse, trimming the unsettled tail before it is stored. {/* note: entry-54 */}
- Fixed a failed read or write of `agent.transcript.<sessionKey>` failing the whole turn, now reported as a row instead. {/* note: entry-55 */}
- Fixed the OpenAI / Responses adapter for agent projects always ending with "did not produce output item". {/* note: entry-56 */}
- Fixed `createAgentConversationProject({ outputItemId })` deriving the answer item id from the session instead of the declared one. {/* note: entry-57 */}
- Fixed a symlink inside the workspace letting `read`, `write`, `edit`, `grep`, and `find` reach outside it. {/* note: entry-58 */}
- Fixed a `bash` timeout or abort ending only the shell, now ending the whole process tree it started. {/* note: entry-59 */}
- Fixed cancelling a run not really stopping the turn, with `context.abortSignal` now calling pi's `agent.abort()`. {/* note: entry-60 */}
- Fixed `read` loading a whole file into memory, now streaming the requested line range past 8 MiB. {/* note: entry-61 */}
- Fixed `edit` expanding `$&` and `$'` as replacement patterns, now replacing literally. {/* note: entry-62 */}
- Fixed the compaction split point able to hand the whole transcript, current task included, to the summarizer. {/* note: entry-63 */}
- Fixed `/compact` flashing a compaction row when there was nothing to compact. {/* note: entry-64 */}
- Fixed an empty `effort` string being treated as a level, which left `reasoningEffort` unset on OpenAI-style endpoints. {/* note: entry-65 */}
- Fixed context usage estimated at one token per four characters, which undercounted Chinese by about three times. {/* note: entry-66 */}
- Fixed `kv_store` writing the runtime's own `tokenUsage.*`, `conversation.state`, and `agent.*` keys. {/* note: entry-67 */}
- Fixed the declared capability length limits (knowledge and memory `markdown`, `title`, `query`, `cursor`, KV `key`) not being enforced in the implementation. {/* note: entry-68 */}
- Fixed the memory `cursor` meaning different things to `list` and `search` without returned values carrying a `list:` / `search:` prefix. {/* note: entry-69 */}
- Fixed an unusable host bridge URL throwing through the other capabilities, with `isAvailable` now returning `false`. {/* note: entry-70 */}
- Fixed a server-published MCP tool schema that was not an object, too deep, or over 256 KiB taking the process down at registration. {/* note: entry-71 */}
- Fixed the MCP per-server tool cap being checked after a page is merged instead of before. {/* note: entry-72 */}
- Fixed MCP tool listing paging forever against a server that repeats its cursor, now reporting an error instead. {/* note: entry-73 */}
- Fixed host configuration `values` losing its key and value checks, so out-of-range arguments travelled to the host bridge. {/* note: entry-74 */}
- Fixed a skill file listing cut short by the 60-path cap reading as the whole of it. {/* note: entry-75 */}
- Fixed a node's `workdir`, `provider`, `model`, `effort`, and `agent` coming from the runtime options rather than the run's own input. {/* note: entry-76 */}
- Fixed `createAgentInputFromArgs` folding an unrecognised `--flag` and its value into the prompt. {/* note: entry-77 */}
- Fixed a turn that only called tools appending an empty assistant message to the conversation. {/* note: entry-78 */}
- Fixed a run carrying `hostInput` writing the workflow conversation, leaving the host's own record written twice. {/* note: entry-79 */}
- Fixed custom endpoints and credentials leaking through a process-wide model registry when concurrent runs use the same model ID. {/* note: entry-80 */}
- Fixed `AgentInput.workdir` only affecting the output payload while the built-in tools stayed inside the runtime's workdir. {/* note: entry-81 */}
- Fixed image attachments disappearing before the model, with the host's `imageFiles` now read into base64. {/* note: entry-82 */}
- Fixed an image-only turn ending with `Prompt is required.`. {/* note: entry-83 */}
- Fixed `--images` being swallowed for `defineAgentConversationExecutor` / `createAgentProjectInput` projects. {/* note: entry-84 */}
- Fixed agent model calls carrying no retry budget, so the first 502 or mid-stream drop ended the whole run. {/* note: entry-85 */}
- Fixed a model stream cut off mid-answer failing the turn on `terminated`, now continuing and keeping what was produced. {/* note: entry-86 */}
- Fixed a turn cut off by the model's output limit being finalized as a finished answer, now continuing on a separate 2-attempt budget. {/* note: entry-87 */}
- Fixed a message announcing a tool call but carrying none being finalized as a successful text-only answer. {/* note: entry-88 */}
- Fixed a model stream ending without a verdict leaving the turn hanging forever, now synthesized into a recoverable error. {/* note: entry-89 */}
- Fixed reasoning buffered until the turn ended, leaving high-effort models with nothing to show while they thought. {/* note: entry-90 */}
- Fixed related project knowledge writes bypassing the per-key grant on the mutation route, where the index and documents were written directly. {/* note: entry-91 */}
- Fixed `readEntrypointOutput(...)` returning a failed entrypoint's result as a payload. {/* note: entry-92 */}
- Fixed an unreachable related project knowledge base reporting only "relation unconfirmed" instead of the missing persistent-value handle. {/* note: entry-93 */}
