# Core 0.1.2

2026-10-27 · Tag `steamharness/v0.1.2` · npm

#### Pi Durable

- [Fixed] Reset retry and continuation budgets after a complete successful model response so later failures restart at Retry 1 / 10. Consecutive failures, interrupted streams and process recovery retain their current budget; retry records with repeated numbers remain separate and preserve their history positions. {/* note: entry-1 */}
- [Fixed] Emit automatic retry records after interrupted content and before its continuation instead of appending them at completion. Durable sessions and reopened history retain their position and collapsed details. {/* note: entry-2 */}
- [Fixed] Project durable model usage per answer turn without mixing independent forks, inherited history or follow-ups, while retaining failed retries and in-turn compaction consumption. Publish current context occupancy per conversation through follow-ups, streaming, compaction and reset; uncalibrated estimates include actual system instructions, prompt sections and tool declarations. {/* note: entry-3 */}
- Fix durable streaming of thinking, text and tool block starts and deltas, preventing sparse content indices, type access failures and repeated text. Runtime exceptions settle unfinished tasks and queues under the same owner, persist the failure and publish current terminal state, so reopening cannot continue failed work. Normal host shutdown still preserves recovery checkpoints. {/* note: entry-4 */}
- [Fixed] Settled durable tasks no longer project a retained abort request as stopping. Completed cancellation and reopened history expose the actual terminal outcome. {/* note: entry-5 */}
- [Added] Atomically promote a queued durable input into the current turn while retaining its request identity, images and receipt. Inputs already consumed are never sent again. {/* note: entry-6 */}
- [Fixed] Scope tool output identities to committed assistant messages so reused call IDs across turns do not suppress events or misidentify historical tools. Bind approvals to durable tasks so later calls cannot reuse a previous decision in ordinary Agent mode. Task snapshots retain submitted arguments for inspecting nested calls. {/* note: entry-7 */}
- [Fixed] Capture durable session commands as JSON before queuing and reject invalid task input before reserving its request identity. Check persisted definitions for predeclared catalogs on reopen, and protect both SQLite backup paths with owner locks to prevent definition drift and destination creation races. {/* note: entry-8 */}
- Added durable Agent registries/hooks, custom tasks and timer checkpoints, authorized tool discovery and deferred MCP. Opt-in QuickJS Code Mode and remote ExecutionEnv retain approval, cancellation and replay checks for nested calls. Add resource diagnostics, custom storage and offline SQLite import/export, with self-contained public extension types. {/* note: entry-9 */}
- Added durable Agent session controls: Harness inbox, steer/withdraw, background compaction, context reset/handoff, independent forks, versioned configuration, and transactional plans. Public snapshots and host leases retain tools and the AI bridge after foreground completion. {/* note: entry-10 */}
- Added project-enabled restricted subagents, durable single-result reporting, and nested tool calls with tool/model allowlists, concurrency limits, caller/approval checks, scoped cancellation, and separate parent/child task and usage projections. {/* note: entry-11 */}
- Fix lost tasks after approval pauses in memory agents and initial transcripts overwriting durable history. After a process interruption during streaming, continue from committed text and discard incomplete tool calls. {/* note: entry-12 */}
- Serialize stale local KV lock recovery after a crash so concurrent reclaimers cannot delete a new owner's lock or break mutual exclusion. {/* note: entry-13 */}
- Upgrade Agent to Pi / Pi Durable 1.2.0 with Harness and SQLite as the sole durable execution backend. Add request deduplication, tool and approval recovery across processes, idempotent usage projections and durable cancellation. Old KV transcripts are no longer read; interrupted writes and commands with unknown results are not automatically replayed. {/* note: entry-14 */}

#### New Features

- **Standard Conversation composer**: always uses the standard message input, with attachment capabilities moving to `conversation.attachments`. {/* note: entry-15 */}
- **Conversation resource cards**: agents create, update, pin, or remove cards by stable `cardId`, and browser cards accept `preview` to control the preview area. {/* note: entry-16 */}
- **Agent context ring**: occupancy appears before the first model response and updates during streaming, tool results, and compaction. {/* note: entry-17 */}

#### Breaking Changes

- **Product rename**: the SDK global `workflow` is now `steamharness`; `defineWorkflow`, `runWorkflow`, `defineWorkflowExecutor` and `defineWorkflowEntrypoint` are now `defineProject`, `runProject`, `defineProjectExecutor` and `defineProjectEntrypoint`, and the remaining `Workflow*` exports were renamed with them. {/* note: entry-18 */}
  Migration: Apply the new contract described in this entry before upgrading.
- **Field rename**: `workflowId` / `workflowName` are now `projectId` / `projectName`; `WorkflowError` is now `HarnessError`, the `workflow_execution` error type is now `execution`, and the `workflow` metadata key is now `project`. {/* note: entry-19 */}
  Migration: Apply the new contract described in this entry before upgrading.
- Conversation removes its enable setting and custom main fields, and legacy configurations now fail structure validation. {/* note: entry-20 */}
  Migration: declare attachments as `conversation.attachments` and keep parameters in Auxiliary / Quick / Mode / Slash only.
- Executor `params` become ordered action declarations, and the legacy `panel` declaration is no longer accepted. {/* note: entry-21 */}
  Migration: let Auxiliary and Quick define several groups each, declare Conversation Mode explicitly, and keep the display order through `paramLayout.actions` in structure reports.
