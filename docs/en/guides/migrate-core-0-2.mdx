# Fresh aggregate declarations

Create a root project identity, register its entries, and move child settings into child declarations. The current protocol requires new declarations and data, without legacy-model compatibility or automatic migration.

## Declaration example

`package.json`

```json
{
  "name": "workspace-example",
  "version": "1.0.0",
  "private": true,
  "type": "module"
}
```

`steamharness.json`

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "name": "workspace-example",
  "version": "1.0.0",
  "defaultEntry": "agent",
  "entries": [
    {
      "entryId": "agent",
      "root": "agent"
    },
    {
      "entryId": "database",
      "root": "database"
    },
    {
      "entryId": "map",
      "root": "map"
    }
  ]
}
```

`agent/steamharness.json`

```json
{
  "type": "conversation",
  "name": "Assistant",
  "entry": "index.ts",
  "databases": []
}
```

`database/steamharness.json`

```json
{
  "type": "workflow",
  "name": "Database operations",
  "entry": "index.ts",
  "configuration": "configuration.json",
  "databases": [
    "data"
  ]
}
```

`map/steamharness.json`

```json
{
  "type": "kanban",
  "name": "Map",
  "entry": "dist/steamharness/entries/map/build/map/index.html",
  "databases": []
}
```

Keep business code directories and register them in root entries. Remove child SteamHarness identities. Executor `projectType` still describes the entry runtime contract; the root package has no single type.

Use `context.entries.get(entryId)` for Workflow calls. Define relational models and generate descriptors for `context.databases.connect(descriptor)`, with Server-managed account/project/entry bindings. Knowledge uses `context.knowledgeBases.get(alias)` with independent declarations and configuration. Old KV data is not migrated.

When cleaning old identities, limit deletion to their old-model records. Do not clear unrelated host business data. The new project does not read old data. See [Workflow model](/en/concepts/workflow-model) and [Project storage](/en/concepts/data-storage).

## Validate and bind

1. Run `steamharness check .` to inspect the root and every child declaration.
2. Generate relational models and explicitly create or select an authorized resource.
3. Use `database bind` to save the account/entry binding on Server. `databases` declarations contain alias strings only.
4. Run each entry, then test data access and conversation isolation.
