# workspace publish

Use `workspace publish` to publish a prepared Server draft. The entire aggregate shares one version and source hash.

## Command

```sh
pnpm exec steamharness workspace publish <project-id> --release-log "Update entries"
```

Complete local validation and [upload](/en/cli/workspace/upload) first. Publication reads root `steamharness.json.version`; a version cannot be published twice.

## Concurrency checks

The CLI submits the source hash and each entry's `expectedConfigurationRevisions`. Revisions are nonnegative safe integers starting at `0`. Server rejects publication if source or configuration changed during preparation.

After a conflict, read the latest draft and configuration, inspect the changes, then upload or publish again. Do not repeatedly submit stale revisions.

## Release contents

A version contains every entry's code, dependency declarations, configuration definitions, models, and static artifacts. It excludes host credentials, runtime state, and business data. Recipients obtain resource access and bind entries under their own account.

Server processes only the static snapshot. Inspect the version and source hash with [versions](/en/cli/workspace/versions) after publishing.
