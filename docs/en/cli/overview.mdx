# CLI overview

Install `@steamharness/cli` to use `steamharness`. Inside a project, prefer `pnpm exec steamharness` so commands use the version installed by that project.

## Typical workflow

Inspect and execute locally before uploading:

```sh
pnpm exec steamharness check .
pnpm exec steamharness structure .
pnpm exec steamharness run .
pnpm exec steamharness json .
```

Choose the Server address explicitly. Replace `<project-id>` below with a registered project ID:

```sh
pnpm exec steamharness workspace health --server http://localhost:7126
pnpm exec steamharness workspace login --server http://localhost:7126
pnpm exec steamharness workspace upload <project-id> --path .
pnpm exec steamharness workspace publish <project-id> --release-log "Initial release"
```

## Databases and entries

Local commands read `entries` from the aggregate root. `--entry` selects an entry, while `check` validates all entries by default. Create, grant, migrate, and bind relational resources before use. Knowledge resources use separate declarations and bindings.

CLI Web and Studio share user-level project registration. See [data storage](/en/concepts/data-storage) for storage locations and access rules.
