# CLI and aggregate entries

Run the installed CLI from the aggregate root using Node.js 24. Install project dependencies first, then validate the root manifest and every registered entry. Child directories have no separate project identity.

```sh
pnpm exec steamharness check .
pnpm exec steamharness check . --entry database
pnpm exec steamharness structure . --entry database
pnpm exec steamharness run . --entry database --entrypoint search -- --query example
pnpm exec steamharness json . --entry database --entrypoint search -- --query example
pnpm exec steamharness web . --entry agent
pnpm exec steamharness mcp . --entry database
```

## Entry selection

`--entry` selects the window entry. `run`, `json`, `structure`, `mcp` and `web` default to `defaultEntry`. `check` inspects all entries unless `--entry` selects one. `--entrypoint` selects an operation inside a Workflow. Keep the two identifiers distinct.

Entry IDs and paths follow the [reserved artifact name rules](/en/concepts/data-storage#artifacts-and-runtime-data), avoiding collisions with caches, reports, generated databases, and Windows device names.

Arguments after `--` pass unchanged to the Workflow. `--locale zh-CN|en` selects host text without altering business parameters.

## Build and run a release

Build a release from the aggregate root, or prepare the latest release when starting an entry:

```sh
pnpm exec steamharness release . --json
pnpm exec steamharness run . --release --entry database --entrypoint search -- --query example
pnpm exec steamharness web . --release --entry agent
```

The release project is written to `dist/release/project/`, with its archive under `dist/release/`. The `--release` option on `run`, `json`, and `web` runs only entries included in the release configuration. A failed build reports an error and preserves the previous complete output.

In Studio, click **Run (Release Mode)** beside the Run button. Studio saves the project files, builds the release, and opens a new window rooted at the release run directory with the selected entry. That entry must be included in the release configuration.

The release window shows the aggregate project's logo and name in the upper left, stays in Steam mode, and omits Editor and Assistant from the tools area. Source windows show the version declared in source. Opening a release project shows its installed version and checks for upgrades.

## Validation and output

`check` and `structure` statically inspect registered entries without executing user modules. Unsafe paths, duplicate IDs, invalid defaults, mismatched types and legacy declarations fail. `json` returns a run report with project and entry identity. Failed runs return a nonzero exit code. Cancellation propagates to the current execution and calls to other entries.

Use [workspace commands](/en/cli/server-workspace) for remote static project management. Server never executes project code.

Kanban cards in assistant replies preview their saved project, entry and configuration, keeping the owning host's entry prefix in resource URLs. Studio's `get_kanban_diagnostics` covers both open workspace boards and assistant cards, returning page instances, configuration identity and the latest 50 reads; `previews` identifies card sources. Use the current `instanceId` and `configurationId` to call page methods explicitly declared `readOnly: true` and verify actual state such as image readiness.

Closing or refreshing a card invalidates its old instance; missing live instances do not prove successful rendering. File bridge reads allow up to 120 seconds without an earlier transport timeout; reads exceeding that limit still require investigation of the file path.
