# Database KV and conversations

Business data requires an approved database alias declared by the entry. Hosts manage run history, tool approvals, drafts and conversation state by `projectId + entryId`; data grants do not replace execution permissions.

## KV scopes

```ts
const database = context.databases.get("data");
await database.kv.setValue("settings:theme", "dark");
const theme = await database.kv.getValue("settings:theme");
const knowledge = context.knowledgeBases.get("docs");
const document = await knowledge.getDocument("guide");
```

`database.kv` addresses shared space keys. `database.kv.conversation` additionally isolates the current project, entry and `conversationId`. Projects sharing a space can share top-level KV, but equal conversation IDs do not expose each other's conversation KV.

```ts
await database.kv.conversation.setValue("lastQuery", "example");
await database.kv.updateValue("counter", value => Number(value ?? 0) + 1);
```

`updateValue` uses host CAS and rereads on conflicts; both read and write access are required. `database.transaction` commits within one space, not across spaces. Knowledge documents live in independent platform relational tables and use `context.knowledgeBases.get("docs")`.

## Calls within the aggregate

```ts
const operations = await context.entries.get("database").listEntrypoints();
const result = await context.entries.get("database")
  .runEntrypoint("search", ["--query", "example"]);
```

Only registered Workflow entries expose operations. The host preserves the current actor, cancellation signal and tool permissions, loads the target configuration snapshot and database bindings, and authorizes again. Ask mode cannot acquire Build permissions through another entry.

## Last writer

Writes record `projectId`, `entryId` and available `runId` and `conversationId`. These identify the source without changing the space address or granting access.

## Knowledge and attachments

`context.knowledgeBases.get("docs")` provides listing, reading, creation, editing, deletion, search and line reads. `context.knowledgeBases.get("docs").files` manages attachments. Documents, files, indexes and revisions use knowledge base authorization, independently of KV spaces. See [Knowledge API](/en/core-api/knowledge-documents).

## Conversation state

Hosts persist each entry's history, input queue, drafts, parameters, token usage and approvals independently. CLI Web preserves background runs while switching windows. Studio entry tabs share the host and keep separate conversations. Configuration changes apply to the next execution. Recovery must match both project and entry, including pending approvals.

Conversations, messages, queues, runs, usage and Agent checkpoints use Server platform relational tables, isolated by account, project and entry, independently of business KV. CLI/Studio no longer read or migrate legacy JSON or default SQLite history. Persistent history requires sign-in and connectivity. Disconnection stops execution without clearing sign-in or falling back locally. Files and attachments remain host managed. See [platform runtime storage](/en/core-api/runtime-storage).
