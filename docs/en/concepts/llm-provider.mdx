# LLM Provider

An LLM Provider connects model calls to a workflow. Projects can configure their own endpoint, model, and API key. Server neither stores nor proxies those third-party credentials.

## System AI catalogue

Call `getServerLLMCredentials({ signal })` to obtain the catalogue available to the current account. Catalogues are reused for 30 seconds in the process, scoped to service URL and account; concurrent refreshes are merged.

| Situation | Behavior |
| --- | --- |
| A fresh catalogue is needed | Pass `{ fresh: true, signal }` for an online refresh |
| Proxy credentials are about to expire | Refresh credentials online |
| The account or service URL changes | Load the corresponding catalogue |
| One caller cancels its wait | Other callers' shared refresh continues |

Catalogues and short-lived tokens remain in memory. Server still authorizes every model request.

## Create a provider ref

Create a provider ref so that nodes resolve configuration when they run:

```ts
const llmProvider = steamharness.createLLMProviderRef("default", () => {
  return steamharness.createLLMProviderFromConfig();
});
```

The node resolves the provider at runtime instead of reading business configuration while the module is loading.

## LLM nodes

Non-streaming node:

```ts
const llmNode = steamharness.createLLMNode<Input>({
  name: "answer-llm",
  provider: llmProvider,
  mapInput(input) {
    return {
      system: "You are a concise assistant.",
      prompt: input.message,
      maxOutputTokens: 300,
    };
  },
});
```

Streaming nodes use the same provider:

```ts
const llmStreamNode = steamharness.createLLMStreamNode<Input>({
  name: "answer-stream",
  provider: llmProvider,
  mapInput(input) {
    return { messages: [{ role: "user", content: input.message }] };
  },
});
```

## Project configuration fields

Declare the model fields in `configuration.json`, then enter values in Project configurations. `steamharness.createLLMProviderFromConfig()` reads these fields:

- `LLM_TYPE`
- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL`

Each run reads its frozen configuration snapshot, without falling back to `.env` or process variables. `LLM_BASE_URL` must be an HTTP(S) URL without a username, password, query, or fragment.

Third-party services use their own fields through `steamharness.getConfig()`. Host account credentials and transport settings remain host managed.

## Provider types and errors

The provider factory supports the types in `LLM_PROVIDER_TYPES`. When no model is configured, it selects a default by provider type; tests can use a mock provider.

A provider failure becomes a workflow error in the execution report. Unsupported optional settings may produce a compatibility warning; authentication failures, unavailable models, and upstream request failures remain errors.
