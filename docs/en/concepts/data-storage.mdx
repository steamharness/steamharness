# Runtime and file storage

CLI Web and Studio save conversations, runs, queues, usage, and Agent state locally by default. These records do not live in project source or `dist/`. Local runs do not require a Server login.

When source has no valid UUID, the host derives a stable local storage key from its canonical project directory without changing the manifest. Different directories keep separate records, and reopening the same directory reuses its history. Release builds still validate the authored project UUID.

| Content | Location |
| --- | --- |
| Standalone SDK history | `~/.steamharness/runtime/<projectId>/<entryId>/` by default |
| CLI Web history | An external directory selected with `--data-dir` |
| Server runtime storage | Stored by Server after an explicit choice, subject to account and project access |
| Managed project files | Uploaded to Server and read under project membership |
| Configuration attachments | Read under the project, entry, and configuration version |

See [Runtime storage](/en/core-api/runtime-storage) for APIs, backups, and failures. See [Files](/en/concepts/files) for the distinction between managed files and configuration attachments.

## Artifacts and runtime data

Rebuildable output lives under `dist/steamharness/` at the aggregate project root. Child entries do not create separate output roots.

| Content | Path |
| --- | --- |
| Root entry builds and static pages | `dist/steamharness/build/<entryId>/` |
| Child entry builds and static pages | `dist/steamharness/entries/<encodeURIComponent(entry.root)>/build/<entryId>/` |
| Cache, test reports, and releases | `dist/steamharness/cache/`, `dist/steamharness/reports/`, `dist/steamharness/release/` |

Each builder cleans only its own output directory. Rebuilding after deleting `dist/` leaves runtime history outside the project intact.

Entry IDs cannot use the managed directory names `steamharness`, `cache`, `reports`, `release`, or `tmp`, or the Windows device names `con`, `prn`, `aux`, `nul`, `com1`–`com9`, and `lpt1`–`lpt9`. An entry path under `dist/` must point to its own `build/<entryId>/` directory.
