# Kanban entries

Kanban is a static HTML entry in an aggregate project and does not export an executor. Register its source directory at the aggregate root:

```json
{ "entries": [{ "entryId": "map", "root": "map" }] }
```

Declare the entry in `map/steamharness.json`:

```json
{ "type": "kanban", "name": "Map", "entry": "dist/steamharness/entries/map/build/map/index.html", "configuration": "configuration.json", "databases": [] }
```

`root` identifies the source directory. A Kanban `entry` is relative to the aggregate root and defaults to `dist/steamharness/build/<entryId>/index.html` for root entries or `dist/steamharness/entries/<encodeURIComponent(entry.root)>/build/<entryId>/index.html` for child entries when omitted. Workflow/Conversation modules remain relative to their own `root`. Frontend builders clean only their source root's `build/<entryId>/`, preserving database outputs.

Build on the client before upload. Server validates, stores and serves static files without installing dependencies or executing builds. Relative assets and all registered entry artifacts are retained during packaging and installation.

Studio includes a minimal board and two task boards. Templates generate database descriptors before building `dist/steamharness/build/main/index.html`. Task boards use an approved database with the `data` alias and isolate rows by configurationId. Missing bindings or failed reads disable editing; failed writes preserve drafts.

## Configuration and presentation

The host injects `window.steamHarnessKanban`. `getConfiguration()` reads the current entry configuration; `getPresentation()` reads the presentation mode. Listen for `steamharness:kanban-configuration-change` and `steamharness:kanban-presentation-change`. Named configurations, snapshots and configuration files are isolated by `projectId + entryId`.

Identical configuration snapshots do not repeat configuration events or ready notifications. Changes update the existing page. CLI Web and Studio retain the preview during connection recovery; a sustained interruption shows a compact overlay without shifting the map canvas.

The file bridge allows up to 120 seconds to read large attachments, and its background worker uses the same file deadline. A timeout keeps the error and retry action available.

## Data bridge

```js
import { data } from "./dist/steamharness/generated/database/browser/index.js";
const api = window.steamHarnessKanban;
const database = await api.databases.connect(data);
const configurationId = api.getConfiguration().id || "default";
const page = await database.task.rows({ where: { configurationId } });
const row = await database.task.insert({ id: crypto.randomUUID(), configurationId, title: "Review", status: "todo" });
await database.task.update({ key: { id: row.values.id }, rowVersion: row.rowVersion, data: { status: "done" } });
```

The alias must be declared in this entry's `databases` and approved before use. The host validates entry identity, actor and space grants. Pages cannot select arbitrary projects or spaces. Use `window.steamHarnessKanban.knowledgeBases.get("docs")` for documents and `window.steamHarnessKanban.knowledgeBases.get("docs").files.createFile/readFile/deleteFile` for attachments.

Server stores knowledge attachments in private file storage; PostgreSQL stores metadata and digests. Table writes use rowVersion concurrency checks. Read and write failures remain explicit; failed writes preserve the saved rows and user draft.

## Page methods

```js
window.steamHarnessKanban.methods.register({
  name: "focus", description: "Focus a map location", readOnly: true,
  inputSchema: { type: "object", properties: { x: { type: "number" } } },
}, async (input, { signal }) => ({ focused: input.x }));
```

Targets include `projectId`, `entryId`, source, location and instance. Resource cards and previews also carry `entryId`. Validate business parameters and honor cancellation signals. Enumerate again after an instance refreshes or closes.

## Hosts and security

In Studio, page shortcuts take priority: call `event.preventDefault()` in a `keydown` handler to claim a shortcut. Unhandled keys reach Studio's keybinding service. This applies to both Kanban tabs and resource card previews. Kanban pages in a standalone browser retain normal browser keyboard behavior.

CLI Web uses `/entries/map/`; Studio opens entries as independent tabs. Server Web provides authenticated static previews. Previews use sandboxing, constrained relative asset paths and short-lived capabilities. `studio.getLocalAnalysis()` is available only in supported local Studio hosts.

Publish the aggregate as one unit. Requirements travel with the package; bindings and credentials do not. See [Database spaces](/en/concepts/data-storage) and [Packaging](/en/cli/workspace/pack).

Knowledge requires an independent `knowledgeBases: ["docs"]` declaration, a root `knowledgeBases.docs` configuration mapping and a Server binding. Subscribe with `knowledgeBases.get("docs").subscribe(...)`; changes to a relational alias with the same name do not trigger this subscription.

## Aggregate Workflow calls and Conversation subscriptions

In local CLI Web or Studio, call a registered Workflow with `window.steamHarnessKanban.entries.get("api").runEntrypoint("state", ["--payload", "{}"])`. The page cannot select a user or project identity. Keep business writes and message routing in that Workflow.

`await window.steamHarnessKanban.entries.list()` reads the local aggregate catalogue directly and returns `entryId`, `name`, `type`, and `status` without waiting for a business database. Show registered Conversations first, then load saved Bot profiles in the background. An entry does not imply that its profile, binding, or execution permissions are ready. Preserve the local list and retry guidance on failure without presenting unsaved data as saved.

Mount a native private chat with `conversations.mount(container, { entryId, conversationId, draft?, locale? })`. Give the container a usable height and call the returned disposal function when unmounting or changing configurations. The view reuses CLI Web Conversation rendering, Markdown, model parameters, streaming, drafts, FIFO queues, approvals, cancellation, Trace, and retry. It shares its Controller and persisted history with the native Conversation tab. This embed accepts text and parameters; attachment upload, exports, and navigation to conversation branches are currently unavailable.

One Kanban page can mount multiple views of the same Conversation, such as a group composer and a focused Bot conversation. These views share the page’s session writer while keeping UI parameter resolution and drafts separate. Other pages retain independent write isolation. Closing a view releases its claim immediately; the last view releases an idle session, while running tasks retain their execution owner.

To submit through a business Workflow, provide `submit: { entryId: "api", entrypointId: "message-send", payload: { workspaceId, threadId } }`. The host adds the bound `conversationId` and the current `text`, `params`, and `requestId`, then reads the durable receipt from `{ data: { errCode: 0, errMessage: "", data: [{ id, conversationId }] } }`. The receipt `id` must match the request ID admitted to the Conversation. The native UI correlates optimistic messages with this ID to avoid duplicates. Queue edits, approvals, and cancellation continue through the same native Controller; the business Workflow must reconcile those operations.

Projects can supply custom `@` references and display slots to an embedded view. For example, turn project members into mention choices and resolve recipients in a business Workflow:

```ts
const view = await window.steamHarnessKanban.conversations.mount(container, {
  entryId: "assistant", conversationId: "room-assistant",
  ui: {
    presentation: "composer",
    placeholder: "Write a message, @ to choose participants",
    mentions: [{ kind: "bot", label: "Bot", items: [
      { value: "researcher", label: "Researcher", description: "Verify information" },
    ] }],
  },
  submit: { entryId: "api", entrypointId: "message-send", payload: { roomId } },
}, {
  slots: { header: participantsElement, transcript: messagesElement, footer: statusElement },
  onSubmission: event => updateSubmission(event), // sending / accepted / failed
  onSubmitted: ({ requestId, receiptId }) => recordReceipt(requestId, receiptId),
});
await view.update({ presentation: "composer", mentions: updatedGroups });
// Call view() when unmounting.
```

`onSubmission` reports `sending`, `accepted`, and `failed` for the same `requestId`. `sending` is provisional local feedback, not a successful delivery. `accepted.result` contains the authorized submit Workflow result, so projects can update their business transcript and subscribe to target sessions without waiting for a full reload. Reconcile by request ID with durable records. After a failure, the user can explicitly call `view.retry(requestId)` to reuse the native submission identity and parameters while preserving the current draft. Submissions are never replayed automatically. Full native transcripts retain their own optimistic messages.

Choosing an item only inserts and highlights `@bot:researcher`; sending invokes the business Workflow. Each `kind` is a project-owned namespace and cannot replace `skill`, `file`, or `entry`. Up to 16 groups and 200 items per group are supported. Labels and descriptions render as plain text. `view.update(ui)` replaces all UI options while preserving the input, draft, and native conversation. Update it when membership changes. Built-in skill, file, and project-entry menus also work in embedded views; files retain their short names and full-path hover text.

The default `presentation: "conversation"` retains the full native transcript. `"composer"` hides it and displays project messages in `slots.transcript`. The native input resizes to fit its content, with the `@` menu opening above it. All three optional slots are project-owned DOM nodes that remain in the Kanban document. The project renders and subscribes to its transcript and handles approvals, cancellation, and each member's queue. Slots do not pass HTML or executable callbacks into the native sandbox. `onSubmitted` reports durable admission, not model completion.

A business Workflow may return a durable receipt for another target conversation, such as a participant mentioned in the current topic. The host releases the local submission after acknowledgment; the project transcript subscribes to replies from other targets. The business Workflow validates membership, permissions, idempotency, conversation isolation, and delivery states. Mention choices do not grant execution privileges.


The native view runs in a separate `allow-scripts` sandbox over the existing Bridge/SSE channel without receiving a host login token. The host binds the project, source entry, user, page, and one conversation, rejecting cross-session and account/project configuration actions. Identity, configuration, or preview changes dispose old views. Each Kanban host permits up to eight views. Pages may retain recently visited views to reduce switching work and should dispose views they no longer need.

Workflow calls have a separate 120-second Bridge deadline for database authorization and durable receipts. Conversation submit, queue resume, input resolution, and cancellation IPC allow the same 120-second budget; ordinary read IPC retains 15 seconds. Receipts never wait for model completion: run model work asynchronously through a durable queue. A timeout may follow a committed write: retain the request ID and query its receipt instead of automatically replaying the write.

Known public database error codes survive node reports and Workflow calls. The Bridge maps only allowlisted codes, such as `DATABASE_UNBOUND`, `DATABASE_BUSY`, and `DATABASE_SCHEMA_MISMATCH`, to fixed guidance. It never exposes underlying connection strings, SQL, file paths, or arbitrary exception text.

`conversations.snapshot(entryId, conversationId)` reads the native projection. `conversations.subscribe({ entryId, conversationId }, listener, onError)` delivers streaming output, queues, approvals, and run state over the existing SSE / IPC channel and returns an unsubscribe function. Up to 16 subscriptions are allowed. Configuration, identity, and iframe generation changes retire subscriptions. Reconnect by reading and subscribing again. Match `requestId` to determine completion; do not assume the last message belongs to the current request.

Server static previews return `409` with safe code `ENTRY_RUNTIME_UNAVAILABLE` for execution operations. Show guidance to open the project in local CLI Web / Studio. Read-only resource previews in conversations retain their existing data access boundary.
