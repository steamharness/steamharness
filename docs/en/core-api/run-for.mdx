# runFor

Use `steamharness.runFor()` to process `items` sequentially, carrying each iteration's returned state forward. Runtime emits `branch-node` start and completion events; Diagram groups the body in a loop container.

## Example

```ts
const finalState = await steamharness.runFor(seed, context, {
  name: "Round loop",
  maxIterations: 6,
  items: (state) => Array.from({ length: state.rounds }, (_, index) => index + 1),
  async run(state, value, index, loopContext) {
    return steamharness.runNode(addRoundNode, { ...state, value, index }, loopContext);
  },
});
```

## Signature

```ts
steamharness.runFor<State, Item>(
  input: State,
  context: RunContext,
  options: {
    name?: string;
    items(
      input: State,
      context: RunContext,
    ): Iterable<Item> | AsyncIterable<Item> | Promise<Iterable<Item> | AsyncIterable<Item>>;
    run(input: State, item: Item, index: number, context: RunContext): State | Promise<State>;
    maxIterations?: number;
    metadata?: Partial<NodeMetadata>;
  },
): Promise<State>
```

## Parameter

|Parameter|Type|Description|
| --- | --- | --- |
| `input` | `State` |Initial cycle state.|
| `context` | `RunContext` |runtime context for hooks, provider, databases, files, abortSignal.|
| `options.name` | `string` |Diagram and the cycle node title displayed in Trace. Default `Run for`.|
| `options.items` | `Iterable` / `AsyncIterable` |A cycle term is generated based on the initial state. Supports synchronous and asynchronous iterable, and also supports return Promise.|
| `options.run` | `function` |The loop body of each item. Receives the current state, item, index and context starting from `0`, and returns the next round state.|
| `options.maxIterations` | `number` |The maximum number of iterations. Default `1000` to prevent accidental infinite loops.|
| `options.metadata` | `Partial<NodeMetadata>` |Overrides the loop node meta information. The default type is `run-for`.|

## Operation Report

`runFor` uses the standard node name `run-for` and runs type as `branch-node`. The `executionInfo` of the completion event will contain:

```json
{
  "loopType": "for",
  "iterations": 3,
  "iterationCount": 3,
  "maxIterations": 1000,
  "completed": true
}
```

`completed` is `false` on failure and retains the number of iterations that have completed.

## Diagram

Static structure analysis recognizes `items`, `maxIterations`, and `run` as object literals. `steamharness.runNode`, `steamharness.runStreamNode`, `steamharness.runIf`, `steamharness.runFor`, and `steamharness.runWhile` in `run` become loop body nodes and are wrapped by the loop container in shared runtime UI Diagram. In order to make Diagram readable, the loop configuration is kept as literal as possible; the dynamic assembly options can still be run, but the static diagram can only show limited information.

## Error

|Situation|Error Type|Description|
| --- | --- | --- |
|More than `maxIterations`| `node_execution` |Throw out `Run-for node "<name>" exceeded maxIterations (<value>).`.|
|`items` or `run` error thrown| `node_execution` |The original error is wrapped as `HarnessError` and written to the loop node report.|
|Break before execution or in a loop|`execution_aborted` or `node_execution`|From `context.abortSignal`.|
