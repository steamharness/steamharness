# Identify the runtime platform

The runtime platform identifies where code executes. Terminals and CLI Web use `cli`; Studio uses `desktop`.

## Example and signatures

```ts
const platform = steamharness.getRuntimePlatform();
const local = steamharness.isCli();
```

```ts
steamharness.getRuntimePlatform(): "cli" | "desktop"
steamharness.isCli(): boolean
steamharness.isDesktop(): boolean
```

An absent host marker defaults to `cli`; an unknown nonempty marker throws. Server does not execute project code, so there is no Server execution marker or `isWeb()`.

## Configure storage separately

Use generated descriptors with `context.databases.connect(descriptor)` for business databases. Server resolves an authorized PostgreSQL resource from the account and entry binding. Knowledge access uses `context.knowledgeBases.get(alias)`.

Local development can run Server and Docker PostgreSQL on one machine. [Runtime storage](/en/core-api/runtime-storage) determines where history persists; do not infer it from the platform name.

## Host resource management

Studio and CLI Web open authenticated Server Web pages for models, data, attachments, and account grants. Links contain no account token.

SQL credentials, connections, and binding identities remain in the host. Project RPC and Browser pages receive only authorized model operations. This API exposes neither local database directories nor a KV management context.
