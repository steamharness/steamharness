# Runtime platform

```ts
workflow.getRuntimePlatform(): "cli" | "desktop"
workflow.isCli(): boolean
workflow.isDesktop(): boolean
```

Platforms describe where code executes. Terminal and CLI Web use `cli`; an absent marker defaults to `cli`. Unknown nonempty markers throw. Server does not execute projects and provides no server execution marker or `isWeb()`.

```ts
const platform = workflow.getRuntimePlatform();
const local = workflow.isCli();
```

Runtime platform does not select a storage backend. Import a generated database descriptor and call `context.databases.connect(descriptor)`; the Server account and entry binding choose an independently authorized PostgreSQL resource. Knowledge uses `context.knowledgeBases.get(alias)`. Local development can run Server and Docker PostgreSQL on the same machine.

## Host resource management

Studio and CLI Web list Server resources and open authenticated Server Web pages for model, table, attachment and account access management. Links contain no account token. The host retains SQL credentials, connections and binding identities; project RPC and Browser pages receive only authorized model operations. There is no local database registry or KV management context.
