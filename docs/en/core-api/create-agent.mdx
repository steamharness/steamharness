# createAgent

Create a programmable Agent with `steamharness.createAgent()`, submit a prompt, and consume events. The runtime handles model and tool loops, reasoning effort, context compaction, plan approval, and durable sessions.

The runtime uses Pi Durable 1.2.0 as its only execution backend and requires Node.js `>=22.19.0`.

Core Agent includes the [i-have-adhd](https://github.com/ayghri/i-have-adhd) communication skill. The complete guide ships with the package and is loaded directly into each turn's system prompt, without installation, `/i-have-adhd`, or a configured `skill` tool. It favors action-first answers, short steps and fewer tangents in build mode, plan mode, custom `systemPrompt` personas and durable sessions. The user's language, format and requests for detailed explanations take precedence; `stop adhd mode` or `normal mode` stops the style. The skill shapes communication while task execution, plan-mode constraints and tool permissions retain their own rules.

## Example

```ts
const agent = await steamharness.createAgent({ workdir: ".", provider: "anthropic", effort: "high" });

for await (const event of agent.run({ prompt: "Summarize this repository", errCode: 0, errMessage: "" })) {
  if (event.type === "text_delta") process.stdout.write(event.delta);
}
```

Inside a workflow, [createAgentNode](./create-agent-node.mdx) or [defineBot](./define-bot.mdx) do more of the work for you.

## Signature

```ts
const agent = await steamharness.createAgent({
  storage?: AgentStorageFactory,
  workdir?: string,
  systemPrompt?: string,
  provider?: string,
  model?: string,
  baseUrl?: string,
  apiKey?: string,
  apiKind?: "openai-responses" | "anthropic-messages" | "openai-completions",
  webSearch?: boolean,
  modelAttributes?: AgentModelAttributes,
  effort?: AgentEffort,
  permissionPolicy?: AgentPermissionPolicySetting,
  mode?: AgentMode,
  tools?: string[],
  toolDefinitions?: ToolPermissionDefinition[],
  allowedDirectories?: string[],
  extraTools?: AgentTool[],
  sessionId?: string,
  session?: AgentSessionOptions,
  models?: MutableModels,
  resolvedModel?: Model<Api>,
}): Promise<AgentRuntime>
```

The returned runtime exposes:

| Member | Description |
| --- | --- |
| `run(input, host?)` | Run once, yielding `AgentStreamEvent` values. |
| `close()` | Close the Harness and release ownership. Unfinished work remains recoverable when the same store is reopened. Always call it after use. |
| `getContextUsage()` | Read current context occupancy as `{ used, total }`, including the message still streaming; returns `undefined` when the model window is unavailable. |
| `updateContextUsage({ used, total })` | Supply an absolute measurement of the current context. An active run immediately emits the update through `context_usage`; it does not count toward billed usage. |
| `sessionId` | The session id this runtime uses. |
| `reset()` | Clear the context projection; the next run checkpoints the new context. Active tasks must be settled first. |
| `restoreTranscript(messages)` | The record the next run continues from; only takes effect before the runtime has built its agent — see "The transcript". |
| `readTranscript()` | Inspect or export the model-visible context projection. The Harness store owns execution history. |

## Options

| Parameter | Type | Description |
| --- | --- | --- |
| `session` | `AgentSessionOptions` | Enable durable inputs, task/plan snapshots, and background execution. See below. |
| `workdir` | `string` | Directory tools resolve relative paths against. Defaults to `process.cwd()`. |
| `systemPrompt` | `string` | Overrides the default persona prompt; the runtime still appends the built-in communication skill. |
| `provider` / `model` | `string` | Provider and model id. A self-hosted endpoint must also provide `baseUrl`. |
| `baseUrl` / `apiKey` | `string` | Endpoint and key for a self-hosted gateway. Defaults come from the matching environment variables. |
| `modelAttributes` | `AgentModelAttributes` | The attribute record for the model a custom endpoint serves. See "Model attributes" below. |
| `apiKind` | `string` | Custom endpoint protocol. OpenAI native search requires `openai-responses`. |
| `webSearch` | `boolean` | Follows the model search capability by default. `false` disables it; `true` explicitly enables it. See "Web search" below. |
| `effort` | `AgentEffort` | Default reasoning effort. |
| `permissionPolicy` | `AgentPermissionPolicySetting` | Default permission policy. |
| `mode` | `AgentMode` | Default run mode. |
| `tools` | `string[]` | Narrow the available tools. Never widens what the policy disabled. |
| `allowedDirectories` | `string[]` | Roots the tools may touch. Defaults to `workdir` alone. |
| `extraTools` | `AgentTool[]` | Tools to add alongside the built-ins. See "Your own tools" below. |
| `models` / `resolvedModel` | pi types | For reusing your own provider collection or pinning a model. |

## Input (`AgentInput`)

| Field | Type | Description |
| --- | --- | --- |
| `prompt` | `string` | The turn's input. It may be an empty string when the turn carries images: an attachment-only turn is a real turn, and the runtime sends the images as the message content instead of failing with a missing prompt. |
| `requestId` | `string` | Logical submission identity. Reuse it for recovery or retransmission; use a new value for new input. Repeating a submission in the same store returns its original result without invoking models or tools again. |
| `images` | `AgentImageInput[]` | Images as `{ data, mimeType }`. |
| `imageFiles` | `FileReference[]` | Attachments as host file references, resolved through the workflow file store by the run's input node. An unreadable reference, or one that is not an image, ends the turn with an error naming the file rather than quietly dropping the attachment. Once resolved it becomes `images`, and nothing downstream sees that a reference was involved. |
| `modelAttributes` | `AgentModelAttributes` | Overrides the runtime option of the same name. See "Model attributes" below. |
| `webSearch` | `boolean` | Follows the model search capability by default. `false` disables it; `true` explicitly enables it. See "Web search" below. |
| `workdir` | `string` | Overrides the runtime's working directory. |
| `allowedDirectories` | `string[]` | Overrides the roots the tools may reach. Relative entries resolve against this turn's `workdir`; omitting it leaves `workdir` alone. |
| `systemPrompt` | `string` | This turn's system prompt. Applies per run and overrides the option of the same name. |
| `provider` / `model` / `baseUrl` | `string` | Override the runtime's model configuration. |
| `effort` | `AgentEffort` | See "Reasoning effort" below. |
| `agent` | `"build" \| "plan"` | `build` does the work; `plan` only researches and proposes. |
| `permissionPolicy` | `"read-only" \| "workspace" \| "auto" \| "inherit"` | See "Permission policy" below. |
| `contextWindow` | `number` | Denominator for context usage. Defaults to the model's declared window, then to the runtime fallback when no declaration exists. |
| `compact` | `boolean` | When `true`, the turn becomes a context compaction. |
| `hostInput` | `unknown` | This turn is driven by host input (the OpenAI/Responses gateway); a turn carrying it writes no workflow conversation and neither reads nor writes the transcript. |
| `planResume` / `askResume` | resume payloads | Programmatic hosts provide a plan decision or answers. Node hosts submit the original request's answer through `userInput`. |

## Events

`run()` yields:

| Event | Description |
| --- | --- |
| `text_delta` | Answer text delta. |
| `thinking_delta` | Reasoning delta. |
| `tool` | Tool call start / update / end. |
| `web_search` | A native search snapshot: `search: { id, status, query?, sources, error? }`. |
| `sources` | Sources returned by the current assistant response: `sources: { url, title?, citedText? }[]`. |
| `plan` | Plan text start / end. |
| `compaction` | Compaction start / end; the end event carries the summary. |
| `retry` | An attempt at carrying on a turn whose stream died mid-answer, hit the model's output limit, or lost a tool call, with `attempt` / `maxAttempts` / `reason` / `kind` (`dropped` / `length` / `lost-call`). |
| `context_usage` | Current context occupancy at run start, during streaming, after tool results, and after compaction. |
| `approval` | Plan approval outcome. |

## Host hooks (`AgentHost`)

Without a `host` nothing ever pauses. Supplying one takes over:

| Hook | Description |
| --- | --- |
| `approveToolCall(input)` | Resolving allows the call; throwing denies it and the message becomes the tool error. Throwing `user_input_required` pauses the run. |
| `approvePlan(input)` | Requests plan approval; throwing `user_input_required` pauses the run. |
| `reportUsage(usage)` | Reports billed tokens with a stable `recordId` for each returned model response. Hosts must upsert by that identity when replaying; Core token usage does so atomically. Returned promises are awaited. |
| `abortSignal` | Aborts the run. |

Durable stores usage returned before a response commits, including failed responses. Tokens consumed upstream before SIGKILL without a returned usage result cannot be inferred locally and require provider reconciliation.

### Live context

`run()` emits `context_usage` before requesting the model, allowing the ring to appear as soon as the first conversation run starts. Text, reasoning, tool arguments, and tool results update occupancy as they enter the context. Streaming updates are limited to one per 100 milliseconds; message endings and updates after compaction are immediate. Failed or cancelled runs retain the updates already emitted.

Following Pi's estimation approach, Core uses the latest valid model response usage, including cache tokens, plus estimates for subsequent messages. It does not sum billed usage across requests to measure context size. Without valid usage, it estimates system instructions, named prompt sections, tool declarations and message text in the actual context, counts CJK characters individually, and approximates image tokens. Retained responses from before compaction cannot calibrate the smaller context, including after transcript restoration.

Call `agent.getContextUsage()` while a response is streaming to query the current value. An external meter can supply a more accurate measurement with `agent.updateContextUsage({ used, total })`; `used` must be finite and nonnegative, and `total` must be finite and positive. Subsequent estimates grow from this measurement until valid model usage or actual compaction recalibrates it. `total` does not configure the model: the next model calibration uses this run's `contextWindow` or the model window. `reset()` clears the measurement and restored transcript.

Agent nodes automatically convert these events to [standard ring outputs](./create-agent-node.mdx), without extra host logic reading Agent fields. For a standalone transcript estimate, use `estimateAgentContextTokens(messages)` from `steamharness/agent`.
