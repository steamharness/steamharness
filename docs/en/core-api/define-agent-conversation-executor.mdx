# defineAgentConversationExecutor

`workflow.defineAgentConversationExecutor()` creates a complete Conversation Agent executor for embedding hosts and tests. Project entrypoints keep an inline `workflow.defineExecutor({...})` with `conversation`, `tokenUsage`, and `tools`. When its workflow comes from `workflow.createAgentConversationProject(...)`, Core inherits the built-in parameters and resolver automatically.

The helper saves an embedding host from implementing streaming, approvals, compaction, or output-item assembly. Projects can reuse the underlying workflow and input implementation while keeping their declarations visible to the host.


The permission menu contains `read-only`, `workspace`, and `auto`. Core projects follow Project Assistant: permissions bind to the user setting with `userSetting: { key: "agent.permissionPolicy", mode: "fixed" }`; hostless user settings use `auto`. An explicit `permissionPolicy` supplies a project default. Use `paramOptions.fields.permissionPolicy` to customize the binding, hide the field, or fix its actual value. See [User settings](/en/core-api/user-settings).

## Signature

```ts
workflow.defineAgentConversationExecutor(options?: AgentProjectOptions):
  ConversationExecutorDefinition<AgentInput, AgentOutputPayload>
```

Core validates the returned definition for embedding callers. Passing it to a project's `defineExecutor` still does not expose its fields to static structure analysis.

## Options

`session` enables [durable session control](./create-agent.mdx#durable-session-control). The convenience executor adds `conversation.durable: { enabled: true }` and default permissions for `update_plan` and, when enabled, `subagent`. Custom `toolDefinitions` must include these declarations explicitly. Static inline projects declare recovery/durable and pass session, for example `session: { subagents: { tools: ["read", "grep", "find", "ls"], maxAgents: 4 }, planFork: "asOf" }`. Child tools only narrow parent permissions; background results are delivered once. CLI Web / Studio keeps the execution owner alive and displays tasks, plans, records, and usage in four sidebar views.

Every [createAgentNode](./create-agent-node.mdx) option, plus:

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `projectName` | `string` | — | Display name of the project. |
| `executorName` | `string` | `agent` | Workflow name, also the node-name prefix (`<name>-input`, `<name>-output`, `<name>-agent`). |
| `collapseIntermediate` | `boolean` | `true` | Default folding of completed turns, keeping the final reply on success or the error on failure; emitted as `conversation.collapseIntermediate`; users can show or hide the process with each turn's button. |
| `outputItemId` | `string` | `agent-answer` | Item id of the assistant's answer, also written to `conversation.openai.outputItemId`. The answer item carries exactly this value, so an adapter looking it up by id always finds it. |
| `params` | `ConversationParamDeclaration[]` | see below | Replaces the entire parameter table; supports Auxiliary, Quick, Mode, and Slash. |
| `paramOptions` | `AgentProjectParamOptions` | — | Customize built-in defaults, bindings, visibility, fixed values, and groups by field name. |

## What it generates

| Part | Content |
| --- | --- |
| `projectType` | `"conversation"` |
| `conversation` | Standard message input always enabled; `inputQueue.enabled`, `recovery.enabled`, `openai.outputItemId` |
| `tokenUsage` | Enabled and displayed |
| `tools` | `read`, `write`, `edit`, `bash`, `grep`, `find`, `ls` |
| `params` | `provider`, `model`, `effort`, `plan`, `permissionPolicy` |
| `workflow` | Input node parses, agent node streams, output node writes the conversation |

Effort defaults to `high` and `/plan` is off. Models follow user settings by default; `modelSource: "project"` uses configured project models. Provider remains a hidden compatibility field.

The inherited resolver supplies model choices from the selected source, hides `provider`, and applies visibility and fixed values. It patches declared fields only. `model` stores a configuration entry ID that execution resolves to a connection. Explicit `executor.params` replaces the table; explicit `resolveParams` retains custom logic while Core still applies visibility and fixed values. See [Project configurations](/en/concepts/project-configuration).

## Input and output

Input uses [createAgent](./create-agent.mdx)'s `AgentInput`. `createAgentProjectInput(context, options?)` accepts an `ExecutorContext` carrying `args` and `paramValues`, parses messages, attachments, and effective parameters, and maps `plan` to `agent`. The existing `createAgentProjectInput(args, options?)` overload remains available for programmatic and advanced arguments.

Output is an `AgentOutputPayload`, and the turn's user message and assistant answer are appended to the conversation, so the host's history list, titles and export treat it as an ordinary conversation run.

Two exceptions: a turn that only called tools and produced no text appends no empty assistant message, and a turn carrying `hostInput` (the OpenAI/Responses gateway) appends nothing at all, because the gateway keeps that history itself — the same arrangement the built-in Conversation project makes.

**Pi Durable preserves multi-turn context and unfinished tasks.** Core selects SQLite by project, conversation and `sessionKey`, committing messages, tool intents and results, approval waits and usage identities. The same `runId` resumes the same request; completed requests reconstruct only their own output. Old KV transcripts are not read, and storage failures stop execution. Use different session keys for different agent nodes. Gateway runs carrying `hostInput` use memory by default; see [createAgentNode](./create-agent-node.mdx).

The helper enables `conversation.recovery: { enabled: true }`. Projects requiring static structure analysis must declare that field inline in `defineExecutor`. CLI Web / Studio use it to recover interrupted workers.

> **The answer item's id must equal `conversation.openai.outputItemId`.** The OpenAI/Responses adapters look that answer up **by id** in `report.outputs[].output.items` — the local gateway and CLI `__openai-responses-runner` all do — and a mismatch fails the run with "did not produce output item".

That item is produced by a **host-driven run** only, since the text read back by id has to be the whole turn. An ordinary conversation run writes its text as `partType: "text"` rows — one per run of text between two activity rows, where it was spoken — and joins them back into the conversation message.

## Example

For an embedding host or test:

```ts
const agentExecutor = workflow.defineAgentConversationExecutor({
  projectName: "Pi",
  executorName: "pi",
  outputItemId: "pi-answer",
  provider: "anthropic",
  effort: "high",
});
```


## Project parameter inheritance and customization

Context input consumes only enabled fields from the selected parameter table; fixed user-setting bindings reject host parameter overrides. Legacy `-m` and `--agent plan|build` flags remain available through inherited executors, with explicit `--plan` taking precedence over the legacy mode flag. Message and attachment values are excluded from parameter parsing. An `undefined` field override is equivalent to omission; use `userSetting: null` to clear a binding. Static inheritance supports shorthand `workflow` / `coreAgent` properties and SDK namespace imports.

Executors using a Core workflow can omit `params` and `resolveParams`. For a business workflow wrapping Core, set `coreAgent: agentProject` on the executor and retain the business workflow and `createInput`. Parameter options must be statically readable; inspection follows only the selected reference and never executes project code.

`fields` supports `defaultValue`, `userSetting` (`null` clears a binding), `visible`, `fixedValue`, `label`, `description`, and `options`. Set a field to `false` to remove it. `groups` rearranges Quick/Auxiliary groups by field name; unassigned fields keep their original group. `fixedValue` replaces bindings and defaults and is enforced during input construction and at the Core execution boundary. Visibility controls presentation; add `fixedValue` to prevent overrides. An explicit default clears the user setting binding.

```ts
const agentProject = workflow.createAgentConversationProject({
  modelSource: "project",
  paramOptions: {
    fields: {
      effort: { defaultValue: "medium" },
      plan: false,
      permissionPolicy: { visible: false, fixedValue: "auto" },
    },
    groups: [{ kind: "quick", id: "ai", label: "AI",
      fields: ["provider", "model", "effort"], summary: ["model", "effort"] }],
  },
});

export const executor = workflow.defineExecutor({
  projectType: "conversation",
  workflow: agentProject,
  createInput(context) { return workflow.createAgentProjectInput(context); },
});
```
