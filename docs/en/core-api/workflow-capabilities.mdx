# Workflow capabilities

Project capability tools expose host configuration, Kanban page methods, and Bot resource cards. Each capability shares a JSON Schema and implementation across native Agent tools and MCP. Declare the tool IDs you need in the executor's `tools` list.

| Capability | Tool ID |
| --- | --- |
| Kanban page methods | `steamharness-kanban_kanban_methods` |
| Bot resource cards | `workflow-ui_present_card` |

## Create and call tools

```ts
const tools = await steamharness.createProjectCapabilityTools({
  context,
  approve: (toolId, args) => approval.approve({ name: toolId, arguments: args }, context),
});

const ids = steamharness.listProjectCapabilityToolIds();
const result = await steamharness.runProjectCapabilityAction(ids[0], context, args);
```

`createProjectCapabilityServer(toolId, { context, approve })` wraps one capability as an MCP server. Unknown tool IDs throw. Use `isProjectCapabilityAvailable(toolId)` to check whether the current host offers a capability before displaying it.

The executor's `tools` declaration controls approval. After a pause, resume through `runProjectCapabilityAction` using the approved tool ID; the Agent turn that created the original closure has ended.

## Resource cards

`workflow-ui_present_card` identifies cards by a stable `cardId`. Use `action: "upsert"` to create or update one, and `action: "remove"` to remove it. Supported kinds are `project`, `kanban`, `browser`, and `file`. File paths are project-relative; browser URLs use HTTP(S).

```json
{
  "action": "upsert",
  "cardId": "roadmap-board",
  "kind": "kanban",
  "target": { "source": "current", "entryId": "map" },
  "pinned": true,
  "preview": true
}
```

`preview` applies to Kanban, project, and browser cards. Select an existing configuration with `target.configurationId`, or supply temporary values with `kanban: { mode: "preview", values }`. Cards do not save configuration values; use Studio Control `manage_configurations` for that.
