# createLLMProviderFromConfig

Use `steamharness.createLLMProviderFromConfig()` to create a provider from the current run configuration. The SDK export with the same name also accepts an explicit configuration object. Neither form falls back to environment variables.

## Example

```ts
const provider = steamharness.createLLMProviderRef("default", () =>
  steamharness.createLLMProviderFromConfig());
```

## Signatures

```ts
steamharness.createLLMProviderFromConfig(): LLMProvider
createLLMProviderFromConfig(config?: ConfigurationValues): LLMProvider
```

## Configuration fields

Declare string fields in `configuration.json`, then fill them through project configuration. Mark API keys as sensitive.

| Key | Aliases | Value |
| --- | --- | --- |
| `LLM_TYPE` | `TYPE` | `openai-completion`, `openai-responses`, or `anthropic` |
| `LLM_API_KEY` | `API_KEY`, `APIKEY` | Required |
| `LLM_BASE_URL` | `BASE_URL` | Optional endpoint |
| `LLM_MODEL` | `MODEL` | Optional model ID |

Without an explicit model, OpenAI defaults to `gpt-4.1-mini` and Anthropic to `claude-3-haiku-20240307`. Missing required keys or invalid provider types throw `input_validation`.

See [project configuration](/en/concepts/project-configuration) for saving and snapshots.
