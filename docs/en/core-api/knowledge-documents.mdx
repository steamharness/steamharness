# Database knowledge API

Use `context.databases.get(alias).knowledge` to access an approved space's Markdown knowledge documents. Knowledge and KV share a space identity with separate permissions. Ordinary KV cannot read or modify document, index or attachment keys.

```ts
const knowledge = context.databases.get("data").knowledge;
await knowledge.createDocument({ id: "guide", title: "Guide", markdown: "# Guide" });
await knowledge.editDocument({ id: "guide", markdown: "# Updated guide" });
const page = await knowledge.listDocuments({ pageSize: 20 });
const document = await knowledge.getDocument("guide");
const matches = await knowledge.searchDocuments({ query: "guide", pageSize: 20 });
const lines = await knowledge.readDocumentLines({ documentId: "guide", startLine: 1, endLine: 10 });
await knowledge.deleteDocument("guide");
```

Documents contain `id`, `title`, `markdown`, `createdAt` and `updatedAt`. Lists return summaries and pagination cursors; read bodies on demand. Search and line reads preserve line numbers. Document and search index mutations commit in the same space transaction; host locks and CAS keep concurrent updates consistent.

## Attachments

```ts
const files = knowledge.files;
const image = await files.createFile({ name: "image.png", mimeType: "image/png", buffer });
const resolved = await files.readFile(image.id);
await files.deleteFile(image.id);
```

References include `storage: "database"` and `spaceId`. Create, read, delete and subsequent reads through retained handles check knowledge permissions. Each attachment is limited to 50 MiB. Other approved projects can read the same attachment. Deleting a project preserves space content.

## Failures and recovery

Unbound, pending, incorrectly hosted, revoked or insufficient grants fail without falling back to KV or another host. The UI exposes request, rebind and recovery actions. See [Independent database spaces](/en/concepts/data-storage).
