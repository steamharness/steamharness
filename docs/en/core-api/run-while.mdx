# runWhile

Use `steamharness.runWhile()` to check `condition` before each iteration. When true, it executes `run` and passes the returned state to the next iteration. Reports contain `branch-node` events, and Diagram shows the loop body.

## Example

```ts
const finalState = await steamharness.runWhile(seed, context, {
  name: "Boost until target",
  maxIterations: 8,
  condition: (state) => state.total < state.target,
  async run(state, loopContext, iteration) {
    return steamharness.runIf(state, loopContext, {
      name: "Choose boost strategy",
      branches: [
        {
          label: "burst",
          condition: (current) => current.target - current.total >= 7,
          async run(current, branchContext) {
            return steamharness.runFor(current, branchContext, {
              name: "Burst passes",
              maxIterations: 3,
              items: () => [4, 3],
              async run(passState, value, index, passContext) {
                return steamharness.runNode(boostNode, { ...passState, value, index, iteration }, passContext);
              },
            });
          },
        },
      ],
      else: {
        label: "finish",
        async run(current, branchContext) {
          return steamharness.runNode(boostNode, { ...current, iteration }, branchContext);
        },
      },
    });
  },
});
```

## Signature

```ts
steamharness.runWhile<State>(
  input: State,
  context: RunContext,
  options: {
    name?: string;
    condition(input: State, context: RunContext, iteration: number): boolean | Promise<boolean>;
    run(input: State, context: RunContext, iteration: number): State | Promise<State>;
    maxIterations?: number;
    metadata?: Partial<NodeMetadata>;
  },
): Promise<State>
```

## Parameter

|Parameter|Type|Description|
| --- | --- | --- |
| `input` | `State` |Initial cycle state.|
| `context` | `RunContext` |runtime context for hooks, provider, databases, files, abortSignal.|
| `options.name` | `string` |Diagram and the loop node titles displayed in the Trace. Default `Run while`.|
| `options.condition` | `function` |Execute before start of each round; continue loop when return `true`. The third argument is the iteration starting at `0`.|
| `options.run` | `function` |The body of the loop executed after the condition is hit, returning to the next round.|
| `options.maxIterations` | `number` |The maximum number of iterations. Default `100` to prevent accidental infinite loops.|
| `options.metadata` | `Partial<NodeMetadata>` |Overwrites the metadata of loop nodes; by default, the type is `run-while`.|

## Operation Report

`runWhile` Use the standard node name `run-while`, and run with kind `branch-node`. The `executionInfo` that completes the event will include:

```json
{
  "loopType": "while",
  "iterations": 2,
  "iterationCount": 2,
  "maxIterations": 100,
  "completed": true
}
```

`completed` is `false` on failure and retains the number of iterations that have completed.

## Diagram

Static structural analysis identifies object literals in the forms of `condition`, `maxIterations`, and `run`. In `run`, `steamharness.runNode`, `steamharness.runStreamNode`, `steamharness.runIf`, `steamharness.runFor`, and `steamharness.runWhile` will become loop body nodes and will be enclosed by the loop container in shared runtime UI Diagram. To ensure Diagram remains readable, the loop configuration should preferably be kept as an object literal; dynamically constructing the options is still feasible, but the static diagram can only display limited information.

## Error

|Situation|Error Type|Description|
| --- | --- | --- |
|More than `maxIterations`| `node_execution` |Throw out `Run-while node "<name>" exceeded maxIterations (<value>).`.|
|`condition` or `run` throws an error| `node_execution` |The original error is wrapped as `HarnessError` and written to the loop node report.|
|Break before execution or in a loop|`execution_aborted` or `node_execution`|From `context.abortSignal`.|
