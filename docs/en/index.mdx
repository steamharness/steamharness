# Start with SteamHarness

Build Agent projects with SteamHarness, run them in Studio or the CLI, and use Server to manage source code, versions, and access.

Start with the [quickstart](/en/guides/quickstart) to run a Hello workflow. If you already have a project, [open it in Studio](/en/guides/studio/create-import).

## Three project types

| Your task | Entry type | Start here |
| --- | --- | --- |
| Connect inputs, models, tools, and conditions into a task | Workflow | [Build a workflow](/en/guides/development/workflow) |
| Create an assistant that accepts successive messages | Conversation | [Build a conversation](/en/guides/development/conversation) |
| Display a board, map, or interactive data page | Kanban | [Build a board](/en/guides/development/kanban) |

A project can contain several entry types under one project ID and version. Choose an entry to run; each entry has its own configuration, drafts, and conversation state.

### Workflow

Declare inputs, nodes, and execution order in TypeScript. Use workflows for data processing, content generation, and multi-step automation. The [workflow model](/en/concepts/workflow-model) covers branches and loops.

### Conversation

Organize work around messages and rounds. A conversation executor accepts input using the same runtime as workflows. See [databases and conversations](/en/concepts/database-and-conversation) for history management.

### Kanban

Write HTML, CSS, and JavaScript with `index.html` as the entry. A restricted Bridge can access relational or knowledge resources that the entry has bound and the account is allowed to use.

## Where projects run

| Surface | Purpose |
| --- | --- |
| Studio | Edit source, run local projects, inspect results and traces |
| Local CLI | Run tasks, inspect structure, export JSON, or expose MCP tools |
| Server | Store source, versions, members, databases, knowledge bases, and files |
| Server Web management console | Manage Server projects and resources in a browser |
| Store | Browse, download, and publish project versions |

Project code runs on the machine hosting Studio or the local CLI. Server stores source archives without installing project dependencies or running project code. Server-side Kanban previews serve static pages under access controls.

## Project data and configuration

Business databases, knowledge bases, and runtime history have separate lifecycles. Declare relational aliases in `databases`; Server maintains their bindings by account, project, and entry. Declare knowledge resources in `knowledgeBases`.

Configuration and conversations are scoped by `projectId + entryId`. Configuration changes apply to subsequent runs. See [project configuration](/en/concepts/project-configuration) and [data storage](/en/concepts/data-storage).

## Accounts, permissions, and collaboration

| Role | Main capabilities |
| --- | --- |
| `guest` | View and download published projects, then run them locally |
| `developer` | Edit drafts, upload, publish, and modify authorized data |
| `maintainer` | Manage project information, official configuration, guests, and developers |
| `owner` | Manage every role, project ownership, and deletion |

Groups support nested subgroups. Effective access is the highest role granted directly or inherited from a group. Project access and data-resource grants are checked separately. See [project management](/en/guides/server/project-management).

## AI capabilities

The open-source edition supports custom models in Studio and LLM Providers configured by a project. See [model settings](/en/guides/studio/models) and [LLM Provider](/en/concepts/llm-provider).

The enhanced edition adds account-provided models, provider preferences, subscriptions, and usage. See [system AI](https://docs.steamharness.yuhe.space/en/enhanced/ai/overview).

## Development workflow

1. [Create a project](/en/guides/studio/create-import), select a template, and wait for dependency installation.
2. Write the entry and check `entries` and `defaultEntry` in the root `steamharness.json`.
3. [Run locally](/en/guides/studio/run-debug) and inspect the result and trace.
4. [Upload and publish](/en/guides/studio/versions), then assign member access as needed.
5. For public distribution, [publish to Store](https://docs.steamharness.yuhe.space/en/enhanced/store/publishing).

## Project structure

The root `steamharness.json` declares project identity, version, and entries. Workflow and Conversation entries point to executor source; Kanban entries point to built HTML. `package.json` and the lockfile manage ordinary dependencies.

See the [workflow model](/en/concepts/workflow-model) for declarations. Read the [Core 0.2 migration guide](/en/guides/migrate-core-0-2) before updating an older project.

## Built-in projects

The Developer Assistant handles coding tasks, Studio Control provides permission-checked editor operations, and Studio Analysis summarizes local runs. See [release notes](/en/guides/releases/overview) for built-in Codex, Conversation, OpenCode, Pi, and assistant versions.

## Versions, testing, and deployment

Pin compatible Core and CLI dependencies in your project. Check [version compatibility](/en/guides/releases/compatibility) before upgrades and run [project tests and structure checks](/en/guides/testing) during development. See [Deploy Server](/en/guides/server/deployment) for hosting.
