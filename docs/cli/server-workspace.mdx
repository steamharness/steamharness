# Workspace 静态项目管理

`steamharness workspace` 管理 Server 上的聚合项目源码与不可变版本。Server 不安装项目依赖、不构建、不执行项目。

```sh
pnpm exec steamharness workspace login --server <server-url>
pnpm exec steamharness workspace status
pnpm exec steamharness workspace pack <project-id> --path . --output project.tgz
pnpm exec steamharness workspace upload <project-id> --path .
pnpm exec steamharness workspace publish <project-id> --release-log "Update entries"
pnpm exec steamharness workspace versions <project-id>
pnpm exec steamharness workspace download <project-id> --target latest --path ./downloaded
```

整个聚合是一个上传、版本与下载单元。打包包含全部注册入口代码、各包依赖声明和 Kanban 构建产物；排除 Git、node_modules、运行数据和凭据。保留数据库 `alias → databaseId` 映射，授权与凭据由宿主维护。

## 注册与归属

使用客户端的创建项目流程申请 Server 身份。`upload --create` 显式创建并替换本地聚合身份；`--group-id` 选择权限组归属。项目成员、组继承与源码访问申请仍使用固定角色，与数据库申请分别管理。

## 传输与配置

`upload --file` 接受已打包归档，`--no-wait` 返回准备任务，`preparation` 查询静态准备结果。`file-upload/file-download/file-delete` 管理业务文件。`--server`、`--token` 可覆盖保存的登录信息；不要把凭据加入 manifest。

CLI Web 的「项目信息 → 全局记忆」按 Core 实际能力显示，可切换个人全局与当前项目／目录、搜索和分页，并查看、编辑或遗忘。弹窗保持受视口约束的固定尺寸；服务暂时故障时保留入口并显示故障状态。未接入或关闭时隐藏。账号记忆需要重新登录取得独立凭据，不使用项目 API Key，也不写入业务数据库。

配置模板、方案、快照与附件按入口保存。数据库通过 CLI Web、Studio 或 Server Web 的独立空间管理申请与绑定，下载后需重新获批。
