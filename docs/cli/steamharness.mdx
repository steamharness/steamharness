# CLI 与聚合入口

在聚合项目根目录运行已安装的 CLI，使用 Node.js 24。先安装项目依赖，再检查根清单和全部注册入口；子目录不拥有独立项目身份。

本地运行允许省略 `steamharness.json.id`，无需先在 Server 登记项目。发行构建要求清单中有有效的项目 UUID；本地运行不会替你把 ID 写入源码。

```sh
pnpm exec steamharness check .
pnpm exec steamharness check . --entry workflow
pnpm exec steamharness structure . --entry workflow
pnpm exec steamharness run . --entry workflow --entrypoint summarize -- --text example
pnpm exec steamharness json . --entry workflow --entrypoint summarize -- --text example
pnpm exec steamharness web . --entry agent
pnpm exec steamharness mcp . --entry workflow
```

## 入口选择

`--entry` 选择窗口入口，省略时 `run`、`json`、`structure`、`mcp` 和 `web` 使用 `defaultEntry`。`check` 默认检查所有注册入口，加 `--entry` 只检查指定入口。`--entrypoint` 选择 Workflow 内部操作。两者不能混用。

入口 ID 和路径须遵守[产物目录的保留名称规则](/concepts/data-storage#产物与运行数据目录)，不能与缓存、报告或 Windows 设备名冲突。

`--` 后的参数原样传给 Workflow。`--locale zh-CN|en` 控制宿主文案语言，不改变业务参数。

## 发行构建与运行

在聚合根构建发行版，或在运行时自动准备最新发行结果：

```sh
pnpm exec steamharness release . --json
pnpm exec steamharness run . --release --entry workflow --entrypoint summarize -- --text example
pnpm exec steamharness web . --release --entry agent
```

发行项目保存在 `dist/steamharness/release/project/`，压缩包保存在 `dist/steamharness/release/`。`run`、`json` 和 `web` 的 `--release` 只运行发行配置中包含的入口；构建失败会报告错误，保留上一次完整产物。

Bot 记忆开关的默认值按最终发行入口和配置定义生成，支持 `release.entryOverrides` 的 `entry` 与 `configuration`。补入记忆开关时保留 v2 配置档位。

发行目录中的项目声明、配置定义和额外 JSON 资源统一压缩为单行，保留字段名、字符串内容和数值原文。Server 发布配置后也会重新压缩，并更新文件校验清单。

`structure.json` 使用 v2 格式，明文保留项目 ID、入口 ID、入口名称和类型，内部结构以 `brotli-base64` 压缩编码。SDK、CLI 和 Server 统一解码，供结构检查、运行和静态校验使用。

此格式要求配套宿主，旧发行产物需从源码重新构建；损坏载荷和解压后超过 64 MiB 的结构会被拒绝。压缩编码不提供加密，宿主仍可还原结构。

在 Studio 中，点击运行按钮右侧的**运行（发行模式）**。Studio 保存项目文件、构建发行版，再以发行运行目录为根打开新窗口并启动当前入口。该入口必须包含在发行配置中。

发行窗口直接采用 Steam 布局，启动期间显示项目加载状态，不经过 IDE 模式，也不会自动打开小助手。主项目页始终留在主区域；即使恢复了右侧的同项目工具标签，启动和重试也不会改用该标签。

发行窗口左上角显示聚合项目的图标和名称，固定使用 Steam 模式，右侧工具区不提供编辑器和小助手。进入 Steam 模式或重新打开窗口时，工具区默认收起；点击右上角的**显示工具区**可展开，已有工具标签和宽度会保留。

源码窗口只显示源码中的版本；打开发行项目时显示已安装版本，并检查是否可以升级。

## CLI Web

完整操作见[使用 CLI Web](/cli/web)。

本地宿主可用 `--folder-context` 运行支持[文件夹上下文](/core-api/overview)的 Bot。它需要 `--host-stdio`、指定默认 Bot 的 `--entry`，以及由宿主通过标准输入提供的本机目录；不能与 `--release` 或 `--inspect` 同用。直接在终端启动 CLI Web 不需要这个选项。

在 Bot 对话里问「当前运行环境是什么？」可以查本轮的 Core、CLI 和项目版本。[`runtime_info` 工具](/core-api/agent/context#自带工具)会区分 CLI、CLI Web 和 Studio。Agent 还会返回工作目录；[LLM Bot](/core-api/define-bot) 不返回本机路径。

## 检查与输出

`check` 和 `structure` 只静态读取注册入口，不执行用户模块。非法路径、重复入口 ID、无效默认入口、类型不匹配或旧声明会失败。`json` 返回运行报告，包含项目与入口身份；运行失败使用非零退出码。取消信号传递给当前执行及其跨入口调用。

CLI Web 和 Studio 的运行结果支持内嵌图片，可点击放大并在历史记录中回看。若旧页面在运行成功后仍显示进度，更新 CLI 并刷新项目页面后，再打开该记录即可查看已保存的图片，无需重新执行工作流。

远程静态项目管理使用 [workspace 命令](/cli/server-workspace)，Server 不运行项目代码。

小助手回复中的看板卡片按保存的项目、入口和配置预览，资源地址保留卡片宿主的入口前缀。Studio 的 `get_kanban_diagnostics` 同时支持已打开的项目看板与小助手卡片，返回页面实例、配置身份和最近 50 条请求记录；`previews` 可区分卡片来源。使用当前 `instanceId`、`configurationId` 调用明确声明 `readOnly: true` 的页面方法，可核验图片加载等实际状态。关闭或刷新卡片后，旧实例失效；没有活实例时不能视为页面验收通过。文件桥接最多等待 120 秒，传输层不会提前截断；超过该时限仍须排查实际文件读取链路。

看板或内嵌对话报错时，先记下提示中的操作和错误码。如果还有诊断编号，可用 Studio 的 `get_kanban_diagnostics` 在当前看板或对应卡片的最近请求中按编号查找，也可用同一编号查 CLI 主机日志中的异常原因。失败记录会给出类别，例如超时、连接或权限错误；文件读取还会列出尝试过的来源。

刷新看板会清空记录。Workflow 明确返回的业务拒绝会显示面向用户的原因，其他宿主异常不会把原始路径或凭据带到页面。
