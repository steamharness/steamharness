# CLI 与聚合入口

在项目根目录使用已安装的本地 CLI。运行环境为 Node.js 24，项目按包管理器声明安装依赖。根 manifest 及所有注册入口必须有效；子目录不再拥有独立 SteamHarness 项目身份。

```sh
pnpm exec steamharness check .
pnpm exec steamharness check . --entry database
pnpm exec steamharness structure . --entry database
pnpm exec steamharness run . --entry database --entrypoint search -- --query example
pnpm exec steamharness json . --entry database --entrypoint search -- --query example
pnpm exec steamharness web . --entry agent
pnpm exec steamharness mcp . --entry database
```

## 入口选择

`--entry` 选择窗口入口，省略时 `run`、`json`、`structure`、`mcp` 和 `web` 使用 `defaultEntry`。`check` 默认检查所有注册入口，加 `--entry` 只检查指定入口。`--entrypoint` 选择 Workflow 内部操作。两者不能混用。

`--` 后的参数原样传给 Workflow。`--locale zh-CN|en` 控制宿主文案语言，不改变业务参数。

## CLI Web

一个根目录启动一个聚合宿主。顶部项目名称旁的窗口选择器显示入口名称、类型与状态，每个入口使用 `/entries/<entryId>/` URL。切换窗口保留输入草稿、历史和后台运行；每个入口拥有独立控制器。

点击顶部“数据库”打开数据库管理；出现“请处理数据库绑定”提示时，也可直接点击提示中的“打开数据库管理”。Studio 小助手、Conversation、Workflow 和 Kanban 使用同一入口，支持申请、审批、共享、绑定、收窄、撤销、轮换与数据管理。未获批不会自动创建空间。详见 [数据库空间](/concepts/data-storage)。

## 检查与输出

`check` 和 `structure` 只静态读取注册入口，不执行用户模块。非法路径、重复 ID、无效默认入口、类型不匹配或旧声明会失败。`json` 返回运行报告，包含项目与入口身份；运行失败使用非零退出码。取消信号传递给当前执行及其跨入口调用。

远程静态项目管理使用 [workspace 命令](/cli/server-workspace)，Server 不运行项目代码。

## 用户模型与权限

CLI Web 可由 Studio 宿主注入用户权限快照及后续更新，通过能力握手兼容旧 CLI。项目显式选择 `permissionPolicy: "inherit"` 才继承；未配置仍默认 `workspace`。独立 CLI 本期不保存用户权限设置，没有宿主注入时 `inherit` 使用 `auto`。持久会话中的当前任务保留启动快照，后续输入在空闲安全边界后采用新值。见[用户设置与权限继承](/core-api/user-settings)。

绑定用户模型的 Quick 菜单先展示模型列表，加载和任务运行期间也保留“添加模型”入口，当前不可修改的选择保持禁用。没有可用模型时，入口显示“配置模型”及设置引导，点击直接打开模型设置；添加模型后恢复选择列表。模型参数中的 `inherit` 是普通模型 ID，不代表权限继承；重置模型参数才会恢复用户默认。

默认 Agent 与小助手将模型、effort 拆为独立 Quick 入口。模型菜单按内置在上、自定义在下分组，底部保留添加模型入口；项目仍可自定义参数分组。

CLI Web 接受宿主注入的用户模型快照和更新。模型参数可绑定 `userSetting: { key: "agent.model", mode: "default" }`，点击先打开可用模型列表，再通过“添加模型”进入 Studio 的模型设置。显式选择保存为会话覆盖，重置继续跟随用户默认。入口也可使用项目模型配置 API；独立 CLI 不保存 Studio 的用户模型。三方密钥不进入页面状态、普通会话历史和导出，持久会话在任务空闲后采用新设置。详见[用户设置](/core-api/user-settings#用户模型与免配置-agent)。
