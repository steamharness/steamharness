# CLI 与聚合入口

在项目根目录使用已安装的本地 CLI。运行环境为 Node.js 24，项目按包管理器声明安装依赖。根 manifest 及所有注册入口必须有效；子目录不再拥有独立 SteamHarness 项目身份。

```sh
pnpm exec steamharness check .
pnpm exec steamharness check . --entry database
pnpm exec steamharness structure . --entry database
pnpm exec steamharness run . --entry database --entrypoint search -- --query example
pnpm exec steamharness json . --entry database --entrypoint search -- --query example
pnpm exec steamharness web . --entry agent
pnpm exec steamharness mcp . --entry database
```

## 入口选择

`--entry` 选择窗口入口，省略时 `run`、`json`、`structure`、`mcp` 和 `web` 使用 `defaultEntry`。`check` 默认检查所有注册入口，加 `--entry` 只检查指定入口。`--entrypoint` 选择 Workflow 内部操作。两者不能混用。

入口 ID 和路径须遵守[产物目录的保留名称规则](/concepts/data-storage#产物与运行数据目录)，不能与缓存、报告、数据库生成目录或 Windows 设备名冲突。

`--` 后的参数原样传给 Workflow。`--locale zh-CN|en` 控制宿主文案语言，不改变业务参数。

## CLI Web

Bot 主对话框中输入 `@`，选择 **技能**、**文件** 或 **项目入口**，也可继续输入名称直接搜索。技能读取当前入口实际配置的目录；文件从项目根目录（小助手使用绑定的工作目录）搜索，Git 项目遵循忽略规则，并排除依赖、构建产物、运行数据与 `.env` 配置。使用 ↑/↓ 选择，Enter 或 Tab 插入，Esc 关闭；Shift+Enter 继续换行。插入的 `@skill:…`、`@file:…`、`@entry:…` 在输入框中高亮；文件仅显示文件名，悬停时展示完整路径，含空格的文件名自动加引号。保存和发送仍保留完整路径，引用作为消息文本保存，可随草稿恢复、编辑队列消息或重新发送。选择入口仅引用入口标识，不切换窗口或运行入口。原有 `/` 命令继续可用。

Core Agent 默认或 `modelSource: "user-settings"` 在 Studio 使用设置的内置／自定义模型，不展示项目“AI 模型”。独立 `steamharness web` 没有模型设置能力时自动改用项目模型，点击“配置模型”可添加系统 AI／第三方 AI。Studio 设置列表为空时仍进入设置管理；显式 `modelSource: "project"` 始终使用项目模型。

Core Agent 的执行 worker 在活动宿主中意外退出时，最多自动恢复 3 次，沿用原任务、子会话和检查点。 本地执行锁随旧进程退出自动释放；显式使用 Server 关系存储时，最多等待 35 秒让旧租约到期。等待响应停止操作，不接管仍有效的其他执行身份，也不重放已提交写入。宿主自身强退重开时，普通会话按原运行身份恢复，含未完成业务任务的会话等待明确输入。宿主退出会关闭运行 worker；不响应清理的 worker 最迟在 5 秒后退出并释放会话锁。失败、停止或超时后，待发队列保留并暂停；只有一轮成功完成后才自动发送下一条。可显式继续队列或发送新输入，新输入成功后再顺序发送保留的队列。

重新打开会话或同步其它窗口的历史时，已持久化的 Agent 回合终态会校正旧的“回复中”和恢复标记。已经完成、失败或停止的回答不会继续计时，也不会因旧标记再次执行；尚未完成的回合继续按恢复规则处理。每轮回答结束后保留最终耗时，刷新或重开历史仍可查看；后续追问从该轮开始执行时独立计时。子 Agent 首次打开及恢复历史时使用持久记录中的实际执行起止时间，包含打开前已经执行的时间；排队时间不计入该轮。旧历史缺少可靠计时记录时不按当前时间补算。

在 Studio 中，Agent 回复与计划中的本地文件链接、行内代码路径和正文绝对路径可点击，在编辑区打开对应文件。支持相对路径、`file://` 链接及 `src/main.ts:12:3`、`src/main.ts#L12C3` 形式的行列定位；相对路径从聚合项目根目录或小助手绑定的工作目录解析。普通网页链接继续在浏览器中打开。独立浏览器中的 CLI Web 无法打开本机编辑器，点击本地文件路径时会提示使用 Studio。

在 Studio 中导出对话、单条消息或工作流记录时，会打开原生保存窗口，默认位置为用户主目录下的 Downloads（下载）目录，也可手动选择其他位置。确认位置并成功写入文件后，右下角通知显示保存路径；取消保存不提示成功，保存失败显示错误。独立浏览器中的 CLI Web 使用浏览器下载。

一个根目录启动一个聚合宿主，默认只展示 `defaultEntry`。点击顶部操作区的 **项目窗口** 图标，面板以紧凑卡片显示各入口的图标、名称、类型、默认／当前标记和运行状态。点击入口右侧的打开图标，在独立 CLI Web 中打开新浏览器页面，在 Studio 中打开新的原生标签。每次点击都会新开一个标签，包括当前入口；各标签独立保留页面状态和草稿，共享聚合运行宿主。关闭一个标签不影响其他标签；关闭最后一个 Studio 标签后释放宿主。

每个入口使用 `/entries/<entryId>/` URL 和独立控制器。入口的可选 `projectCard` 配置 `icon`、`iconColor` 与 `iconBackgroundColor`，颜色使用 `#RRGGBB`；未配置的字段采用入口类型的默认值。根 `steamharness.json.projectCard` 用于聚合项目卡片，入口图标相互独立。版本只在根 `steamharness.json.version` 声明，入口不接受独立版本。

点击右上角的 **项目信息** 图标，统一查看概览、项目配置、工具、技能与数据库。面板使用固定宽高，宽屏采用左侧导航，窄屏改用可横向滚动的顶部标签，内容区独立滚动；切换分栏不会改变面板大小，也不会丢弃配置草稿或工具搜索。工具清单与权限随项目状态更新。工具与技能供支持它们的入口使用。技能页读取当前入口的真实技能目录，展示技能数量并区分项目技能与 Core 内置技能，支持搜索。点击技能可在固定面板内预览完整 `SKILL.md` 或查看 Markdown 源码；预览的返回栏固定，正文在独立区域内滚动，返回列表保留搜索与滚动位置。技能仅作只读展示，没有启用或自动批准开关，预览不执行技能指令。原有的配置模型快捷入口会直接打开面板中的项目配置。

CLI Web 的“项目信息 → 数据库”展示关系库和独立知识库引用、状态及共享入口。关联操作使用各自绑定规则，浏览操作打开 Server Web 对应资源，URL 不含账号 token；资源创建、授权和数据编辑在 Server Web 或 CLI 管理命令中完成。

入口在 `steamharness.json` 中分别声明 `databases` 与 `knowledgeBases` 别名。关系库资源由 Server 按账号、项目、入口和别名绑定；根 `config.json.knowledgeBases` 记录知识库别名到 UUID 的映射，支持 `STEAMHARNESS_PROJECT_CONFIG` 覆盖。一个入口可关联多个资源，绑定不授予权限。详见 [项目数据存储](/concepts/data-storage)。

## 检查与输出

`check` 和 `structure` 只静态读取注册入口，不执行用户模块。非法路径、重复 ID、无效默认入口、类型不匹配或旧声明会失败。`json` 返回运行报告，包含项目与入口身份；运行失败使用非零退出码。取消信号传递给当前执行及其跨入口调用。

远程静态项目管理使用 [workspace 命令](/cli/server-workspace)，Server 不运行项目代码。

小助手回复中的看板卡片按保存的项目、入口和配置预览，资源地址保留卡片宿主的入口前缀。Studio 的 `get_kanban_diagnostics` 同时支持已打开的项目看板与小助手卡片，返回页面实例、配置身份和最近 50 条读取记录；`previews` 可区分卡片来源。使用当前 `instanceId`、`configurationId` 调用明确声明 `readOnly: true` 的页面方法，可核验图片加载等实际状态。关闭或刷新卡片后，旧实例失效；没有活实例时不能视为页面验收通过。文件桥接最多等待 120 秒，传输层不会提前截断；超过该时限仍须排查实际文件读取链路。

## 用户模型与权限

CLI Web 可由 Studio 宿主注入用户权限快照及后续更新，通过能力握手兼容旧 CLI。项目显式选择 `permissionPolicy: "inherit"` 才继承；未配置仍默认 `workspace`。独立 CLI 本期不保存用户权限设置，没有宿主注入时 `inherit` 使用 `auto`。持久会话中的当前任务保留启动快照，后续输入在空闲安全边界后采用新值。见[用户设置与权限继承](/core-api/user-settings)。

绑定用户模型的 Quick 菜单先展示模型列表，加载和任务运行期间也保留“添加模型”入口，当前不可修改的选择保持禁用。没有可用模型时，入口显示“配置模型”及设置引导，点击直接打开模型设置；添加模型后恢复选择列表。模型参数中的 `inherit` 是普通模型 ID，不代表权限继承；重置模型参数才会恢复用户默认。

默认 Agent 与小助手将模型、effort 拆为独立 Quick 入口。模型菜单按内置在上、自定义在下分组，底部保留添加模型入口；项目仍可自定义参数分组。

CLI Web 接受宿主注入的用户模型快照和更新。模型参数可绑定 `userSetting: { key: "agent.model", mode: "default" }`，点击先打开可用模型列表，再通过“添加模型”进入 Studio 的模型设置。显式选择保存为会话覆盖，重置继续跟随用户默认。入口也可使用项目模型配置 API；独立 CLI 不保存 Studio 的用户模型。三方密钥不进入页面状态、普通会话历史和导出，持久会话在任务空闲后采用新设置。详见[用户设置](/core-api/user-settings#用户模型与免配置-agent)。

## 分叉对话

回答下方的分叉按钮经确认后弹窗展示创建和打开进度，成功自动打开新分支，失败在弹窗内展示原因；已创建但打开失败时会明确提示，可从会话历史打开。新分支复制截至该回答（含该回答）的历史，不包含后续消息。创建分支只操作已保存的会话记录，不调用 AI、不重新执行项目，也不恢复旧任务；系统 AI 未配置或不可用时仍可创建。原会话保留，只有在分支中发送新消息时才检查模型并开始执行。

## 多 Agent 批次与待发消息

Studio Trace 的 **错误** 分类集中展示运行失败、节点和工具错误以及模型重试原因；重试成功后仍可查看已有诊断，并可按会话和轮次筛选。运行错误不会占用输入框上方的操作错误提示。参数校验、附件和资源打开等操作错误仍在原位置显示，右侧 **×** 可隐藏提示；关闭参数错误提示不会跳过参数校验。

持久 Agent 对话在“正在回复…”右侧显示 **子 Agent** 入口，按当前会话统计运行、排队、失败和已完成数量。点击就地展开任务列表，再展开单项查看角色、阶段、进度、当前活动、结果和错误；**打开子会话** 进入对应的独立对话。匿名委派和项目命名角色均支持，不把 `subagent` 工具调用或其他会话、独立分叉的工作重复计入。入口随任务快照更新，主回复结束后仍保留；后续回复保留展开状态。断线时标明最近状态并禁用子会话跳转，重新连接后恢复。Studio 与独立 CLI Web 共用此界面，完整任务管理仍在 Studio Tasks/Trace。

子 Agent 每行右侧显示运行耗时和 Token 用量，状态保留在图标和展开详情中。耗时从实际开始执行时计起，排队不计时，结束后固定；断线或中断时停在最近快照，旧历史缺少计时记录时显示“—”。最新回答下方的 **会话总用量** 包含主会话和所属子 Agent 的全部已提交消耗，后台执行时继续更新，包括失败、重试和停止前消耗；隐藏子会话入口不会减少用量，重开不重复累计。独立分叉分别统计；单轮回答自身用量继续单独显示。项目关闭 Token 用量展示时，同样隐藏这些 Token 统计。

项目工作进入 `needs_review` 阶段，或返回 `MEDIA_RESULT_UNKNOWN`／`BODY_RESULT_UNKNOWN` 时，子 Agent 图标及详情显示警示色的 **待核对**，保留原因和未完成进度。子会话顶部显示同一工作项的状态与进度；回复正常结束、保存草稿不等于业务验收通过。结果经核验后才显示完成，取消仍显示停止，独立分叉不显示原工作项状态。断线时状态仅代表最近快照。

Tasks 显示角色、视频、阶段、排队状态和已完成／目标；可打开独立子会话、停止单项、重试失败项或停止整个批次。项目业务队列与输入框的待发用户消息分别保存。忙碌时的普通消息先留在宿主，成功的用户轮次完成后才逐条提交；后台报告完成不触发发送。失败、取消或强退保留并暂停待发消息。重新打开包含未完成业务任务的会话不会自动重跑批次；明确输入先清理旧执行树，业务批次通过项目的恢复工具继续，保留草稿和已核验回执。

开启输入队列时，可以连续发送消息，无需等待上一条的发送确认。停止后输入新消息会直接提交，保留的旧队列仍等待成功轮次再继续。点击待发消息的“立即发送”或 × 会立即移走该行；操作失败时恢复原消息并提供重试。新建对话尚未完成时撤回本地待发消息，不会在对话创建后再次发送。

输入框的“停止”取消当前会话的全部执行树，包括后台批次与子 Agent；仍有后台任务时保留停止入口，独立 fork 不包含在该范围内。执行 worker 意外崩溃后先在当前宿主内恢复已有执行树；恢复期间待发消息暂停，已成功的回复保持成功。自动恢复耗尽或宿主自身强退重开后，下一次明确输入先清理旧执行树，再在空闲边界采用更新后的配置，业务批次通过项目恢复工具继续。仅停止前台可通过 Tasks/Trace 的 `cancel scope=foreground` 单独控制。

分叉是独立的新对话，使用各自的服务端会话、执行宿主、租约和配置，可独立选择模型、推理强度、Plan 模式及工具权限。停止、删除或重开原会话不会停止或删除分支；分支历史中的托管附件复制到新会话。原执行的任务、审批、重试、用量和控制回执不带入新对话。不迁移旧版共享宿主或 SQLite 分支。项目共享数据库仍由项目配置决定，不会随对话分叉复制。标题下保留来源入口。

创建分叉和打开子会话只响应当前页面、当前会话发起的对应请求；迟到、重复或其他视图的回执不会自动切换对话。子 Agent 的详情页仍属于其所属执行树，只有用户创建的分支作为独立对话管理。


## 数据库模型与生成

`steamharness database`（简写 `steamharness db`）提供 `init`、`validate`、`generate`，可带项目目录，默认当前目录。项目在 `steamharness.database.ts` 声明多个别名，在 `steamharness.schema` 定义模型；生成无需数据库连接。`workspace pack` 自动为聚合根与注册入口生成并携带 Node/Browser 产物，上传与下载检查静态清单和哈希。

```sh
pnpm exec steamharness database init .
pnpm exec steamharness db validate .
pnpm exec steamharness database generate .
pnpm exec steamharness database generate . --entry billing
```

所有生成命令的目录参数均为聚合项目根。`validate`、`generate` 不带 `--entry` 时处理根与所有已声明入口的数据库定义，并按源码根去重；`--entry <id>` 只处理该入口的源码根。`init --entry <id>` 在该源码根创建定义，无需先构建入口。生成和校验的 JSON 返回 `outputs` 数组，每项包含 `sourceRoot`、`databases`；生成还包含 `directory` 和 `cached`。根定义输出到 `dist/steamharness/generated/database/`，子定义输出到 `dist/steamharness/entries/<encodeURIComponent(entry.root)>/generated/database/`。 Kanban 构建与生成代码按源码根归到同一父目录：根入口默认使用 `dist/steamharness/build/<entryId>/index.html`，子入口使用 `dist/steamharness/entries/<encodeURIComponent(entry.root)>/build/<entryId>/index.html`。显式 `dist` 入口也必须位于自己的构建目录，构建器仅清理该目录。

资源与迁移管理还提供 `create / list / inspect / retry / grant / revoke`、`migrate dev / deploy / status`。`migrate dev --draft` 保存可审阅的 SQL、模型快照与校验清单，`deploy` 只应用已有历史；`--database` 指定资源 UUID，`--alias` 指定模型别名（默认 main）。管理命令需要目标 Server 的账号登录，可用 `--server` 和 `--token` 覆盖。详见 [SteamHarness Database](/core-api/database)。关系库使用 `bind [directory] --database <id> [--entry <id>] [--alias main] [--mode read|write]` 绑定入口，`bindings [directory] [--entry <id>]` 查询宿主绑定，`unbind [directory] [--entry <id>] [--alias main]` 解除。绑定按账号、项目、入口和别名保存于 Server，不写回项目文件，也不授予资源权限。Node 入口通过 `context.databases.connect(descriptor)` 查询；Browser 通过 `window.steamHarnessKanban.databases.connect(descriptor)` 使用表级 `rows/insert/update/delete`。旧 KV API 已移除。

Studio 与 CLI Web 的资源启动检查区分网络、登录、权限和绑定问题。Server 暂时不可达时，每 5 秒自动重新检查；恢复连接后清除临时提示。重新检查只读取当前授权与绑定，不重新提交业务操作。

初次检查和正常结果保持静默。自动重试或同账号复查期间保留上次检查结果和页面内容，检查完成后再更新提示；切换账号或 Server 时会清理旧结果并重新校验。失败提示提供 HTTP 状态（如有）、处理步骤和“连接详情”中的服务器、项目 ID 与入口。通过“账号 / 服务器设置”核对登录，通过“项目信息 → 数据库”检查资源引用，或直接“打开云端项目”核对登记与权限。Server 返回 5xx 时应检查服务器日志及已登记入口；只有需要新建应用时才使用“创建项目”，该操作会申请新 ID，不会迁移原项目的数据与权限。

配置附件上传期间，后台账号校验不会中断上传；实际切换账号或失去登录后，宿主会拒绝旧账号的上传结果，需在当前账号下重新选择文件。

持久 Agent 的命令确认与快照传输分别处理。确认超时或临时连接错误会自动按原请求 ID 重试，最多 3 次；恢复后继续原输入，迟到回执也会核对同一请求。项目连接恢复后，可恢复的运行沿用原 runId 自动继续。主动停止会取消待确认命令的重试；持续失败保留原因及原请求供显式重试。

## 平台运行历史

Bot、Workflow 与助手历史默认持久化到宿主本地 SQLite，包括消息、Run、队列、草稿、参数、用量和 Agent 检查点；重开可恢复，无需为历史存储登录或连接 Server。回复按流式事件展示，历史合并保存，不等待云端上传。系统 AI 和业务资源仍分别校验授权。跨窗口由本地文件锁互斥，进程退出后自动释放。云端存储须显式选择，也可通过 `copyRuntimePersistence` 在会话空闲时后台备份到空目标；已有云端和旧本地记录保留，不自动迁移或覆盖。附件和工作区文件另行备份。详见[运行存储](/core-api/runtime-storage)。

## 知识库与表数据管理

`steamharness knowledge` 提供 `create / list / grants / grant / revoke / bind / unbind / bindings / operation`。绑定使用 `--knowledge-base <UUID>`、`--alias <alias>`、`--entry <entry>`，缺省 alias 为 main。`list --page 2 --page-size 20 --search Docs` 在服务端分页和过滤。`operation <UUID> knowledge.listDocuments < input.json` 接受 JSON 标准输入，操作请求不自动重放；附件正文传输上限 50 MiB。

`steamharness database data <UUID> < request.json` 管理已应用模型的表数据，operation 为 `models / rows / insert / update / delete`。先读取 models 的 schemaHash，后续请求传该值；更新和删除还需要当前 rowVersion 和完整稳定 key。请求输入上限 4 MiB。BigInt、Decimal 使用十进制字符串，DateTime 使用带时区的 ISO 并按 UTC 读写，Bytes 使用 Base64；枚举使用声明值，未提供且无默认值的列表写为空数组。`database list` 也支持上述分页参数。详见 [知识库 API](/core-api/knowledge-documents) 与 [数据库 API](/core-api/database)。

Kanban 可通过聚合宿主调用已登记 Workflow 和订阅原生 Bot，详见 [Kanban](/concepts/kanban) 与 [入口会话控制](/concepts/database-and-conversation#本地-conversation-入口控制)。宿主复用各入口原生控制器、执行 owner 与队列；Studio 的同一聚合项目共享此宿主。

## 项目发行模式

`steamharness release . --json` 生成 `dist/release/project/` 和同级版本压缩包。发行目录保留可读的项目 UUID、版本、入口、参数、工具及配置定义；业务 JavaScript 合并压缩、局部变量名混淆，不携带 TypeScript 源码和 source map。

```sh
pnpm exec steamharness release .
pnpm exec steamharness web . --release
pnpm exec steamharness json . --release --entry main
pnpm exec steamharness workspace pack example --path . --mode release
```

根 `steamharness.json` 的可选 `release` 控制发行内容。例如：

```json
{
  "release": {
    "entries": ["agent", "database", "board"],
    "defaultEntry": "agent",
    "entryOverrides": {
      "agent": { "entry": "index.release.ts", "configuration": "configuration.release.json", "profiles": ["ask"] }
    },
    "build": ["corepack", "pnpm", "run", "build"],
    "files": ["README.md", "LICENSE"],
    "externals": []
  }
}
```

`entries` 缺省包含全部入口。覆盖模块、配置和 `assets` 路径相对原入口根；`files` 相对聚合根，支持 glob。未指定 `build` 时使用项目的 `build` 脚本；包含 Kanban 必须有构建步骤。依赖默认打包，SDK 和 Node 内置模块由宿主提供；无法打包的 npm 包放入 `externals`，发行清单写入已安装的精确版本。文件包含规则不能绕过凭据、源码、测试和运行数据的排除规则。

入口裁剪必须同时处理跨入口依赖。`profiles` 只裁剪配置，若需要彻底移除某项能力，应使用发行专用模块，并将相关实现拆成独立依赖，不能仅隐藏界面选项。

运行命令的 `--release` 会检查输入指纹并在需要时重新构建，使用固定的构建快照运行。发行运行与源码运行的本地会话、配置和检查点分别保存在宿主/用户数据目录；两者仍使用原项目 UUID 和服务器资源绑定。删除 `dist/` 不会删除运行数据。

Studio 在运行按钮右侧提供“运行（发行模式）”，显示可取消的构建进度。源码项目只显示本地声明的版本；下载或导入的发行项目检查可用升级，默认进入 Steam 模式并隐藏 IDE 模式切换。发行安装不能被源码版本替换。

上传和打包支持 `--mode auto|source|release`，默认 `auto`：存在发行配置或发行结果时，先检查并构建最新发行结果，再上传发行目录。构建失败会停止上传，不回退到源码。`source` 显式上传源码；`release` 强制发行。发行上传使用完整文件清单，不继承源码 `.steamharnessignore`；服务器发布配置时遵守发行 profile 和字段限制。

发行目录中的 `steamharness.release.json` 声明格式版本、构建身份及文件哈希。宿主在检查、运行和下载时验证它；不支持该格式的旧宿主需要升级。发行命令只生成项目产物，不发布 npm 包或部署服务。
