# workspace status

用 `workspace status` 检查保存的登录信息，以及本次命令真正会使用的服务器。它只读本地配置，不访问 Server，因此不能证明 API Key 仍有效。

连接设置按以下顺序解析：

1. `--server` 与 `--token`。
2. `STEAMHARNESS_SERVER_URL` 与 `STEAMHARNESS_SERVER_ADMIN_KEY`。
3. 保存的 CLI 登录信息。
4. 渠道默认值。

查看 `effective.serverUrl` 和 `effective.tokenSource` 确认本次连接设置。`serverUrl` 只表示保存值。指定其他地址时，不会复用原地址的凭证。

## 命令格式

```bash
pnpm exec steamharness workspace status
pnpm exec steamharness workspace status --ai --server https://server.example.com
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--ai` | 查看系统 AI 凭证；此时使用 `STEAMHARNESS_AI_SERVER_URL` 和 `STEAMHARNESS_AI_API_KEY`。 |
| `--server <URL>` | 仅查看指定地址的登录与连接设置。 |

## 输出字段

| 字段 | 说明 |
| --- | --- |
| `loggedIn` | 本机保存了服务器地址和未过期的 API Key 时为 `true`，不代表已通过 Server 验证。 |
| `serverUrl` | CLI 登录态中保存的 server URL。 |
| `user` | 最近一次 device flow 登录得到的用户摘要。 |
| `expiresAt` | API Key 过期时间。 |
| `expiringSoon` | 距离过期不足 3 天时为 `true`。 |
| `source` | 登录来源，当前为 `device_flow` 或 `manual`。 |
| `effective.serverUrl` | 本次调用实际会使用的 server URL。 |
| `effective.serverSource` | 该 server URL 的来源：`env`、`flag`、`file` 或 `default`。 |
| `effective.tokenSource` | 本次调用会使用的 token 来源：`env`、`flag`、`file` 或 `none`。 |

## 示例输出

```json
{
  "errCode": 0,
  "errMessage": "",
  "data": {
    "loggedIn": true,
    "serverUrl": "http://localhost:7126",
    "user": {
      "userId": "user-1",
      "email": "user@example.com",
      "displayName": "Normal User"
    },
    "expiresAt": "2026-07-01T00:00:00.000Z",
    "expiringSoon": false,
    "source": "device_flow",
    "effective": {
      "serverUrl": "https://server-alpha.example.com",
      "serverSource": "env",
      "tokenSource": "env"
    }
  }
}
```

## 示例

```bash
pnpm exec steamharness workspace status
```

## 注意事项

| 场景 | 说明 |
| --- | --- |
| 需要验证 server 可用 | 使用 [`health`](/cli/workspace/health)。 |
| 需要验证 token 可用 | 使用 [`login`](/cli/workspace/login) 重新验证，或执行需要鉴权的命令。 |
| 需要知道命令会连哪台服务器 | 看 `effective`；`serverUrl` 只是保存的登录，可能已被环境变量或命令行参数覆盖。 |
