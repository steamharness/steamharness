# workspace upload

用 `workspace upload` 替换 Server 项目的源码草稿。上传覆盖聚合项目的全部注册入口。

## 命令

```sh
pnpm exec steamharness workspace upload <project-id> --path .
```

先登录 Server，确认项目已注册且账号有写入权限。安装依赖、构建静态入口并执行 `steamharness check .` 后再上传。

## 上传方式

| 选项 | 用途 |
| --- | --- |
| `--path` | 从源码目录打包上传 |
| `--file` | 上传已打包归档 |
| `--mode release` | 构建或更新发行包后上传编译产物 |
| `--no-wait` | 返回准备任务，随后用 `preparation <project-id> <job-id>` 查询 |

只有静态校验通过，Server 才替换草稿。它不安装依赖或执行项目代码。上传后创建不可变版本，继续执行 [publish](/cli/workspace/publish)。

上传发行包时，Server 保留编译入口与项目版本，并将当前项目名称、头像和声明同步到草稿。完整性校验通过后才能发布；被修改或缺少文件的发行包会被拒绝。

## 数据与凭据

归档包含代码、依赖清单、配置定义和 Kanban 产物，过滤宿主凭据和运行数据。关系库绑定保存在 Server，换账号或环境后需要重新检查授权。文件规则见 [pack](/cli/workspace/pack)。
