# Kanban 入口

Kanban 是聚合项目中的静态 HTML 入口，不导出 executor。注册示例：

```json
{ "entryId": "map", "type": "kanban", "name": "Map", "root": "map", "entry": "dist/map/index.html", "configuration": "configuration.json", "databases": [] }
```

`root` 指向源码目录；Kanban 的 `entry` 相对聚合项目根解析，省略时默认 `dist/<entryId>/index.html`。Workflow/Conversation 的源码入口仍相对各自 `root`。前端只清理 `dist/<entryId>/`，保留数据库生成目录。

构建必须先在客户端完成。Server 只验证、保存及提供静态文件，不安装依赖或运行构建。资源引用使用入口相对路径，上传与安装保留全部注册入口的产物。

Studio 提供最小看板与两种任务看板。任务看板先生成数据库描述符并构建 dist/map/index.html，再进行检查；以 data 别名读写 Task 行，按 configurationId 筛选。未绑定或加载失败时禁用编辑并显示错误。

## 配置与展示

宿主注入 `window.steamHarnessKanban`。`getConfiguration()` 读取当前入口配置，`getPresentation()` 读取展示模式；监听 `steamharness:kanban-configuration-change` 和 `steamharness:kanban-presentation-change` 更新页面。命名配置、快照和配置附件按 `projectId + entryId` 隔离。

相同配置快照不会重复触发配置事件或就绪通知；配置变化在现有页面内生效。CLI Web 与 Studio 在连接中断时保留预览，持续断线才显示重连浮层，恢复连接不会挤动地图画布。

文件 Bridge 允许最多 120 秒读取大附件，后台任务使用相同的文件时限。超时后保留错误与重试入口。

## 数据 Bridge

```js
import { data } from "./dist/steamharness/generated/database/browser/index.js";
const api = window.steamHarnessKanban;
const database = await api.databases.connect(data);
const configurationId = api.getConfiguration().id || "default";
const page = await database.task.rows({ where: { configurationId } });
const row = await database.task.insert({ id: crypto.randomUUID(), configurationId, title: "Review", status: "todo" });
await database.task.update({ key: { id: row.values.id }, rowVersion: row.rowVersion, data: { status: "done" } });
```

必须在该入口的 `databases` 中声明 alias，获批后才能访问。数据 Bridge 在宿主端校验入口、用户及空间授权；页面不能选择任意项目或数据库。知识库通过 `window.steamHarnessKanban.knowledgeBases.get("docs")` 访问，附件通过 `window.steamHarnessKanban.knowledgeBases.get("docs").files.createFile/readFile/deleteFile` 访问。

Server 将知识附件保存在私有文件存储，PostgreSQL 保存元数据与摘要。关系表更新和删除通过 rowVersion 检查并发版本。读写失败明确显示，写入失败保留已保存记录与用户草稿。

## 页面方法

```js
window.steamHarnessKanban.methods.register({
  name: "focus", description: "Focus a map location", readOnly: true,
  inputSchema: { type: "object", properties: { x: { type: "number" } } },
}, async (input, { signal }) => ({ focused: input.x }));
```

方法目标包括 `projectId`、`entryId`、来源、位置与实例。资源卡片及预览同样携带 `entryId`。方法必须验证业务参数并响应取消信号；刷新或关闭实例后重新枚举。

## 安全与宿主

Studio 中的快捷键以页面处理为先：在 `keydown` 处理函数中调用 `event.preventDefault()` 可保留项目快捷键；未处理的按键交给 Studio 的快捷键系统。该规则同时适用于独立 Kanban 标签和资源卡片预览。普通浏览器中的 Kanban 保留浏览器的按键行为。

CLI Web 使用 `/entries/map/`；Studio 可以将入口打开为独立标签；Server Web 提供经过鉴权的静态预览。预览使用沙箱、受约束的相对资源路径和短期能力凭据；`studio.getLocalAnalysis()` 仅由支持的本地 Studio 宿主提供。

发布以整个聚合项目为单位。数据库需求随包保存，绑定与凭据不随安装转移。详见 [数据库资源](/concepts/data-storage) 与 [打包](/cli/workspace/pack)。

知识库必须独立声明 `knowledgeBases: ["docs"]`，根配置映射 `knowledgeBases.docs`，并建立 Server 绑定。可在 `knowledgeBases.get("docs").subscribe(...)` 订阅不透明修订号；同名业务库 alias 的更新不会触发此订阅。

## 调用聚合内 Workflow 与订阅会话

在本地 CLI Web 或 Studio 中，页面通过 `window.steamHarnessKanban.entries.get("api").runEntrypoint("state", ["--payload", "{}"])` 调用已登记 Workflow 的操作。页面不能指定用户或项目身份；数据写入与消息路由可以统一放在该 Workflow 中。

Workflow 调用独立使用 120 秒 Bridge 时限，供数据库授权及持久回执完成；Conversation 的提交、恢复队列、确认输入和停止 IPC 同样允许最多 120 秒，普通只读 IPC 保持 15 秒。回执不等待模型完成，耗时模型工作由持久队列异步执行。超时可能已有副作用，页面应保留请求 ID 并查询回执，不自动重放写入。

数据库错误的已知公开 `code` 会跨节点报告及 Workflow 调用保留。Bridge 仅将白名单代码映射为固定提示（如 `DATABASE_UNBOUND`、`DATABASE_BUSY`、`DATABASE_SCHEMA_MISMATCH`），不向页面暴露底层连接串、SQL、文件路径或任意异常文本。

`conversations.snapshot(entryId, conversationId)` 读取原生会话投影，`conversations.subscribe({ entryId, conversationId }, listener, onError)` 通过现有 SSE / IPC 通道接收流式输出、队列、审批和运行状态，返回注销函数。最多保留 16 个订阅。配置、身份或 iframe 代次变化时注销旧订阅，忽略旧快照；重新连接后重新读取并订阅。不要用轮询最后一条消息判断某个请求完成，必须匹配 `requestId`。

Server 静态预览对这些执行操作返回 `409` 和安全代码 `ENTRY_RUNTIME_UNAVAILABLE`，页面应提示使用本地 CLI Web / Studio。对话中的只读资源预览保持原数据访问边界。
