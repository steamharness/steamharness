# 独立数据库空间

数据库是 local 或 server 宿主的独立资源。一个 `spaceId` 同时承载 KV、知识库、索引、附件与修订号，可由多个项目和入口获批访问。删除项目不会删除空间。

## 记录数据库引用

项目根目录的 `config.json` 集中维护部署配置，`databases` 只保存唯一的别名到数据库 ID 映射，不包含 `entries`。`package.json` 的各入口仅通过 `databases` 字符串数组声明使用的别名。权限和凭据由宿主管理。旧的 `{alias, databaseId}` 对象数组以及 `host`、`permissions`、`bindingRef` 声明不再接受。

```json
{
  "version": 1,
  "databases": {
    "data": "00000000-0000-4000-8000-000000000001",
    "archive": "00000000-0000-4000-8000-000000000002"
  }
}
```

各入口在 `package.json` 中引用所需别名：

```json
{
  "steamHarness": {
    "defaultEntry": "agent",
    "entries": [
      { "entryId": "agent", "type": "conversation", "name": "Agent", "root": "agent", "entry": "index.ts", "databases": ["data", "archive"] },
      { "entryId": "database", "type": "workflow", "name": "Database", "root": "database", "entry": "index.ts", "databases": ["data"] }
    ]
  }
}
```

示例 UUID 必须替换为宿主批准的真实 ID。一个数据库使用一个别名，多个入口引用同一别名；一个入口可以关联多个数据库。业务代码仍使用 `context.databases.get("data")`。迁移时只修改 `config.json` 中 `databases.data` 一处，所有引用它的入口在下一次执行时采用新 ID。

环境变量 `STEAMHARNESS_PROJECT_CONFIG` 接受 JSON 对象，例如 `{"databases":{"data":"00000000-0000-4000-8000-000000000003"}}`。它按别名覆盖数据库 ID，优先于文件；也可提供完整配置，无需文件。缺失别名、无效 UUID 或重复 ID会明确报错，不回退到其他数据库。配置不执行项目代码，也不会自动读取 `.env`。宿主启动时注入环境变量；上传、打包及 Store 发行保留原始 `config.json`，不会把运行机器的环境覆盖值写进源码。

宿主授权分别控制 `kv.read/write` 与 `knowledge.read/write`，每条规则为 `{"mode":"none"}`、`{"mode":"all"}` 或 `{"mode":"prefixes","prefixes":["public:"]}`。KV 列表在分页和计数前应用获批的键范围；客户端传入的键前缀只能进一步收窄范围。

## 申请与审批

1. 在 CLI Web 或 Studio 中打开目标入口，点击顶部“数据库”；若已显示“请处理数据库绑定”，直接点击提示中的“打开数据库管理”，即可处理对应 alias。小助手也支持此操作；Server Web 提供独立数据库页面。
2. 申请创建新空间，或填写已有 `spaceId` 申请访问。提交后状态为 `pending`，此时不能访问数据，也不会创建空间。
3. local 由本机宿主使用者显式批准；Server 的新空间由系统管理员批准，申请人成为空间负责人；共享访问由空间负责人或系统管理员批准。
4. 审批者可拒绝并填写原因，也可收窄权限后批准。批准返回 `databaseId`，并在宿主维护项目、入口对应的授权。申请前不需要在清单声明数据库。
5. 在目标别名下填写获批 ID，点击“保存数据库引用”。保存时更新根 config.json 的共享映射，并在当前入口的 package.json 声明中添加该别名；实际访问按当前入口重新校验授权，不创建数据库或授予权限。拒绝或撤销后可重新申请；凭据轮换由宿主刷新。

CLI Web 与 Studio 使用同一用户级 SQLite 注册表，空间数据目录按 `spaceId` 隔离。Server 使用独立持久化目录与 PostgreSQL。普通项目成员角色仍限制调用者的数据访问，空间授权不能提升用户角色。

## 使用与共享

```ts
const database = context.databases.get("data");
await database.transaction(async db => {
  await db.kv.setValue("settings:theme", "dark");
  await db.knowledge.createDocument({
    id: "guide", title: "Guide", markdown: "# Guide\nShared content",
  });
});
const theme = await database.kv.getValue("settings:theme");
const document = await database.knowledge.getDocument("guide");
```

项目与入口身份用于鉴权和记录写入来源，数据按空间寻址。普通 KV 不能访问知识库的保留键。知识库附件也需要有效知识库权限。每次操作、事务、CAS、锁和修订订阅都重新检查授权。

两个项目通过各自申请绑定到同一空间后，可以共享相同键、知识库与附件；会话 KV 继续以项目、入口和会话身份隔离。索引修改与知识文档一起提交。

## 引用不可用

未知 ID、未获批或撤销的授权会显示错误与宿主管理入口。其他入口仍可管理和运行。上传、打包与 Store 发行保留别名到 ID 的引用。引用不携带权限或凭据，宿主始终校验调用者、项目和入口授权。
