# 项目数据存储

SteamHarness 将业务模型、知识内容和运行历史分别管理。业务库和知识库通过 Server 授权；运行历史默认保存在宿主本地 SQLite，无需为历史存储连接 Server。

| 数据 | 存储和隔离 | 项目 API |
| --- | --- | --- |
| 自定义业务模型 | 每个显式申请的资源拥有独立 PostgreSQL database 和权限角色 | `context.databases.connect(descriptor)` |
| 知识文档、分块、搜索索引、附件元数据 | 平台共享关系表，按知识库 UUID 及账号授权隔离 | `context.knowledgeBases.get(alias)` |
| Conversation、消息、Run、队列、Usage、Agent 状态 | 宿主本地 SQLite，按项目、入口和会话隔离；云端按需备份 | 宿主运行存储 |
| 知识附件正文 | Server 私有文件存储，SQL 保存元数据和校验和 | `knowledge.files` |

新建项目或对话不会自动创建 PostgreSQL database。A、B 项目分别申请业务资源后，可定义结构不同的 `User` 表；共享必须显式绑定到同一资源并获得授权。知识库独立于业务库，不需要项目定义系统知识表。

## 产物与运行数据目录

所有可重建产物统一写入聚合项目根的 `dist/`，子入口不得另建产物根：

| 内容 | 路径 |
| --- | --- |
| 根数据库定义的生成代码 | `dist/steamharness/generated/database/` |
| 子入口数据库定义的生成代码 | `dist/steamharness/entries/<encodeURIComponent(entry.root)>/generated/database/` |
| 编译和静态页面 | `dist/<entryId>/` |
| 工具缓存、测试报告和打包文件 | `dist/cache/`、`dist/reports/`、`dist/release/` |

子入口使用完整 `entry.root` 的 URL 编码，例如 `apps/board` 对应 `apps%2Fboard`；同一源码根的入口共用生成代码。每个构建器只清理自己的子目录，不能清空整个 `dist/`。源码、配置、数据库模型和迁移保留在源码目录，根 `.gitignore` 忽略 `/dist/`。

会话、检查点、登录状态和其他持久数据保存在宿主应用数据目录或用户目录，不能写入源码目录或 `dist/`。独立 SDK 默认使用 `~/.steamharness/runtime/<projectId>/<entryId>/`；CLI Web 的 `--data-dir` 同样必须在项目外。删除 `dist/` 后重新生成和构建即可恢复产物，外部运行数据不受影响。旧路径不再读取、迁移或回退；迁出已有持久数据时先关闭对应宿主，离线移动并保留权限。

## 业务数据库

在 `steamharness.database.ts` 声明多个别名，在 `database/<alias>/steamharness.schema` 定义模型；CLI 生成 Node/Browser 描述符和类型。创建、授权、迁移、绑定由 `steamharness database` 管理。关系库绑定按账号、项目、入口和别名保存在 Server，不写入旧 `config.databases` 映射。连接不自动建库或迁移。

```ts
import { main } from "./dist/steamharness/generated/database/node/index.js";
const db = await context.databases.connect(main);
await db.user.create({ data: { id: "alice", name: "Alice" } });
```

参见 [SteamHarness Database](/core-api/database)。

## 知识库声明

```sh
steamharness knowledge create "Docs"
steamharness knowledge bind . --entry main --alias docs --knowledge-base <UUID>
```

入口 `steamharness.json` 声明 `"knowledgeBases": ["docs"]`；项目根 `config.json` 保存部署映射：

```json
{
  "version": 1,
  "knowledgeBases": {
    "docs": "00000000-0000-4000-8000-000000000001"
  }
}
```

替换示例 UUID 为创建结果。多个入口可复用同一别名，一个入口可声明多个知识库。`STEAMHARNESS_PROJECT_CONFIG` 接受 JSON，例如 `{"knowledgeBases":{"docs":"00000000-0000-4000-8000-000000000002"}}`，按别名覆盖文件值；不自动读取 `.env`，分发保留原文件，不把环境值写回源码。未知、缺失、重复别名或无效 UUID 明确失败。

```ts
const knowledge = context.knowledgeBases.get("docs");
const doc = await knowledge.createDocument({ title: "Guide", markdown: "# Guide" });
await knowledge.editDocument({ id: doc.id, markdown: "# Updated", expectedRevision: doc.revision });
```

Server 同时校验账号授权和消费方绑定；已注册项目额外校验项目成员与入口声明。修改 ID 后须在 Server 建立匹配绑定并重新打开入口；旧客户端不能将草稿写入另一个资源。撤权及授权版本变化同样失效旧客户端。`knowledge unbind` 删除 Server 绑定，保留项目声明供之后重新绑定。参见 [知识库 API](/core-api/knowledge-documents)。

## 管理入口

Server Web 的“数据库”提供关系库与知识库目录，支持服务端分页、搜索和创建。资源页面管理账号授权及项目入口绑定；关系库显示已应用模型、指纹和表数据，知识库管理文档与附件。编辑表行需要完整稳定键和当前行版本，冲突时保留草稿；未保存草稿受导航保护。

Studio 数据库视图和 CLI Web 项目数据库面板展示资源引用，并打开对应 Server Web 页面，链接不含账号 token。管理入口不提供 KV 编辑或本地/远程 KV 切换。旧 KV 与本地 KV API 已删除，不保留兼容入口或自动迁移。

## 客户端缓存

个人配置、用户模型设置和运行历史保存在宿主本地。系统 AI 目录按服务地址和账号在进程内缓存 30 秒；CLI 资源引用与 Studio 资源视图短期复用 5 秒的展示数据。并发读取合并，手动刷新和修改使相应展示缓存失效，账号切换清除旧状态。缓存不作为执行权限证明，执行前仍在线检查绑定。

配置模板和配置附件沿用经过校验的本地快照与内容缓存。知识库正文、搜索、发布、授权、资源创建与迁移保留在线确认；附件内容可在在线校验访问权后复用有界内存缓存或条件请求。敏感目录凭据只保存在内存，缓存不增加自动上传、离线授权或后台业务写入。

## 持久历史与故障

对话历史默认使用本地运行存储，与业务库或知识库的授权和生命周期分别管理。运行事件先供视图消费，历史在本地持久化；按需备份在后台执行。系统 AI 或业务资源断连可能影响对应操作，不影响已保存历史的读取。显式选择 Server 仓储时，断连、撤权和租约丢失明确失败。已有云端及旧本地记录不删除或自动覆盖。删除项目不会自动删除独立资源。参见[运行存储](/core-api/runtime-storage)。
