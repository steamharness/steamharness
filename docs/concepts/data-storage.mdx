# 项目数据存储

先区分业务数据、知识内容和运行历史，再选择存储接口。业务库和知识库由 Server 授权；运行历史默认保存在宿主本地 SQLite，不要求连接 Server。

| 数据 | 存储和隔离 | 项目 API |
| --- | --- | --- |
| 自定义业务模型 | 每个显式申请的资源拥有独立 PostgreSQL database 和权限角色 | `context.databases.connect(descriptor)` |
| 知识文档、分块、搜索索引、附件元数据 | 平台共享关系表，按知识库 UUID 及账号授权隔离 | `context.knowledgeBases.get(alias)` |
| Conversation、消息、Run、队列、Usage、Agent 状态 | 宿主本地 SQLite，按项目、入口和会话隔离；云端按需备份 | 宿主运行存储 |
| 知识附件正文 | Server 私有文件存储，SQL 保存元数据和校验和 | `knowledge.files` |

资源隔离取决于绑定：

- 创建项目或会话不会自动创建 PostgreSQL database。
- 两个项目分别申请资源后，可以定义结构不同的同名表，例如 `User`。
- 需要共享时，显式绑定同一资源，并分别取得授权。
- 知识库独立管理，不需要在业务项目中定义系统知识表。

## 产物与运行数据目录

所有可重建产物统一写入聚合项目根的 `dist/`，子入口不得另建产物根：

| 内容 | 路径 |
| --- | --- |
| 根数据库定义的生成代码 | `dist/steamharness/generated/database/` |
| 子入口数据库定义的生成代码 | `dist/steamharness/entries/<encodeURIComponent(entry.root)>/generated/database/` |
| 根入口编译和静态页面 | `dist/steamharness/build/<entryId>/` |
| 子入口编译和静态页面 | `dist/steamharness/entries/<encodeURIComponent(entry.root)>/build/<entryId>/` |
| 工具缓存、测试报告和打包文件 | `dist/cache/`、`dist/reports/`、`dist/release/` |

目录按源码根和入口区分。将完整 `entry.root` 做 URL 编码，例如 `apps/board` 对应 `apps%2Fboard`；同一源码根共用生成代码，各入口分别写入 `build/<entryId>/`。

构建器只能清理自己的子目录。源码、配置、模型和迁移继续放在源码目录，并在根 `.gitignore` 中忽略 `/dist/`。

`entryId` 不得使用受管目录名 `steamharness`、`cache`、`reports`、`release`、`tmp`，也不得使用 Windows 设备名 `con`、`prn`、`aux`、`nul`、`com1`–`com9`、`lpt1`–`lpt9`。显式入口路径位于 `dist/` 时，必须指向当前源码根对应的 `build/<entryId>/`，不能占用 `generated/` 或其他入口的输出。

### 保存持久数据

会话、检查点和登录状态必须放在宿主应用数据目录或用户目录，不能放进源码或 `dist/`。

| 宿主 | 位置要求 |
| --- | --- |
| 独立 SDK | 默认 `~/.steamharness/runtime/<projectId>/<entryId>/` |
| CLI Web | `--data-dir` 必须位于项目目录之外 |

删除 `dist/` 后重新生成、构建即可，项目外的运行数据不受影响。旧路径不会自动读取、迁移或回退；需要迁出持久数据时，先关闭宿主，再离线移动并保留文件权限。

## 业务数据库

1. 在 `steamharness.database.ts` 声明别名，在 `database/<alias>/steamharness.schema` 定义模型。
2. 用 CLI 生成 Node/Browser 描述符和类型。
3. 用 `steamharness database` 创建资源、授权、迁移并绑定入口。
4. 在运行代码中连接生成的描述符。

绑定按账号、项目、入口和别名保存在 Server，不写入旧 `config.databases`。调用连接方法不会自动建库或迁移。

```ts
import { main } from "./dist/steamharness/generated/database/node/index.js";
const db = await context.databases.connect(main);
await db.user.create({ data: { id: "alice", name: "Alice" } });
```

参见 [SteamHarness Database](/core-api/database)。

## 知识库声明

```sh
steamharness knowledge create "Docs"
steamharness knowledge bind . --entry main --alias docs --knowledge-base <UUID>
```

入口 `steamharness.json` 声明 `"knowledgeBases": ["docs"]`；项目根 `config.json` 保存部署映射：

```json
{
  "version": 1,
  "knowledgeBases": {
    "docs": "00000000-0000-4000-8000-000000000001"
  }
}
```

替换示例 UUID 为创建结果。多个入口可复用同一别名，一个入口可声明多个知识库。`STEAMHARNESS_PROJECT_CONFIG` 接受 JSON，例如 `{"knowledgeBases":{"docs":"00000000-0000-4000-8000-000000000002"}}`，按别名覆盖文件值；不自动读取 `.env`，分发保留原文件，不把环境值写回源码。未知、缺失、重复别名或无效 UUID 明确失败。

```ts
const knowledge = context.knowledgeBases.get("docs");
const doc = await knowledge.createDocument({ title: "Guide", markdown: "# Guide" });
await knowledge.editDocument({ id: doc.id, markdown: "# Updated", expectedRevision: doc.revision });
```

更换知识库时按以下顺序处理：

1. 更新配置中的 ID，并在 Server 建立匹配的消费方绑定。
2. 确认账号授权；已注册项目还需要相应成员权限和入口声明。
3. 重新打开入口，让客户端读取新绑定。

旧客户端不能把原草稿写入替换后的资源。撤权或授权版本变化也会使旧客户端失效。`knowledge unbind` 只移除 Server 绑定，保留声明供后续重新绑定；接口见[知识库 API](/core-api/knowledge-documents)。

## 管理入口

在 Server Web 打开 **数据库**，选择关系库或知识库，再搜索或创建资源。

| 页面 | 可完成的操作 |
| --- | --- |
| 资源详情 | 管理账号授权和项目入口绑定 |
| 关系库 | 查看已应用模型、指纹和分页表数据 |
| 知识库 | 管理文档与附件 |

编辑表行需要完整稳定键和当前行版本。版本冲突会保留草稿；离开页面前需要处理未保存的编辑。

Studio 数据库视图和 CLI Web 项目数据库面板展示资源引用，并打开对应 Server Web 页面，链接不含账号 token。管理入口不提供 KV 编辑或本地/远程 KV 切换。旧 KV 与本地 KV API 已删除，不保留兼容入口或自动迁移。

## 客户端缓存

个人配置、用户模型设置和运行历史保存在宿主本地。资源展示数据采用以下缓存：

| 数据 | 复用范围与时长 |
| --- | --- |
| 系统 AI 目录 | 当前进程内，按服务地址和账号隔离，30 秒 |
| CLI 资源引用、Studio 资源视图 | 展示数据复用 5 秒 |

并发读取会合并；手动刷新或修改使相应展示缓存失效，切换账号会清除旧状态。执行前仍在线检查绑定，展示缓存不能证明执行权限。

配置模板和配置附件沿用经过校验的本地快照与内容缓存。知识库正文、搜索、发布、授权、资源创建与迁移保留在线确认；附件内容可在在线校验访问权后复用有界内存缓存或条件请求。敏感目录凭据只保存在内存，缓存不增加自动上传、离线授权或后台业务写入。

## 持久历史与故障

对话历史默认写入本地运行存储，独立于业务库和知识库的授权、生命周期。视图接收运行事件，本地同时保存历史；按需备份在后台执行。

| 情况 | 对已有历史的影响 |
| --- | --- |
| 系统 AI 或业务资源断连 | 对应操作可能失败，仍可读取已保存历史 |
| 显式选择 Server 仓储后断连、撤权或丢失租约 | 存储操作明确失败 |
| 已有云端或旧本地记录 | 保留，不自动覆盖 |
| 删除项目 | 不自动删除独立资源 |

接口和备份方式见[运行存储](/core-api/runtime-storage)。
