# Workflow 定时运行

定时计划按时间规则调用一个 Workflow 操作，每次触发创建独立运行。Bot 与 Kanban 不能作为调度目标，所选操作也不会先执行默认操作。

在 Studio 桌面版中，打开**项目仓库 → 项目详情 → Workflow 定时计划**。只有受信任的本地源码项目可以设置计划。项目包含多个 Workflow 入口时，先选入口，再在计划页选择要执行的操作。

1. 点击**新建计划**，选择时区和规则。也可以从**建议计划**填入项目提供的预设。
2. 点击**预览未来 5 次**核对时间。保存会检查该操作能否使用所填的参数，不会运行项目。
3. 点击**启用计划**，确认目录、入口、版本和时区。只想试一次时可以用**立即运行**，不必先启用计划。

定时计划需要项目安装支持该功能的 SteamHarness CLI。看到升级提示时，请更新该项目的运行时；Studio 不会自动修改项目依赖。

## 触发规则

计划使用 IANA 时区，并支持两种触发方式：

- `window-interval`：选择星期、一个或多个时间窗口，以及每 N 分钟。窗口包含起止时刻，例如 `09:30-11:30 / 5 分钟` 会包含 `09:30` 和 `11:30`。
- `cron`：五字段 Cron 表达式，按计划时区计算。秒字段不受支持。

```ts
type ScheduleTrigger =
  | {
      kind: "window-interval";
      weekdays: number[]; // 1-7，周一到周日
      windows: Array<{ start: string; end: string }>;
      intervalMinutes: number;
    }
  | {
      kind: "cron";
      expression: string;
    };
```

计划只接受操作声明的静态参数，不支持文件输入或日期占位模板。需要“当天”等动态日期时，请在 Workflow 内读取业务时区的当前时间。不要把凭据填入计划参数。

## 声明建议计划

根入口把 `schedulePresets` 写在内联入口中，子入口写在自己目录的 `steamharness.json` 中。例如子入口配置：

```json
{
  "type": "workflow",
  "name": "Scheduled workflow",
  "entry": "index.ts",
  "schedulePresets": [
    {
      "id": "hourly",
      "title": "Hourly sync",
      "entrypointId": "sync",
      "timezone": "Asia/Shanghai",
      "trigger": {
        "kind": "cron",
        "expression": "0 * * * *"
      },
      "paramValues": {}
    }
  ]
}
```

预设 ID 必须匹配 `/^[a-z][a-z0-9_-]{0,63}$/`，项目内唯一，并引用当前 Workflow 已声明的 entrypoint。预设只是建议：本地调度宿主可以按其能力展示并确认，导入或发布项目不会静默开启计划。

## 调度边界

Studio 只在本机运行并唤醒时触发计划。关闭 Studio 或系统休眠期间错过的触发记为**漏跑**，不会补跑。打开多个 Studio 窗口也不会重复触发。目录、目标版本或信任状态改变后，受影响的触发会被跳过，并在历史中显示原因。

Server 不执行计划。上传项目不会创建计划，独立 CLI 也不启动后台调度。

## 重叠、等待与历史

上次运行还没结束时，本次触发记为 `skipped_overlap`，不会排队或重试。等待审批或输入也算未结束。打开**触发历史 → 打开原运行**，在原运行里继续提交输入。

每个定时 run 会在运行记录、摘要和 report 中保存：

```ts
{
  source: "schedule";
  scheduleId: string;
  scheduleName: string;
  fireId: string;
  scheduledFor: string;
  triggerKind: "window-interval" | "cron";
}
```

宿主的计划页应显示启用状态、规则、时区、版本、入口、下次触发、最近结果、跳过原因，并可立即触发一次和查看 fire 历史。手动立即触发仍遵循同一计划的重叠规则。

计划排队、运行或等待输入时，可以暂停计划，但不能编辑或删除。暂停不取消已启动的运行。编辑后先保存，再确认启用。

## 与 Kanban 联动

计划和触发历史按本地源码目录、`projectId` 和 `entryId` 隔离。内部操作使用 `entrypointId`。
