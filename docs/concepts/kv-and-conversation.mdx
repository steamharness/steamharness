# 数据库 KV 与会话

业务数据必须来自入口声明并获批绑定的数据库 alias。运行历史、工具审批、草稿和会话状态由宿主按 `projectId + entryId` 管理，不能以业务 KV 授权代替运行权限。

## KV 作用域

```ts
const database = context.databases.get("data");
await database.transaction(async db => {
  await db.kv.setValue("settings:theme", "dark");
  await db.knowledge.createDocument({
    id: "guide", title: "Guide", markdown: "# Guide\nShared content",
  });
});
const theme = await database.kv.getValue("settings:theme");
const document = await database.knowledge.getDocument("guide");
```

`database.kv` 访问共享空间键；`database.kv.conversation` 进一步隔离当前项目、入口和 `conversationId`。相同空间的两个项目可以共享顶层 KV，但不能借相同会话 ID 读取彼此的会话 KV。

```ts
await database.kv.conversation.setValue("lastQuery", "example");
await database.kv.updateValue("counter", value => Number(value ?? 0) + 1);
```

`updateValue` 使用宿主 CAS，冲突时重新读取；需要读写权限。`database.transaction` 在同一空间内提供事务，不能把不同空间的更新合并成一次原子提交。知识库保留键必须通过 `database.knowledge` 访问。

## 聚合内调用

```ts
const operations = await context.entries.get("database").listEntrypoints();
const result = await context.entries.get("database")
  .runEntrypoint("search", ["--query", "example"]);
```

调用只针对已注册的 Workflow 入口。宿主保留当前用户、取消信号和工具权限，加载目标入口的配置快照与数据库绑定并再次鉴权。Ask 模式不能通过目标入口获得 Build 权限。

## 最后写入来源

每次写入记录 `projectId`、`entryId`，以及可用的 `runId` 和 `conversationId`。这些来源不会改变空间地址，也不授予额外权限。

## 知识库和附件

`database.knowledge` 提供文档列表、读取、创建、编辑、删除、搜索和行读取；`database.knowledge.files` 提供附件操作。共享空间的文档、附件、索引和修订遵守相同授权。详见 [知识库 API](/core-api/knowledge-documents)。

## Conversation 状态

宿主分别持久化各入口的历史、输入队列、草稿、参数、Token 用量和审批状态。CLI Web 切换窗口保留后台运行；Studio 不同入口标签共享宿主，但拥有独立会话。配置修改从下一次执行生效。恢复时必须同时匹配项目与入口，不能将另一个入口的审批恢复到当前入口。
