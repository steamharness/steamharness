# 项目配置

Workflow、Conversation、Kanban 使用同一套项目配置。Studio 与 CLI Web 从工具栏打开“项目配置”，Server Web 从项目详情的配置页管理。没有声明字段时仍可添加自定义字段。

## 声明字段

项目根目录的 `configuration.json` 只声明结构和安全默认值，实际配置值通过面板管理：

```json
{
  "version": 1,
  "fields": [
    { "name": "API_KEY", "type": "string", "label": "API key", "secret": true, "required": true },
    { "name": "retries", "type": "number", "defaultValue": 2 },
    { "name": "enabled", "type": "boolean", "defaultValue": false },
    { "name": "regions", "type": "string", "multiple": true, "options": [{ "value": "east" }, { "value": "west" }] },
    { "name": "metadata", "type": "json", "defaultValue": { "tags": [] } }
  ]
}
```

字段支持 `string`、有限 `number`、`boolean`、`json` 和 `file`，字符串可用 `options` 声明枚举。可选属性为 `label`、`description`、`defaultValue`、`required`、`secret`、`control`、`options`、`accept`。默认值使用原生 JSON 类型；敏感字段不要写真实默认值。配置字段与执行输入参数是两套结构。

`file` 字段直接选择本机文件并上传到当前连接的 Server，单文件上限 50 MiB，沿用项目文件写入权限。`accept` 可声明 MIME 类型（如 `image/png`、`image/*`）或扩展名（如 `.json`）；不符合要求的文件不会上传。上传成功后显示文件名，保存配置才生效；失败保留原引用。单文件值是服务器元数据对象，包含 `id`、`name`、`mimeType`、`size` 和 `storage: "server"`，不包含本地路径、文件内容或连接凭据。`multiple: true` 对字符串表示字符串数组，对文件表示最多 32 个服务器文件引用。清除字段只移除配置引用，不删除服务器文件。

```json
{ "name": "imageFile", "type": "file", "label": "底图", "accept": ["image/png", "image/jpeg", "image/webp", "image/gif"] }
```

字段名以字母或下划线开头，后续允许字母、数字、下划线、点和连字符，最长 200 字符。字段名必须唯一。用户和小助手可以管理自定义字段，自定义字段结构属于整个项目，各套配置分别保存值。声明字段由 `configuration.json` 管理，自定义字段不能覆盖声明字段。重命名自定义字段会同步所有配置中的键；删除会清除所有配置中的对应值。

## 管理配置

面板顶部切换当前配置，使用加号新建配置，“配置操作”菜单提供复制、重命名和删除。“导入 / 导出”菜单集中处理 JSON 文件，菜单内注明导出包含敏感值。字段区独立提供“添加字段”，自定义字段旁的铅笔和垃圾桶图标用于编辑与删除。底部保存区展示草稿状态，刷新图标用于重新加载并放弃草稿；图标均带操作说明并支持键盘访问。

可以新建、复制、重命名、切换和删除命名配置，始终至少保留一套。字段可以直接编辑，无需先勾选；修改后点击底部“保存”统一生效。字段旁的重置图标清除覆盖值，有声明默认值时立即恢复默认值，没有默认值时清空并取消设置。未修改的字段保留原有状态；布尔值、多选项仍使用各自的勾选控件。缺少必填项可先保存，开始运行时才校验。新增声明字段使用默认值，移除声明字段后不再向运行暴露对应值。

移除声明字段或查看其他源码版本不会删除已保存值；再次声明同名字段时可恢复原值。同名项目声明暂时隐藏已有自定义字段定义，声明移除后恢复自定义定义。运行和导出只包含当前有效字段；显式删除自定义字段仍会清除所有配置中的对应值。

保存使用 `revision` 检查和原子写入。其他窗口或小助手修改配置时，面板更新已提交状态；有草稿时保留输入并提示冲突。刷新并丢弃草稿后再重新编辑；失败请求不会写入部分结果。

Studio、独立 CLI 与 CLI Web 共用本机用户目录下的配置存储，按规范化后的项目真实路径隔离。Server 按项目和登录账号隔离，拥有项目读取权限的账号可以管理自己的配置。个人配置值不直接写入项目源码；启用分享后，仅作者显式允许携带的值进入发布模板。本地与 Server 的配置通过导入导出搬运。

## 导入与导出

导出当前或全部配置，得到版本为 `1`、`kind` 为 `steamharness-project-configurations` 的 JSON 文件，包含字段定义和完整有效值，包括敏感值。文件中的配置包含名称和值，不包含原配置 ID。文件字段导出完整服务器引用，不包含文件二进制；导入后仍需能够访问原服务器和项目中的文件。

导入默认新增配置、重新生成 ID 并保留当前选择。未存在的字段添加为自定义字段；同名字段类型、多选属性、选项或文件类型限制冲突、未知字段值、无效类型、无效 JSON 或超过 1 MiB 的请求会整批拒绝，不留下部分字段或配置。妥善保管含敏感值的导出文件。

## 运行时读取

```ts
const token = steamharness.getConfig<string>("API_KEY");

const task = steamharness.defineProject({
  name: "configured-task",
  async run(input, context) {
    const enabled = context.config.enabled;
    return { errCode: 0, errMessage: "", enabled };
  },
});
```

SDK 提供 `ProjectConfigurationSnapshot`、`context.config` 和 `steamharness.getConfig(key)`。配置快照贯通参数解析器、executor、节点和 Agent，按运行隔离并冻结，不写入全局 `process.env`。运行之外的 `getConfig` 返回 `undefined`。直接使用 SDK 时可以向执行接口传入显式 `configuration` 快照，或通过 `createLocalProjectConfigurationStore(projectDir)` 管理本地配置。

显式快照也按 `runId` 保存，恢复时可省略 `configuration`，仍使用最初保存的值。宿主为保留同一 `runId` 的持久会话更新配置时，传入新的 `configurationRunId`；之后恢复该代配置需继续传入相同的 `configurationRunId`。本地存储的 `snapshot({ runId, configuration })` 同样只在该身份首次使用时保存传入快照。

- Workflow 开始执行时冻结配置；恢复等待任务继续使用原快照。
- Conversation 的下一轮执行使用新配置；持久 Agent 在当前任务、排队输入和审批处理结束后重建运行配置，保留会话历史、分支和恢复状态。
- Kanban 保存后更新主页面与资源卡片预览，HTML 仍通过 `window.steamHarnessKanban.getConfiguration().params` 读取原生值，并监听 `steamharness:kanban-configuration-change`。指定配置 ID 的预览引用该配置；配置删除后显示不可用。

项目业务配置不自动读取 `.env`，不使用 `.env.example`，也不回退到进程环境变量。旧项目 env 和旧 Kanban 配置不迁移。请重新在面板填写配置。Server 部署、CI 和 Studio 内部通信变量继续由宿主管理。

## CLI 与小助手

无界面本地接口使用 JSON 输入输出，和面板共用同一个存储：

```sh
printf '%s' '{"action":"get"}' | steamharness configuration ./my-project
```

小助手通过 Studio Control 的 `get_configurations`、`manage_configurations` 和 `open_configurations` 操作。工具的 `input` 是 JSON 字符串：本地指定 `storage: "local"` 和 `projectDir`；Server 指定 `storage: "server"`、`projectId`、`target`（`draft`、`latest` 或版本）。操作不依赖面板打开。

```json
{
  "storage": "local",
  "projectDir": "/projects/my-project",
  "call": { "action": "save", "revision": 3, "id": "profile-id", "values": { "enabled": true }, "unset": ["API_KEY"] }
}
```

查询返回字段、配置列表、当前 ID 与 `revision`。管理支持 `create`、`duplicate`、`rename`、`save`、`select`、`delete`、`field.save`、`field.delete`、`import`。读取工具的 `export: true` 导出全部，指定 `id` 导出当前配置。所有写操作必须传查询到的 revision；配置值操作显式指定 id。只读模式拒绝管理操作，目录与项目范围沿用 Studio 现有权限策略。冲突时保留拟修改内容，重新查询并协调后重试。

Server API 使用 `GET /api/projects/:id/configurations?target=draft` 读取，`POST /api/projects/:id/configurations` 提交 `{ "target": "draft", "call": { ... } }`。成功返回统一 `errCode: 0` 包装，版本冲突返回 HTTP 409 和 `data.code: "CONFIGURATION_CONFLICT"`。配置 API 只保存静态结构和值，Server 不执行项目。

## 分享配置与权限（v2）

配置值、发布模板和个人覆盖值相互独立。作者在“发布与权限”中选择配置集与默认配置，分别设置 `publish`（发布字段）、`includeValue`（携带值）、`editable`（允许接收者修改）。未设置的规则默认是发布字段、允许修改、不携带值；`defaultValue` 也按值过滤。v1 项目保持原行为，保存发布草稿后才启用分享过滤，不会自动发布历史个人值。

```json
{
  "version": 2,
  "fields": [
    { "name": "privateToken", "type": "string", "secret": true, "sharing": { "publish": false } },
    { "name": "userToken", "type": "string", "secret": true },
    { "name": "endpoint", "type": "string", "defaultValue": "https://api.example.com", "sharing": { "includeValue": true, "editable": false } },
    { "name": "preferences", "type": "json", "defaultValue": { "region": "default", "theme": "auto" }, "sharing": { "includeValue": true }, "paths": { "/region": { "editable": false } } }
  ]
}
```

JSON 对象的路径使用 JSON Pointer：`/` 编码为 `~1`，`~` 编码为 `~0`。未声明的路径继承父规则，更具体的规则优先；整个字段不发布时，所有子字段都排除。数组作为整体编辑。面板提供子字段编辑及原始 JSON 编辑，服务端按实际变化检查所有路径；替换父对象、清空值、导入及小助手操作均不能绕过锁定。违规批次整体拒绝，返回 `CONFIGURATION_FORBIDDEN`（HTTP 403）。必填且只读的字段没有可发布值时不能发布。

发布前可查看接收者预览。保存草稿会冻结所选配置的值；修改个人值后，需要显式“更新发布值”并重新保存草稿。发布接口同时校验源码摘要和发布草稿版本，并在临时目录生成过滤后的 `configuration.json`、`configuration.template.json` 和 `configuration-assets/`，不改写作者目录。已发布模板与版本固定；源码下载、分享链接和 Store 分发该版本的同一份内容。完整备份仍包含全部可读取值，不能用完整备份代替分享模板。

只有原项目实际所有者或具有现有管理权限的管理员可以保存官方草稿、发布官方模板。普通 manager、下载或复制项目、请求中的角色参数都不能获得原项目所有权。下载用户管理自己的命名配置及自定义字段，不能修改作者字段定义、权限或模板；运行时合并模板与允许的个人值。个人配置只保存实际覆盖值，未修改的初始值随模板升级；仍可编辑的个人修改和自定义字段继续保留，新锁定路径停止应用旧覆盖值。类型冲突保留草稿并提示处理。运行中的 Workflow 和等待恢复任务继续使用原快照。

附件发布时复制为不可变副本，只携带保留字段引用的文件。下载会验证源码和附件摘要，把已验证模板与附件缓存到源码之外；离线可使用已验证版本并修改获准的个人值，官方草稿修改、发布和新版本下载需要联网。重新选择文件必须上传成功才能保存。下载权限仅授予相应模板和附件，不授予原项目其他数据的访问权限。

### 发布接口与小助手

- `GET /api/projects/:id/configurations` 返回个人配置、`fieldCapabilities` 与锁定原因；作者还会收到 `publication` 和当前 `sourceHash`。
- `POST /api/projects/:id/configurations` 支持 `publication.save`（`revision` 加 `publication`，草稿包含自身 `revision`、字段、配置集和 `defaultConfigurationId`）和 `publication.preview`。草稿版本冲突返回 HTTP 409。
- `GET /api/projects/:id/configurations/template?target=1.0.0` 只读取已发布模板。
- `POST /api/projects/:id/configurations/files?key=background&fileName=map.png&mimeType=image/png` 上传个人配置附件；`GET /api/projects/:id/configurations/files/:fileId?target=1.0.0` 只读取授权附件。
- 发布 `POST /api/projects/:id/publish` 时携带 `expectedSourceHash`、`expectedVersion` 和 `expectedConfigurationRevision`；后者是发布草稿版本。

Studio Control 的 `get_configurations` 会返回权限，`preview: true` 返回接收者预览；`manage_configurations` 支持 `publication.save`。这些操作不依赖面板打开，官方修改必须连接原项目的 Server 并联网；只读模式拒绝所有写入。

分发模板不会包含被排除的字段或子路径名称；生成的不可读规则摘要保留同名冲突与隐藏路径覆盖检查。这些摘要不替代源码下载的身份和完整性验证。
