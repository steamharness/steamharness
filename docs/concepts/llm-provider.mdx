# LLM Provider

LLM Provider 把模型调用接入工作流。项目可以配置自己的服务地址、模型与 API Key，Server 不保存或代理这些第三方凭据。

## 系统 AI 目录

通过 `getServerLLMCredentials({ signal })` 取得当前账号可用目录。目录按服务地址和账号在进程内复用 30 秒，并合并并发刷新。

| 情况 | 行为 |
| --- | --- |
| 需要最新目录 | 传入 `{ fresh: true, signal }` 在线刷新 |
| 代理凭据临近过期 | 在线刷新凭据 |
| 账号或服务地址变化 | 重新加载相应目录 |
| 一次等待被取消 | 其他运行共享的刷新继续 |

目录和短期 token 只留在内存。每次模型请求仍由 Server 检查权限。

## 创建 provider ref

推荐在 workflow 中创建 provider ref，让节点运行时读取配置：

```ts
const llmProvider = steamharness.createLLMProviderRef("default", () => {
  return steamharness.createLLMProviderFromConfig();
});
```

节点运行时才解析 provider，避免业务代码在模块加载阶段读取业务配置。

## LLM 节点

非流式节点：

```ts
const llmNode = steamharness.createLLMNode<Input>({
  name: "answer-llm",
  provider: llmProvider,
  mapInput(input) {
    return {
      system: "你是一个简洁助手。",
      prompt: input.message,
      maxOutputTokens: 300,
    };
  },
});
```

流式节点使用同一个 provider：

```ts
const llmStreamNode = steamharness.createLLMStreamNode<Input>({
  name: "answer-stream",
  provider: llmProvider,
  mapInput(input) {
    return { messages: [{ role: "user", content: input.message }] };
  },
});
```

## 项目配置字段

先在 `configuration.json` 声明模型字段，再到项目配置面板填写实际值。`steamharness.createLLMProviderFromConfig()` 读取以下字段：

- `LLM_TYPE`
- `LLM_API_KEY`
- `LLM_BASE_URL`
- `LLM_MODEL`

运行时使用该次执行的冻结快照，不回退读取 `.env` 或进程变量。`LLM_BASE_URL` 必须为 HTTP(S) 地址，不能含用户名、密码、查询参数或片段。

项目业务值来自[项目配置](/concepts/project-configuration)，不加载项目 env，也不回退读取进程变量。宿主部署和通信配置由宿主单独管理。

## Provider 类型与错误

provider factory 支持的类型来自 `LLM_PROVIDER_TYPES`。未配置模型时，会按 provider 类型选择默认模型；测试时可以使用 mock provider。

provider 调用失败会被包装为 workflow 错误并进入执行报告。模型不支持的可选参数可能产生 compatibility warning；鉴权失败、模型不可用和上游请求失败仍然会直接失败。
