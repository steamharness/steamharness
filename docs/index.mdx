# 开始使用 SteamHarness

用 SteamHarness 编写 Agent 项目，在 Studio 或 CLI 中运行，再通过 Server 管理源码、版本和协作权限。

第一次使用，先跟随[快速开始](/guides/quickstart)运行一个 Hello 工作流。已有项目可以直接[在 Studio 中打开](/guides/studio/create-import)。

## 三种项目类型

| 你要做什么 | 入口类型 | 从这里开始 |
| --- | --- | --- |
| 把输入、模型、工具和条件串成一项任务 | Workflow | [编写工作流](/guides/development/workflow) |
| 创建能持续接收消息的助手 | Conversation | [编写对话项目](/guides/development/conversation) |
| 展示看板、地图或可交互的数据页面 | Kanban | [编写看板](/guides/development/kanban) |

一个项目可以包含多种入口，共享项目 ID 和版本。运行时选择入口，各入口分别保存配置、草稿和会话状态。

### Workflow

用 TypeScript 声明输入、节点和执行顺序，适合数据处理、内容生成和多步骤自动化。需要分支或循环时，使用 [Workflow 模型](/concepts/workflow-model)中的控制结构。

### Conversation

围绕消息和轮次组织任务，适合持续对话的助手。它使用同一套运行时，通过会话执行器接收输入；历史管理见[数据库与会话](/concepts/database-and-conversation)。

### Kanban

用 HTML、CSS 和 JavaScript 编写页面，以 `index.html` 为入口。需要读取项目数据时，通过受限 Bridge 访问已绑定、已授权的关系库或知识库。

## 项目在哪里运行

| 入口 | 用途 |
| --- | --- |
| Studio | 编辑源码、运行本地项目、查看结果和执行轨迹 |
| 本地 CLI | 在终端运行、检查结构、输出 JSON 或提供 MCP 工具 |
| Server | 保存源码、版本、成员、数据库、知识库和文件 |
| Server Web 管理端 | 在浏览器中管理 Server 上的项目与资源 |
| Store | 浏览、下载和发布项目版本 |

项目代码在 Studio 或本地 CLI 所在的机器执行。Server 接收源码归档，不替项目安装依赖或运行代码。Kanban 的服务器预览是受权限约束的静态页面。

## 项目数据与配置

业务关系库、知识库和运行历史分别管理。关系库使用 `databases` 声明别名，由 Server 按账号、项目和入口维护绑定；知识库使用 `knowledgeBases` 声明。

配置与会话按 `projectId + entryId` 隔离，修改配置从下一次运行生效。继续阅读[项目配置](/concepts/project-configuration)和[数据存储](/concepts/data-storage)。

## 账号、权限与协作

| 角色 | 主要能力 |
| --- | --- |
| `guest` | 查看和下载已发布项目，在本地运行 |
| `developer` | 编辑草稿、上传、发布，以及修改获授权的数据 |
| `maintainer` | 管理项目信息、官方配置及访客、开发者 |
| `owner` | 管理所有角色、项目归属和删除操作 |

组支持多级子组，有效角色取项目直接角色和组继承角色的最高值。项目访问权与数据资源授权分别检查，详见[项目管理](/guides/server/project-management)。

## AI 能力

开源版可在 Studio 中添加自定义模型，也可在项目中配置 LLM Provider。接入方式见[模型设置](/guides/studio/models)和 [LLM Provider](/concepts/llm-provider)。

增强版提供账号可用的系统模型、供应方偏好、订阅和用量，见[系统 AI 指南](https://docs.steamharness.yuhe.space/enhanced/ai/overview)。

## 开发流程

1. [创建项目](/guides/studio/create-import)，选择模板并等待依赖安装完成。
2. 编写入口，检查根 `steamharness.json` 中的 `entries` 和 `defaultEntry`。
3. [本地运行](/guides/studio/run-debug)，核对结果与执行轨迹。
4. [上传并发布版本](/guides/studio/versions)，再按需要设置成员权限。
5. 需要公开分发时，[发布到 Store](https://docs.steamharness.yuhe.space/enhanced/store/publishing)。

## 项目结构

根 `steamharness.json` 记录项目身份、版本和入口列表。Workflow、Conversation 入口指向执行器源码，Kanban 入口指向构建后的 HTML。普通依赖由 `package.json` 和锁文件管理。

具体声明见[Workflow 模型](/concepts/workflow-model)。迁移旧项目时，先阅读 [Core 0.2 迁移指南](/guides/migrate-core-0-2)。

## 内置项目

开发者小助手用于代码和开发任务，Studio Control 提供受权限控制的编辑器操作，Studio Analysis 汇总本地运行。Codex、Conversation、OpenCode 和 Pi 等内置项目的版本记录见[发布日志](/guides/releases/overview)。

## 版本、测试与部署

项目应固定兼容的 Core 与 CLI 依赖版本。升级前检查[版本兼容性](/guides/releases/compatibility)，开发过程中运行[项目测试与结构检查](/guides/testing)。服务部署步骤见[部署 Server](/guides/server/deployment)。

## 选择你的下一步

运行第一个项目，从[快速开始](/guides/quickstart)进入；编写业务逻辑，阅读[开发工作流](/guides/development/workflow)；管理已有项目，打开 [Server Web 指南](/guides/server/overview)。
