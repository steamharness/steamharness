# Knowledge Documents

用 `context.knowledgeBases.get(alias)` 访问 Server 管理的知识库。文档、索引和附件元数据按知识库 ID 隔离，附件内容放在私有文件存储；使用知识库无需定义业务 schema，也不会为每个项目新建物理数据库。

## 申请与绑定

先登录 `steamharness workspace login`，再创建资源并绑定入口：

```sh
steamharness knowledge create "Project docs"
steamharness knowledge bind . --entry main --alias docs --knowledge-base <UUID>
steamharness knowledge bindings . --entry main
```

绑定命令维护 Server 上的账号、项目、入口及别名绑定，并在项目声明中加入 `"knowledgeBases": ["docs"]`、在根 `config.json` 中保存 `"knowledgeBases": {"docs": "<UUID>"}`。`STEAMHARNESS_PROJECT_CONFIG` 可按知识别名覆盖 ID。配置不含凭据，也不授予访问权。参见 [项目数据存储](/concepts/data-storage)。

## 文档与并发修改

```ts
const knowledge = context.knowledgeBases.get("docs");
const created = await knowledge.createDocument({
  id: "guide", title: "Guide", markdown: "# Guide\nHello 世界",
});
const current = await knowledge.getDocument(created.id);
if (current) {
  await knowledge.editDocument({
    id: current.id, markdown: "# Updated guide", expectedRevision: current.revision,
  });
}
const page = await knowledge.listDocuments({ pageSize: 20 });
if (page.nextCursor) {
  const next = await knowledge.listDocuments({ pageSize: 20, cursor: page.nextCursor });
}
const matches = await knowledge.searchDocuments({ query: "世界", pageSize: 20 });
const lines = await knowledge.readDocumentLines({ documentId: "guide", startLine: 1, endLine: 10 });
```

### 返回结果与分页

| 结果 | 内容 |
| --- | --- |
| 文档 | `id`、`title`、`markdown`、`revision`、`createdAt`、`updatedAt` |
| 列表 | 摘要、`total`、`hasMore` 和可选 `nextCursor`，按最近写入排序 |
| 搜索 | 忽略大小写的字面子串匹配，支持中文，保留从 1 开始的行号与上下文 |

将不透明游标原样传回。搜索游标绑定查询参数和资源修订号；文档或附件变化后重新搜索。文档与分块索引在同一 SQL 事务内提交。

编辑时传入读到的 `expectedRevision`；删除使用 `deleteDocument(id, expectedRevision)`。版本不符返回冲突并保留调用方草稿，应重新读取后由用户处理。省略该参数表示直接修改当前版本。删除不存在的文档返回 `{ id, deleted: false }`；带过期版本的删除返回冲突。

### 大小与数量限制

| 内容 | 限制 |
| --- | --- |
| 标题 | 512 字符 |
| Markdown 正文 | 4 MiB 字符 |
| ID | 256 字符，不含 NUL |
| 列表分页 | 每页 1–100 项 |
| 搜索分页及最大匹配数 | 上限 1000 |
| 搜索上下文 | 前后各最多 100 行 |
| 按行读取 | 每次最多 1000 行 |

`getRevision()` 返回资源修订号，宿主可据此决定是否刷新。

## 附件

```ts
const image = await knowledge.files.createFile({ name: "image.png", mimeType: "image/png", buffer });
const resolved = await knowledge.files.readFile(image.id);
const bytes = await resolved.readBuffer();
await knowledge.files.deleteFile(image.id);
```

单文件最多 50 MiB。引用保留 `storage: "database"` 和 `spaceId`（知识库 UUID）。HTTP 传输使用 Base64，SQL 只保存元数据和校验和，正文写入私有文件存储；上传与删除意图持久化，失败上传及删除对象由后台回收。读取会校验大小和 SHA-256。

`readFile()` 下载一次，保留句柄后调用 `readBuffer()`、`readBase64()` 等会复用内容，但每次重新检查当前绑定和读取授权；撤权后旧句柄也不可继续使用。配置附件和项目托管文件使用各自的读取权限，不能互换接口。

同一 Server 知识库宿主对重复附件下载保留最多 32 MiB Base64 内容的内存缓存，按账号、消费入口、绑定版本和文件隔离；命中时先在线读取附件元数据验证权限与存在性。写入、撤权、读取失败或账号切换会使缓存失效，不提供离线授权或异步写入确认。可变知识正文、列表与搜索保持在线读取。项目托管文件在服务器支持 ETag 或 Last-Modified 时使用条件请求，并在每次读取时验证权限。

## 授权与失败

知识库所有者管理账号 `read` / `write` 授权。绑定权限不能超过账号授权，已注册项目还检查项目成员权限和入口资源声明。授权、绑定或访问版本变化后，旧客户端拒绝继续操作，应重新打开入口。账号管理密钥不能代替账号身份。

持久访问需要 Server 和 PostgreSQL 可达；可全部部署在本机，无需互联网。未登录、缺少声明、未绑定、撤权、存储故障都会明确失败，不会切到本地 KV。跨知识库、业务库与系统存储不提供联合事务。
