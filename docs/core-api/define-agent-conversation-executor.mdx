# defineAgentConversationExecutor

`workflow.defineAgentConversationExecutor()` 为宿主嵌入或测试一次构造完整的 Conversation Agent executor。项目入口继续使用内联 `workflow.defineExecutor({...})`，声明 `conversation`、`tokenUsage` 和 `tools`；其 `workflow` 来自 `workflow.createAgentConversationProject(...)` 时，Core 自动补全内置参数与 resolver。

这层封装让嵌入方无需实现流式循环、审批、压缩或输出项拼装。项目也可复用其中的工作流与输入实现，同时保留可被宿主读取的内联声明。


权限菜单包含 `read-only`、`workspace` 和 `auto`。Core 项目默认与小助手一致：权限使用 `userSetting: { key: "agent.permissionPolicy", mode: "fixed" }` 跟随用户设置；无宿主时用户设置为 `auto`。显式 `permissionPolicy` 提供项目默认值；使用 `paramOptions.fields.permissionPolicy` 可定制绑定、隐藏或固定实际值。见[用户设置与权限继承](/core-api/user-settings)。

## 签名

```ts
workflow.defineAgentConversationExecutor(options?: AgentProjectOptions):
  ConversationExecutorDefinition<AgentInput, AgentOutputPayload>
```

返回值已经由 Core 校验，可以供嵌入方使用；把它传给项目入口的 `defineExecutor` 仍不能让静态结构分析看到内部字段。

## 选项

`session` 可启用 [持久会话控制](./create-agent.mdx#持久会话控制)。便捷 executor 自动声明 `conversation.durable: { enabled: true }`，默认权限列表增加 `update_plan` 和启用时的 `subagent`。自定义 `toolDefinitions` 时须自行包含这些声明。静态内联项目须声明 durable 并传 session；选定 Core Agent 项目时 recovery 自动继承；例如 `session: { subagents: { tools: ["read", "grep", "find", "ls"], maxAgents: 4 }, planFork: "asOf" }`。子 Agent 工具只收紧父权限，后台结果自动单次回传。CLI Web / Studio 保持执行 owner 存活，在四个侧栏视图展示任务、计划、记录和用量。

除 [createAgentNode](./create-agent-node.mdx) 的全部选项外：

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `projectName` | `string` | — | 项目展示名。 |
| `executorName` | `string` | `agent` | workflow 名，也是节点名前缀（`<name>-input`、`<name>-output`、`<name>-agent`）。 |
| `collapseIntermediate` | `boolean` | `true` | 结束后默认收起中间过程，成功保留最终回复，失败保留错误原因；写入 `conversation.collapseIntermediate`；用户可通过每轮消息的按钮展开或收起。 |
| `outputItemId` | `string` | `agent-answer` | 助手正文回答的 item id，同时写入 `conversation.openai.outputItemId`。正文 item 用的就是这个值本身，因此适配器按 id 查找时一定能找到它。 |
| `params` | `ConversationParamDeclaration[]` | 见下 | 完整替换默认参数表，支持 Auxiliary、Quick、Mode 和 Slash。 |
| `paramOptions` | `AgentProjectParamOptions` | — | 按内置字段名调整默认值、绑定、显隐、固定值与分组。 |

## 生成的 executor

| 部分 | 内容 |
| --- | --- |
| `projectType` | `"conversation"` |
| `conversation` | 标准主输入框始终启用；`inputQueue.enabled`、`recovery.enabled`、`openai.outputItemId` |
| `tokenUsage` | 启用并展示 |
| `tools` | `read`、`write`、`edit`、`bash`、`grep`、`find`、`ls` |
| `params` | `provider`, `model`, `effort`, `plan`, `permissionPolicy` |
| `workflow` | 输入节点解析 → agent 节点流式执行 → 输出节点落 conversation |

Effort 默认 `high`，`/plan` 默认关闭。模型默认或 `modelSource: "user-settings"` 在 Studio 中仅使用设置模型并隐藏项目 AI 配置；独立 CLI Web 自动退化为项目模型。`modelSource: "project"` 在所有宿主中仅使用项目配置，保留系统 AI／第三方 AI 两种添加来源。Provider 是兼容用的隐藏字段。

自动 resolver 根据模型来源生成选项，隐藏 `provider`，并应用隐藏及固定值策略；只为有效参数返回补丁。`model` 保存配置条目 ID，执行时解析实际连接。显式 `executor.params` 完整替换参数表；显式 `resolveParams` 保留自定义处理，隐藏与固定值规则仍由 Core 应用。模型配置见[项目配置](/concepts/project-configuration)。

## 输入与输出

输入使用 [createAgent](./create-agent.mdx) 的 `AgentInput`。`createAgentProjectInput(context, options?)` 接受带 `args` 与 `paramValues` 的 `ExecutorContext`，解析消息、附件与有效参数，自动把 `plan` 映射为 `agent`。原有 `createAgentProjectInput(args, options?)` 仍可用于程序化调用及高级参数。

输出是 `AgentOutputPayload`，同时把本轮的用户消息和助手回答写入 conversation，因此宿主的历史列表、标题和导出都按普通 conversation 运行处理。

两点例外：只调用了工具、没有任何正文的一轮不写空的助手消息；带 `hostInput` 的一轮（OpenAI / Responses 网关）完全不写 conversation，因为网关自己保管这段历史——与内置 Conversation 项目的处理一致。

**多轮上下文和未完成任务由 Pi Durable 保存。** Core 按项目、会话和 `sessionKey` 选择 SQLite 文件，按提交保存消息、工具意图与结果、审批等待和用量身份。相同 `runId` 恢复同一请求；已完成请求只重建自身的输出。旧 KV transcript 不再读取，存储失败终止运行。多个 Agent 节点须使用不同 `sessionKey`；`hostInput` 网关运行默认使用内存存储。详见 [createAgentNode](./create-agent-node.mdx)。

`defineExecutor` 选定 `createAgentConversationProject` 作为 `workflow` 或 `coreAgent` 时，运行时与静态结构报告都会自动继承 `conversation.recovery: { enabled: true }`，并保留项目自己的对话展示配置。CLI Web / Studio 强退重启后使用原 `runId` 恢复未完成任务；恢复失败时保留待发队列，只有一轮成功后才自动继续。

> **正文 item 的 id 必须与 `conversation.openai.outputItemId` 一致。** OpenAI / Responses 适配器是在 `report.outputs[].output.items` 里**按 id 查找**这段正文的：CLI 本地网关与 `__openai-responses-runner` 都走这条查找，两者不一致时运行会以「did not produce output item」失败。

这个条目只在**宿主驱动的运行**里产出（适配器按 id 读回的就是整轮完整文本）。普通会话运行把正文写成 `partType: "text"` 的行——两条活动行之间的每段文字各占一行，写在它被说出的位置——再把它们拼回会话消息。

## 示例

宿主嵌入或测试中的用法：

```ts
const agentExecutor = workflow.defineAgentConversationExecutor({
  projectName: "Pi",
  executorName: "pi",
  outputItemId: "pi-answer",
  provider: "anthropic",
  effort: "high",
});
```


## 项目参数继承与定制

Context 输入只消费当前参数表中启用的字段；固定用户设置绑定不接受宿主参数值覆盖。旧的 `-m` 与 `--agent plan|build` 参数在继承入口中继续可用，显式 `--plan` 优先于旧模式参数；消息和附件的值不作为参数解析。字段定制中的 `undefined` 等同于省略，使用 `userSetting: null` 清除绑定。静态继承支持 `workflow` / `coreAgent` 简写属性与 SDK 命名空间导入。

直接绑定 Core workflow 的 executor 可省略 `params`、`resolveParams`。若业务 workflow 包装了 Core，在 executor 中设置 `coreAgent: agentProject`，保留原来的业务 workflow 和 `createInput`。参数选项必须能静态读取；结构分析只读取选定引用，不执行项目代码。

`fields` 支持 `defaultValue`、`userSetting`（`null` 清除绑定）、`visible`、`fixedValue`、`label`、`description` 和 `options`。设为 `false` 移除字段；`groups` 用字段名重排 Quick/Auxiliary 分组，未分配字段保留原分组。`fixedValue` 覆盖绑定及默认值，并在输入构造和 Core 执行入口强制应用。隐藏只控制展示，需要禁止覆盖时同时使用 `fixedValue`。显式默认值会清除用户设置绑定。

```ts
const agentProject = workflow.createAgentConversationProject({
  modelSource: "project",
  paramOptions: {
    fields: {
      effort: { defaultValue: "medium" },
      plan: false,
      permissionPolicy: { visible: false, fixedValue: "auto" },
    },
    groups: [{ kind: "quick", id: "ai", label: "AI",
      fields: ["provider", "model", "effort"], summary: ["model", "effort"] }],
  },
});

export const executor = workflow.defineExecutor({
  projectType: "conversation",
  workflow: agentProject,
  createInput(context) { return workflow.createAgentProjectInput(context); },
});
```


## 技能目录与宿主预览

`createAgentConversationProject({ skills: { directories: ["skills"] } })` 使用同一声明驱动技能工具与宿主目录。路径相对于当前入口根目录解析，也可使用绝对路径；多个根目录中的同名技能以第一个为准。Core 自动注册 `skill` 工具并沿用当前工具权限，项目仍在内联 `executor.tools` 中声明其权限元数据，不要再在 `createTools` 中重复创建该工具。`createAgentNode` 也接受同一选项供运行时使用；宿主目录只读取选定 `createAgentConversationProject` 的声明，包装 Conversation 时通过 `coreAgent` 显式关联。

宿主通过 `listLocalProjectSkills({ projectDir, entryId?, entrypointId? })` 获取 `AgentSkillGuide[]`：每项包含 `id`、`name`、完整 `description` 与 `source: "project" | "builtin"`。列表包含选定 Core Agent 的项目指南及其默认加载的 Core 内置指南；同名的两种来源保留独立 ID。通过 `readLocalProjectSkill({ projectDir, entryId?, entrypointId?, skillId })` 获取 `{ skill, content }`，`content` 为完整原始 `SKILL.md`，不受模型工具分页限制。两个 API 都只读取目录，不调用工具工厂、不运行任务；非 Core Agent 入口返回空目录。预览只接受已发现的目录 ID，不接受文件路径，并拒绝越界软链接。
