# Agent 服务端存储

`steamharness/runtime-storage` 提供 `createServerAgentStorage`，把 Agent 的持久记录保存到 Server 的 PostgreSQL。Agent 仍在 CLI、Studio 或自己的 Node.js 进程执行；Server 只鉴权并读写数据，不接收可执行的项目代码。

## 连接与重开

```ts
import { createAgent } from "steamharness/agent";
import { createServerAgentStorage } from "steamharness/runtime-storage";

const agent = await createAgent({
  workdir: process.cwd(),
  storage: createServerAgentStorage({
    serverUrl: "http://127.0.0.1:18126",
    token: () => readAccountToken(),
    workspace: {
      kind: "local",
      projectId: "2e22c651-788b-4f26-b652-10a0c16154b7",
      entryId: "main",
      localKey: "host-owned-folder-id",
    },
    sessionKey: "host-owned-conversation-id",
  }),
});
```

`readAccountToken()` 由宿主实现，返回当前账号的 Server Bearer token；不要把它写进项目源码、连接 URL 或模型输入。Server 的管理员密钥不能代替账号身份。`storage` 与 `databasePath` 互斥。模型、工具及会话控制仍按 [createAgent](/core-api/create-agent) 配置。

| 参数 | 说明 |
| --- | --- |
| `serverUrl` | HTTP(S) Server 基址，不含账号密码、query 或 fragment。 |
| `token` | 账号 token 字符串，或同步/异步取 token 的函数。每次请求重新取值。 |
| `workspace` | 下表中的工作区定义，或已登记的 `{ id: workspaceId }`。 |
| `sessionKey` | 宿主持久保存的对话身份，同一工作区重开时必须复用。 |
| `requestTimeoutMs` | 单次 HTTP 超时，默认 10 秒。 |
| `retryDelayMs` | 暂态失败的退避基数，默认 100 毫秒，最多重试两次。 |
| `fetch` | 可选 HTTP transport，默认使用 Node.js `fetch`。 |

| `workspace.kind` | 必填字段与权限 |
| --- | --- |
| `project` | `projectId`、`entryId`。必须有真实项目的读取权限，且入口存在；每次操作重新校验。 |
| `local` | `projectId`、`entryId`、`localKey`。允许尚未发布的本地项目，数据归当前账号私有。 |
| `assistant` | 同 `local`，用于宿主的小助手工作区。 |

项目 ID 必须是 UUID；入口 ID 使用小写字母开头的字母、数字、`_`、`-`，最多 64 字符。`localKey` 和 `sessionKey` 为 1–512 字符的稳定身份，不含 NUL。`localKey` 由宿主管理，可保存文件夹的稳定 ID，不能作为项目授权凭据。

同账号、工作区类型、项目、入口和本地身份定位同一工作区；工作区加 `sessionKey` 定位同一会话。不同账号、入口、本地文件夹及会话隔离。系统管理员不会因此获得其他账号的私有历史。重开时恢复已提交的对话、任务、输入回执、分叉关系及文档检查点，不自动迁移本地 SQLite 或旧 KV。

## 所有权、重试与失败

每个会话同一时间只有一个执行 owner。Server 默认发放 30 秒租约，客户端约每 10 秒续租；正常关闭先等待在途存储请求，再释放租约。进程异常退出后，租约过期即可接管。接管提升 fence，旧 owner 的请求被拒绝。

提交和 ID 分配使用稳定请求 ID；响应丢失后重试返回原结果，避免重复写入及 ID 重用。网络、超时、HTTP 429/502/503/504 有界重试，401/403 直接失败。续租失败后停止接受后续存储操作；不会切换到本地或内存后端。存储请求的幂等性不保证外部工具副作用只执行一次，工具的恢复仍遵守 `replay` 与审批策略。

`RuntimeStorageError.code` 区分 `RUNTIME_STORAGE_OWNER_CONFLICT`、`RUNTIME_STORAGE_LEASE_LOST`、`RUNTIME_STORAGE_IDEMPOTENCY_CONFLICT`、`RUNTIME_STORAGE_ACCESS_DENIED`、`RUNTIME_STORAGE_NOT_FOUND` 和 `RUNTIME_STORAGE_UNAVAILABLE`。无效操作使用 `AgentStorageRequestError`。

## 数据与备份

Server 在现有平台数据库的 `steamharness_runtime` schema 内维护版本迁移和专用关系表：工作区、会话、对话、条目、任务、输入、文档版本与幂等回执。创建工作区不会创建新的 PostgreSQL database。记录身份、状态与检索条件使用独立列和索引；不透明 JSON 载荷使用文本保存，以完整保留合法 JSON 的特殊键及 Unicode。

备份包含整个 PostgreSQL 数据库，并按项目需要备份附件和工作区文件。SQLite 专用的导入、导出、离线分叉和离线取消工具不适用于此后端；在线会话控制仍通过活动 owner 执行。

CLI/Studio 默认后端保持现有行为，使用此入口需显式注入 `storage`。本入口用于平台 Agent 记录；项目自定义关系表和 Prisma schema 不是该 API 的功能。

本地调试见[部署与发布](/guides/server/deployment)，HTTP 协议见 [OpenAPI](/openapi/steamharness.openapi.yaml)。
