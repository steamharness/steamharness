# defineExecutor

`steamharness.defineExecutor()` 声明 Workflow 的操作目录和默认操作。Agent 项目使用 [defineBot](/core-api/define-bot)，由 Core 提供执行流程、输入解析和输出。

## 示例

```ts
export const executor = steamharness.defineExecutor<Input, Output>({
  projectType: "workflow",
  defaultEntrypoint: "main",
  entrypoints: [
    steamharness.defineEntrypoint<Input, Output>({
      id: "main",
      title: "完整流程",
      workflow: exampleProject,
      tokenUsage: { enabled: true, display: true },
      tools: [
        {
          name: "search",
          label: "Search",
          description: "调用外部搜索工具。",
          enabled: true,
          autoApprove: false,
        },
      ],
      params: [
        {
          name: "message",
          flag: "--message",
          type: "string",
          required: true,
          control: "textarea",
          description: "输入文本。",
        },
      ],
      createInput({ args }) {
        return { message: readMessage(args) };
      },
    }),
  ],
});
```

## 签名

```ts
steamharness.defineExecutor<Input, Output>(
  definition: ProjectExecutorDefinition,
): ProjectExecutorDefinition
```

## 参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `definition` | `ProjectExecutorDefinition` | 平台发现和执行 workflow 的入口配置。 |

## Workflow executor

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `projectType` | `"workflow"` | Workflow 项目的类型标记。必填。 |
| `defaultEntrypoint` | `string` | 省略入口选择时使用的入口 ID。必须是静态字符串并命中 `entrypoints`。 |
| `entrypoints` | `EntrypointDefinition[]` | 非空静态入口数组；每项必须直接调用 [`steamharness.defineEntrypoint()`](/core-api/define-entrypoint)。 |

Workflow 的 `workflow`、`params`、`createInput`、`resolveParams`、`createContext`、`requiredProviders`、`tools`、`tokenUsage` 和 `registry` 全部属于具体 entrypoint，不能放在 executor 顶层。入口按声明顺序展示；选择任一入口会直接创建该入口的 run，不会先执行默认入口。

Workflow 可以在 `steamharness.json.entries[].schedulePresets` 中声明建议计划。每项静态引用一个 entrypoint，并包含 IANA 时区、时间窗口或五字段 Cron，以及默认参数值。该目录会进入 Structure 报告，但宿主必须显示确认界面，不能因导入或发布项目自动创建计划。Bot 和 Kanban 声明此字段会被 Structure 拒绝。完整格式与运行边界参见 [Workflow 定时运行](/concepts/workflow-schedules)。

## Bot executor

Bot 使用 [defineBot](/core-api/define-bot)。Core 固定提供项目类型、`AgentOutputPayload`、`agent-answer`、持久队列、恢复和用量。通过 `agent` 配置策略，使用 `prepareInput` 准备业务输入，使用 `onCompleted` 保存回执。

Bot 不声明 Workflow 的 `entrypoints`。聚合项目通过 `--entry` 选择 Bot；`--entrypoint` 仅用于 Workflow。

## `ExecutorContext`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `projectName` | `string` | 当前 workflow 名称。 |
| `projectDir` | `string` | 当前 workflow 目录。 |
| `entrypointId` | `string \| undefined` | Workflow 当前所选入口 ID；Bot 为 `undefined`。 |
| `entrypointTitle` | `string \| undefined` | Workflow 当前所选入口标题；Bot 为 `undefined`。 |
| `args` | `string[]` | 原始 CLI 风格参数。 |
| `paramValues` | `Record<string, string \| string[]>` | 按 `params` 解析后的结构化值。单值保持字符串，多选为字符串数组。 |
| `env` | `NodeJS.ProcessEnv` | 环境变量集合。 |
| `abortSignal` | `AbortSignal` | 中断信号；本地宿主取消运行时会传递到 workflow 和支持 signal 的 SDK/provider 调用。 |
| `conversationId` | `string \| undefined` | 会话 ID。 |
| `toolPermissionPolicies` | `ToolPermissionPolicyMap \| undefined` | 宿主传入的工具策略覆盖值。workflow 通常不直接读取该字段，而是使用 `context.toolPermissions` 或 `steamharness.createToolApprovalGate()`。 |

| 字段 | 类型 | 说明 |

## 执行流程

| 阶段 | 说明 |
| --- | --- |
| 平台选择配置 | Workflow 按显式 ID 或 `defaultEntrypoint` 选择一个入口；Bot 使用 executor 本身。 |
| 创建上下文 | runtime 根据 args、env、projectName、入口和 conversationId 创建 `ExecutorContext`。 |
| `createInput` | 调用所选 Workflow 操作的输入构造；Bot 输入由 Core 解析。 |
| `createContext` | 调用所选 Workflow 操作的可选上下文扩展。 |
| workflow `run` | 执行所选 Workflow 操作；Bot 执行 Core Agent。 |

## 工具权限

`tools` 用于注册 workflow 业务工具的默认权限。每个工具包含稳定 `name`，以及可选 `label`、`description`、`enabled` 和 `autoApprove`。`enabled` 默认 `true`，`autoApprove` 默认 `false`。CLI Web 可以在运行前缓存用户选择并传入覆盖值；runtime 只接受已注册工具的 `enabled/autoApprove` 覆盖，未知工具会被忽略。

workflow 代码可以使用 [`steamharness.createToolApprovalGate()`](/core-api/create-tool-approval-gate) 包装工具函数。工具未注册时会以 `input_validation` 失败；工具被禁用时会以 `tool_permission_denied` 拒绝；工具启用但未自动批准时，会复用 `steamharness.createUserInputNode(...)` 的等待/恢复协议生成 `tool-approval` 请求，批准后继续同一个 run，拒绝后返回 `tool_permission_denied`。

## 注意事项

| 规则 | 说明 |
| --- | --- |
| `createInput` 是必填 | 每个 Workflow entrypoint 必须声明；Bot 由 Core 提供。 |
| `paramValues` 是正式结构化值 | `createInput` 可直接读取参数值；`args` 继续用于需要完整 CLI 参数或未知参数的场景。 |
| Workflow 运行配置属于 entrypoint | 顶层旧字段会给出迁移错误，不再保留兼容别名。 |
| `tools` 必须静态声明 | CLI Web 只能展示所选入口或 Bot executor 静态分析到的工具；工具名必须稳定。 |
| `tokenUsage.enabled` 默认关闭 | 未配置时不会写数据库，也不会展示用量。关闭时 `context.tokenUsage.report()` 是 no-op。 |
| `registry` 用于单节点调试 | Workflow 只搜索所选入口的 registry；没有注册的节点不能通过 debug API 单独运行。 |
