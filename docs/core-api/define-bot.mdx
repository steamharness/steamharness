title: "defineBot"
description: "声明使用 Core Agent 或 LLM 的 Bot 入口，并设置工具权限。"
---

用 `steamharness.defineBot()` 声明 Bot，入口在 `steamharness.json` 中注册为 `type: "bot"`。声明必须包含 `engine`；原有 Bot 加上 `engine: "agent"`，其余配置不变。

会话内不能切换引擎。修改项目的 `engine` 后，重新打开项目，从新会话开始聊天；旧会话仍可查看。

| 引擎 | 适用场景 | 引擎专属配置 |
| --- | --- | --- |
| `"agent"` | 执行多步任务，或使用计划、记忆与持久恢复。 | `agent`、`memory` |
| `"llm"` | 根据当前会话回答，必要时调用工具，无需启动 Agent。 | `llm`（必填，不需要选项时传 `{}`） |

两种引擎都支持 `name`、`params`、`resolveParams`、`conversation`、`tools`、`prepareInput` 和 `onCompleted`，返回 `BotExecutorDefinition`。输出类型为 `AgentOutputPayload`，最终正文项固定为 `agent-answer`。不能覆盖 `workflow`、`coreAgent`、`createInput`、`tokenUsage` 或 `outputItemId`。

## LLM Bot

```ts
export const executor = steamharness.defineBot({
  engine: "llm",
  llm: { systemPrompt: "你是项目助手。" },
});
export default executor;
```

LLM Bot 把当前会话已完成的问答和本轮输入交给模型，流式返回答案。OpenAI Responses 入口只使用请求提供的历史。LLM Bot 支持文本、图片、排队和停止，不启动 Agent，也不使用 Plan、子 Agent、项目记忆或内置联网搜索。

模型不调用工具时，每轮只请求一次。模型需要工具时，Core 校验参数和权限，将工具结果发回同一个模型继续作答。答复的用量包含本轮所有模型请求；工具的调用和返回不会带入下一轮。

`runLocalProjectWithReport({ nodeHooks: { onLLMBotModelRequest } })` 在每次模型请求发起时提供 `LLMBotModelRequestSnapshot`。快照包括供应商、模型、协议、系统提示词、消息、工具声明和已发送的生成参数；图片只保留类型。Core 不把快照写入普通运行报告或事件。快照可能包含私密对话和工具结果，只应提供给有访问权限的调试视图。

| `llm` 字段 | 类型 | 用途 |
| --- | --- | --- |
| `systemPrompt` | `string` | 各轮共用的系统提示词。 |
| `modelSource` | `"user-settings"` 或 `"project"` | 控制从宿主设置还是项目配置选模型。 |
| `model` | `string` | 默认模型条目 ID；省略时使用配置中的默认模型。 |
| `temperature` | `number` | 可选的非负采样温度，端点须支持。 |
| `maxOutputTokens` | `number` | 可选的输出 token 上限，须为正整数。 |
| `createTools` | 返回 `AgentTool[]` 或 `AgentToolSet` 的函数，可异步 | 创建本轮的项目工具，接收 `context` 和 `prepareInput` 处理后的输入。若返回 `close()`，Core 在本轮结束时调用。 |

答复完整返回后，Core 先按 `requestId` 保存问答，再调用 `onCompleted`。回调报错时，重试只重放已保存的答复并补跑回调。模型流中断时，Core 不保存半截答复，也不自动重发。手动重试前，先确认本轮工具是否已产生副作用。

### 在 LLM Bot 中使用工具

在 Studio 或 CLI Web 打开 **项目信息 → 工具**，设置每个工具是否启用、是否自动批准。只有 `runtime_info` 默认启用并自动批准。问「这个 Bot 运行在哪？Core 是什么版本？」可以查看 SteamHarness 的执行宿主、实际版本、系统和项目入口；工具不返回本机绝对路径、凭据或模型服务器位置。

读写、检索、等待和 Shell 工具默认关闭。普通读写工具只访问当前入口目录；`bot_files_*` 访问下文所述的 Bot 文件目录。`bash` 以执行进程的权限运行，不受目录沙箱限制。要添加项目工具，在顶层 `tools` 声明名称和默认权限，再用 `llm.createTools` 返回同名实现。结构检查只读取声明，不执行工具工厂。

模型端点须支持工具调用。本地 Bot 的有效权限为「自动批准」时，已启用的工具直接执行，无需逐个设置。其他模式按工具设置决定是否确认；批准后继续当前轮次，拒绝则结束本轮。OpenAI Responses 入口等非交互宿主仍只能执行已自动批准的工具。端点不支持工具时，设置 `tools: [{ name: "runtime_info", enabled: false }]`，并保持其他工具关闭。

## Agent Bot

`agent` 保留 Core 的模型来源、提示词、技能、权限、工具与 session 配置。Model、Effort、Plan、权限参数自动继承；用 `agent.paramOptions` 定制默认值、分组、显隐和固定值，顶层 `params` 仅追加业务字段，不覆盖保留字段。固定参数在输入钩子后仍生效。

`agent.createTools(context, input)` 和 `agent.createSession(context, input)` 接收准备后的输入。Agent Bot 支持 durable 和 recovery；通过 `conversation.recovery.startup` 选择 `"automatic"` 或 `"manual"`。两种引擎都可通过 `conversation` 定制展示、命令及输入交互。

`prepareInput(input, context)` 在 Core 解析文本和图片后运行，返回扩展的 `AgentInput`。它可读取 `context.config`、`args`、`paramValues` 和取消信号。`onCompleted({ requestId, output }, context)` 接收成功结果的只读快照，必须返回 `void`。业务回执应按 `requestId` 幂等保存。

```ts
export const executor = steamharness.defineBot({
  engine: "agent",
  name: "assistant",
  agent: { systemPrompt: "你是项目助手。" },
  async prepareInput(input, context) {
    return { ...input, systemPrompt: String(context.config.instructions ?? "你是项目助手。") };
  },
});
export default executor;
```

两种引擎共用[模型与凭据配置](/concepts/project-configuration)。默认使用 Studio 用户设置，独立 CLI Web 使用项目模型配置；设 `modelSource: "project"` 时只使用项目模型。系统 AI 与第三方模型都遵循项目的来源限制，鉴权失败不会自动换模型。本地运行可省略项目 `id`；发行构建才校验项目 UUID。

本地 Bot 的有效权限为「自动批准」时，所有已启用的工具直接执行，已禁用的工具仍不可用。这个设置不会修改各工具保存的权限。

在其他权限模式下，工具沿用 Core 的 Plan/Build 审批规则。需要在 Build 中也逐次确认的操作，可声明 `tools[].approvalMode: "always"` 与 `autoApprove: false`；允许免确认的查询可设 `autoApprove: true`。

在 Studio 或 CLI Web 中，Bot 等待工具审批时，你可以先读它在调用工具前写出的文字。此时选择**停止**会取消这次审批。工具不会执行，之前的消息仍留在同一对话里。

## 项目记忆

Agent Bot 默认开启项目记忆，同一项目、同一 Bot 入口的会话共享记忆。不同项目和不同入口分别保存；每条记忆再用 `category` 和 `key` 定位，适合把项目事实、决策和操作流程分开存储。

在项目的“项目配置”中打开当前使用的配置，切换“Bot 记忆”并保存，后续新执行使用该设置。已保存的运行快照继续使用原配置。关闭记忆会移除该次执行的记忆工具与操作提示词，保留已有条目；重新开启后可以继续读取。

`memory.enabled` 定义开关的初始默认值，省略时为 `true`。已保存的项目配置优先于源码默认值。以下声明让新配置默认关闭记忆，用户仍可在界面开启：

```ts
export const executor = steamharness.defineBot({
  engine: "agent",
  memory: { enabled: false },
  agent: { systemPrompt: "你是项目助手。" },
});
```

开关对应配置键 `STEAMHARNESS_BOT_MEMORY_ENABLED`，值为布尔值，通常无需在 `configuration.json` 中声明。显式声明时必须使用 `boolean` 类型；省略 `defaultValue` 时，继承该入口实际导出的 Bot 的 `memory.enabled`。其它 Bot 声明不会改变这个默认值。

Core 自动提供以下工具，可与 `agent.extraTools` 和 `agent.createTools` 提供的业务工具同时使用。两处若声明与记忆工具同名的工具，执行时会报错：

| 工具 | 参数与结果 |
| --- | --- |
| `memory_save` | 传 `category`、`key`，以及 `content`、`title`、`summary`、`properties` 中至少一项有效内容。返回稳定的 `id` 和 `revision`；不会覆盖同分类、同键的条目。 |
| `memory_get` | 用 `id` 或 `category` 加 `key` 读取单条记忆，可加 `relations: "outgoing"` 或 `"incoming"`。不存在时返回 `memory: null`。传 `category`、`query` 或 `where` 可列出摘要；无筛选时只列分类。 |
| `memory_search` | 传 `keywords`，可加 `category`、`where`、`match`、`limit` 和 `offset`。在分类、键、标题、简述和正文中匹配关键词，按命中词数和相关性排序。 |
| `memory_update` | 用 `id` 或 `category` 加 `key` 指定条目，传 `expectedRevision` 和要修改的字段。仅更新传入的字段，并返回新版本号。 |
| `memory_delete` | 用 `id` 或 `category` 加 `key` 指定条目，传 `expectedRevision`。有其他记忆引用时拒绝删除；成功删除时一并移除出向引用，保留被引用的条目。 |
| `memory_link` / `memory_unlink` | 传 `sourceId`、`targetId`、`relation`（如 `depends_on`）和来源条目的 `expectedRevision`。建立或移除一条有向引用，返回来源条目的新版本号。 |

### 结构化记忆与引用

把会独立变化的对象存为单条记忆。例如，发布中心的条目存 `title` 和 `properties: { status: "live" }`，部署流程和发布说明各自引用它的 `id`。改名或更新状态时，只改发布中心这条；再次展开引用就能读到新值。已写入其他条目的正文不会随之改写，可用于保留带日期的历史事实。

`properties` 是一个 JSON 对象，每条记忆序列化后最多 4,000 个字符。更新时按顶层键替换对应值，其他键保留；用 `removeProperties` 删除指定键。`null` 可以作为属性值存储，也可用于清空 `title`、`summary` 或 `content`。`where` 对所有指定的顶层键做精确匹配，支持字符串、数字、布尔值或 `null`；缺少的键不匹配 `null`。

`memory_get` 的 `outgoing` 列出这条记忆引用的对象，`incoming` 列出哪些记忆引用了它。结果只展开一层，包含关联记录最近保存的属性，不读取关联记录的正文。默认最多 5 条，每页最多 10 条，有后续页时读取 `nextOffset`。如需删除仍被引用的条目，先检查入向引用，再解除需要移除的关系。

每轮开始时，Core 从当前输入提取关键词，在调用模型前检索相关记忆；同一轮后续模型请求会刷新结果，避免继续使用已修改或删除的摘要。追加消息、中途补充要求和恢复执行也会使用当前输入检索。只有搜索工具已启用且允许自动审批时，才进行后台检索；不会为此弹出确认。小助手打开多个根目录，或 Bot 分身可按子目录分库时，由 Bot 选定项目目录后主动检索，不自动注入默认库的摘要。

`memory_search` 默认返回最多 5 条，`limit` 最大为 10；正文摘录最多 240 个字符，优先截取命中位置附近的正文，整个搜索结果最多 6,000 个字符。关键词最多 12 个，每个最多 80 个字符，合计最多 500 个字符。`any`（默认）匹配任一关键词，`all` 要求全部匹配；关键词按字面匹配，支持中文。

搜索结果包含 `id`、分类、键、版本和命中关键词，以及已填写的标题和简述。需要全文时再用 `memory_get` 读取，单条正文最多 8,000 个字符。有后续页时用 `nextOffset` 作为下一次的 `offset`；优先缩小关键词范围，不遍历所有记忆。

`memory_get` 的分类和摘要列表支持 `limit`（默认 10，最多 20）与 `offset`。`query` 按空白分词，最多 12 个词且必须全部匹配；正文摘录取前 240 个字符。

修改、删除或操作引用前，先读取要修改的条目的 `revision`，作为 `expectedRevision` 传入。遇到版本冲突，重新读取后再决定如何修改。工具遵守宿主权限与审批，Plan 和只读模式只提供 `memory_get` 与 `memory_search`。

Core 内置提示词要求 Bot 静默维护记忆：发现已确认、对未来有用的项目事实、决策、流程或偏好后，自动判断是否保存，无需用户先说“记住”。新事实先查重，变化时更新，确认失效或要求忘记时删除；不例行询问或在回复中播报记忆操作。

保存什么由模型根据对话判断，不是逐条复制消息。记忆只作为参考数据，不得覆盖当前指令；凭据、完整聊天记录、临时进度、猜测和用户明确要求不保留的信息不应存入记忆。

服务的部署位置、运行状态或配置可能改变。内置提示要求 Bot 把记忆当作查证线索，回答现状前用获准的只读工具核对目标环境，并以实际查到的结果为准。没有权限或没查证成功时，只能把记忆中的说法标为「上次记录，当前未核实」；不会因此放宽权限。

记忆保存在执行宿主的本地 SQLite 中。旧库会在首次访问时升级，保留已有条目和原有的 `category`、`key` 调用方式。记忆跨该宿主的会话和重启保留，不提供账号级记忆或跨机器同步；不同运行数据目录、开发模式与发行模式分别保存。会话导出、复制或删除不会复制或删除项目记忆，项目发行包也不包含记忆正文。

### 按项目目录使用记忆

Studio 小助手可以在同一会话里使用多个已打开的工作区根目录。从目录 A 选择 B，与直接以 B 启动小助手，读写的是同一份 B 的记忆。

分身的记忆库不与本体或其他分身共享。如果一个绑定目录里有多个子项目，分身还可以按子项目所在目录分开保存。

支持目录选择的本地运行时会为所有 `memory_*` 工具提供可选的 `projectPath`。传入目标目录的绝对路径；对同一条记忆的检索、读取、编辑和引用都应指定同一个目录。省略时使用原有的默认库；无效目录会报错，不会回退。已有记忆不迁移，记忆 ID 和结构化引用不能跨库使用。

### 在 Studio 管理记忆

在本地 Studio 中打开 Agent Bot 的 **项目详情 → Bot 管理 → 记忆管理**。先确认面板顶部显示的是本体还是目标分身。可以按关键词、分类或精确属性筛选，例如 `{"status":"live"}`。打开一条记忆，可查看正文、属性、出向引用和反向引用，也可以编辑或解除引用。

在小助手的对话工具中打开 **记忆管理**，可从已打开的根目录中切换。分身可在同一面板输入绑定目录内的子项目绝对路径，选择 **切换记忆目录**。切换只影响面板的读写，不改变当前对话或 Bot 的工作目录。

从支持此功能的运行时开始，面板编辑和 Bot 写入都会记录操作者、差异和版本。Bot 的变更还会记录可用的运行及对话来源。旧条目照常显示，但不会补造升级前的变更记录。

编辑和引用变更的旧值保留 30 天。只有条目仍处于那次改动产生的版本，才可撤销；撤销会产生一个新版本。若另一个窗口或 Bot 已改过该条目，先刷新再处理冲突。

仍被引用的条目不能忘记。先查看反向引用，再按需解除关系。确认 **忘记记忆** 会删除该条目及库中可恢复的旧值，不会删除其他记忆、原对话或外部备份。Bot 的 `memory_delete` 同样不保留可恢复旧值。

## Bot 凭据库

在本地 Studio 的 **项目详情 → Bot 管理 → 凭据管理**，可以核对所选 Bot 入口或分身的凭据别名和类型，不用先打开对话。

在本地 Studio 的 Bot 对话中，打开 **项目信息 → 概览**，在 **Bot 管理** 中选择 **凭据管理**，可添加、替换或删除凭据。API Key、令牌和密码在原生窗口中遮罩录入；SSH 私钥通过文件选择器导入本地 OpenSSH 或 PEM 私钥文件。

两个入口都不能查看、复制或导出已保存的原值。如果忘记密码或丢失密钥、令牌，先在来源服务重置或取得新值，再用 **替换凭据** 更新 Studio 中的条目。不要把新值发到对话中。

Agent Bot 可以调用 `bot_credentials_request`，传 `name`（别名）和 `kind`（`api-key`、`password`、`ssh-private-key` 或 `structured`）。在对话卡上选择 **打开安全输入**，在 Studio 原生窗口录入凭据。同名同类型条目已存在时，不会再次要求录入，也不会自动覆盖。

多个值需要一起保存时，选 **结构化凭据**（`structured`）。`fields` 只用于生成输入示例，实际键名不必与示例一致。提交的内容原样保存，不要求是 JSON；单个字符也可以保存。每条凭据最多 64 KiB。

保存回执包含别名、类型、状态和脱敏结构。JSON 对象最多显示 16 个可安全展示的顶层字段名及值类型，保留键名大小写，不显示值或嵌套内容。没有字段可描述的内容只显示「已隐藏」。

Bot 可按实际键名调整调用映射。调用需要的字段缺失或格式不适用时，工具返回错误，不会发送凭据。若确需重新录入，Bot 可以先征得你的同意，再用 `replace: true` 请求替换原条目。取消不会改动原值。

凭据保存在受操作系统保护的 Studio 存储中，与记忆、对话、项目目录和产物库分开。本体与各个分身独立。凭据原值不会随模板、项目或对话导出；没有可用的系统保护存储时，Studio 会拒绝保存。

凭据工具需要支持安全输入的本地 Studio Agent Bot。Plan 和配对 Web 不提供凭据工具；后台对话只有在本机宿主明确授权时才能使用。项目代码可使用 [凭据输入节点](./create-user-input-node.mdx#bot-凭据输入) 获取保存状态。

### 使用已保存的凭据

`saved` 只表示凭据已保存，不表示查询成功。更新 Studio 和项目运行时后，在原来的 Bot、分身或小助手工作目录中使用凭据别名即可，不用重新录入。

告诉 Bot 要做的事和凭据别名，例如「用已保存的凭据列出对象存储桶」。工作区模式在 Studio 原生窗口确认，自动批准模式直接运行。读取别名、使用凭据和返回结果都不会在聊天里插入凭据卡；只有录入新凭据需要安全输入卡。

Bot 将 `name`、`connector: "host"`、`operation` 和 `args` 交给 `bot_credentials_use`。不确定别名或类型时，先用 `vault.list` 核对；它只列出当前 Bot 已保存条目的别名和类型，不读原值。

### 给本地命令临时传入凭据

用 `command.run` 启动已安装的 CLI，或运行使用本地 SDK 的脚本。`env` 的键是客户端读取的环境变量名，值是已保存的字段名。以下示例将同一条结构化凭据的两个字段交给客户端：

```json
{
  "name": "storage-account",
  "connector": "host",
  "operation": "command.run",
  "args": {
    "kind": "structured",
    "program": "storage-cli",
    "argv": ["list"],
    "env": { "CLIENT_ID": "clientId", "CLIENT_SECRET": "clientSecret" }
  }
}
```

`storage-cli` 和变量名是示例，实际使用时按客户端的要求填写。单值凭据用 `{"CLIENT_TOKEN": true}`，`true` 表示绑定整个值。旧格式 AccessKey 对选 `kind: "access-key-pair"`，映射 `AccessKeyId`、`AccessKeySecret`，不需要重新录入。原有 DNS 专用操作已移除，DNS 和对象存储都通过各自的客户端使用同一个别名。

每次执行只向该子进程注入指定的值，不写入命令参数、Studio 全局环境或聊天。下次执行重新读取凭据；找不到相应程序时，需先准备客户端，不能靠重新录入凭据解决。只使用可信程序，Studio 无法约束程序如何处理收到的值。

| 操作 | 可以使用的凭据 | 参数和限制 |
| --- | --- | --- |
| `vault.list` | 不读取凭据 | 省略 `name`，传 `args: {}`；可用 `query` 按别名过滤。 |
| `https.get-json` | API Key、令牌、密码、结构化凭据和旧格式 AccessKey 对 | 用 Bearer、Basic 或自定义鉴权头发起 HTTPS GET。传 `url` 和 `auth`；结构化值只传字段映射。不跟随重定向，不支持写入请求。 |
| `ssh.authenticate`、`ssh.list-directory` | SSH 私钥；加密私钥可引用同范围内的密码别名 | 传 `host`、`username`、可信的服务端 `fingerprint` 和可选 `port`（默认 22）。目录读取另传 `path`。不启动远程 Shell。 |
| `command.run` | 同范围内已保存的凭据 | 仅对启用命令工具的受信任本地会话开放。用 `program`、`argv` 和 `env` 调用本地客户端，不启动 Shell，也不在 IM 后台执行。 |

凭据查询遵守 **设置 → 权限 → Agent 权限**。如果 Bot 本轮权限更严格，则按更严格的一项执行：

- **只读**：不提供凭据工具，即使已有对话授权。
- **工作区**：列出别名不弹窗。使用凭据时，在 Studio 原生窗口核对命令或目标。宿主查询可选「本次对话允许」，同一请求以后无需再确认；命令按次授权。
- **自动批准**：符合权限范围的操作直接执行，包括使用临时变量的命令。录入新凭据仍需你提供值。

工作区模式的对话授权只留在本地运行内存，不随对话导出。新建或分叉对话、更换凭据或字段映射、重启 Studio 后，需要重新确认。使用临时变量需要同时更新 Studio 和项目运行时。

## Bot 文件目录

Bot 可以把草稿、下载的工作副本和中间产物放在 `temp/YYYY-MM-DD/`，把报告等交付件放在 `artifacts/YYYY-MM-DD/`。日期按执行宿主的本地时间计算，目录在第一次写入或使用本地 Shell 时创建。项目源文件仍在原工作区，用户指定了其他输出位置时遵守原有权限。

文件放在本地运行数据的 `bot-files` 区域，不随项目发布，也不会自动变成对话附件。同一个 Bot 实例的会话共享目录；Studio 的项目本体和各分身使用不同的运行数据目录。现有文件不会搬迁，临时文件也不会按日期自动删除。

Agent Bot 默认提供以下工具，和记忆开关无关。LLM Bot 可以在 **项目信息 → 工具** 或顶层 `tools` 中启用所需工具；默认仍关闭。不提供 Bot 本地文件存储的宿主不会执行这些工具。

| 工具 | 用法 |
| --- | --- |
| `bot_files_list` | 不传 `path` 时返回目录位置和今天的两个相对路径；传 `temp` 或 `artifacts` 查看日期目录，也可列出具体子目录。用 `nextOffset` 翻页。 |
| `bot_files_read` | 用 `path` 分页读取 UTF-8 文本，用 `nextByteOffset` 继续。 |
| `bot_files_write` | 传 `path` 和 `text` 创建文件，按需建立父目录。UTF-8 正文限 128 KiB；只有 `overwrite: true` 才能覆盖。 |
| `bot_files_move` | 传 `path` 和 `destination` 移动或重命名单个文件，支持二进制文件，不覆盖目标。 |
| `bot_files_delete` | 用 `path` 删除一个文件，不递归删除目录。 |

除列出根目录或日期列表外，路径形如 `temp/YYYY-MM-DD/draft.md`。文件工具不接受绝对路径、上级路径或指向其他文件的链接。Plan 和只读模式下只提供列目录和读取，所有工具继续遵守宿主权限与审批。

本地 Agent Bot 的默认工作目录是 `~/.steamharness/accounts/<账号键>/projects/<项目ID>/`，不是加载 Bot 代码的源码目录。没有项目账号时，账号键为 `local`。例如，未指定 `workdir` 时，用 `bash` 创建的 `plan.md` 就在项目 ID 目录下。显式指定工作目录或绑定文件夹时使用所选目录；`prepareInput` 的 `input.workdir` 和运行结果的 `workdir` 都是绝对路径。

传 `directory: "temp"` 或 `"artifacts"` 可让单条 `bash` 命令在当天的对应目录执行。子进程的 `TMPDIR`、`TMP` 和 `TEMP` 指向当天的 `temp`，两个绝对路径也通过 `STEAMHARNESS_BOT_TEMP_DIR` 和 `STEAMHARNESS_BOT_ARTIFACT_DIR` 提供。不会读取这些变量的程序仍需显式指定输出路径。

Bot 的内置说明会指引它把中间文件和成品分开放置，并在任务结束时给出用户要求的成品路径。可以直接说：「把分析过程的临时文件放进你的临时目录，最终报告放到产物目录，告诉我保存位置。」

### 交付文件和产物库

在 Studio 本地对话里，请 Bot 交付完成的文件。Agent Bot 会调用 `bot_files_publish`，传入 `artifacts/YYYY-MM-DD/` 下的相对文件路径 `path` 和可选的 `title`。单个文件最多 50 MiB。工具仅在支持的本地会话中提供，遵守工具审批；LLM Bot 需单独启用。Plan、只读、配对 Web 和 IM 会话不提供交付工具。

交付会在聊天里显示文件卡片。也可以打开 **项目详情 → Bot 管理 → 产物库**，找回同一个本体或分身在其他对话交付的文件。常见文本和图片可直接预览，其他文件可下载。未交付的文件和 `temp/` 不会被收录。

交付保存的是当时的内容。之后覆盖源文件或删除原对话，不会改变快照；删除对话后只不能跳回来源。用户确认移除交付件后，旧卡片会提示已移除，源文件仍保留。

## 技能目录与宿主预览

在 `agent.skills.directories` 中列出技能目录。相对路径按当前入口根目录解析；多个目录包含同名技能时，采用第一个。

Core 自动提供 `skill` 工具，项目可通过 `tools` 调整其权限。宿主预览只读取配置声明，不执行输入钩子或工具工厂。

```ts
export const executor = steamharness.defineBot({
  engine: "agent",
  agent: { skills: { directories: ["skills"] } },
});
```
