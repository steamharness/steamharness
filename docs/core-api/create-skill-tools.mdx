# createSkillTools

`workflow.createSkillTools()` 返回一个 `skill` 工具，模型用它列出有哪些技能、再读需要的那一份。

技能的正文往往几万字符，而大多数轮次用不上，所以注入系统提示词会在每一轮花掉这份预算却什么也不换；让模型自己按需读取，它还能顺着技能里的指引去读引用文件。

## 签名

```ts
const tools: AgentTool[] = await workflow.createSkillTools({
  directories: string[],
  approve?: (toolId: string, args: unknown) => Promise<void>,
});
```

## 选项

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `directories` | `string[]` | 查找技能的根目录，按优先级排序。先出现的目录里的同名技能胜出，所以项目自带的副本会压过随宿主一起发布的那份。 |
| `approve` | `(toolId, args) => Promise<void>` | 每次调用前询问；抛错即阻止这次调用，抛 `user_input_required` 则暂停本轮。 |

## 技能是什么

一个技能就是一个含 `SKILL.md` 的目录。名字与描述取 `SKILL.md` frontmatter 里的 `name` 与 `description`；没有 frontmatter 时用目录名，没有 `SKILL.md` 的目录不是技能。根目录不存在只是「这个根里没有技能」，不是错误。

## 工具动作

| 动作 | 说明 |
| --- | --- |
| `list` | 列出每个技能的名字、描述和文件清单（清单最多 60 条）。 |
| `read` | 读技能里的一个文件；`path` 省略时读 `SKILL.md`。 |

`path` 只能落在该技能目录内：`..` 越界、绝对路径和指向目录外的软链接都会被拒绝，不存在的文件会点名说是哪一个。单个文件超过 200 000 字符会被截断并在结果里标注。

审批恢复时用 `workflow.runSkillAction(directories, args)` 按同样的动作重跑。

## 示例

```ts
const approval = workflow.createToolApprovalGate();

const node = workflow.createAgentNode({
  provider: "anthropic",
  async createTools(context) {
    return workflow.createSkillTools({
      directories: [path.join(import.meta.dirname, "skills")],
      approve: (toolId, args) => approval.approve({ name: toolId, arguments: args }, context),
    });
  },
});
```
