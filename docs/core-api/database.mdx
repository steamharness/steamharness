# SteamHarness Database

`steamharness/database` 提供项目数据库的定义与类型。模型使用 Prisma schema 语法，公开文件名统一为 `steamharness.database.ts` 与 `steamharness.schema`；项目无需手写 `PrismaClient`、datasource 或 generator。

## 定义单库与多库

在使用数据库的项目目录创建 `steamharness.database.ts`：

```ts
import { defineDatabases } from "steamharness/database";

export default defineDatabases({
  main: { schema: "./database/main/steamharness.schema" },
  audit: { schema: "./database/audit/steamharness.schema" },
  archive: { schema: "./database/main/steamharness.schema" },
});
```

单库可以使用 `defineDatabase({ schema: "./database/main/steamharness.schema" })`，默认别名为 `main`。别名使用小写字母开头的字母、数字或下划线，最多 63 字符，不能使用保留词或 `databases`。路径相对于定义文件，使用 `/`，不能越出项目目录或经过符号链接。

别名只标识本地声明，不包含资源 ID、连接地址或授权。多个别名可以复用同一模型文件，此时复用生成代码，仍保留各自的描述符。不同项目或入口中的 `main` 不会因此成为同一资源。

模型文件只定义模型、枚举、关系及约束。例如 `database/main/steamharness.schema`：

```prisma
model User {
  id    String @id @default(uuid())
  email String @unique
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  authorId String
  author   User   @relation(fields: [authorId], references: [id])

  @@unique([authorId, title])
}
```

`audit` 可以独立定义另一张 `User`，例如 `id Int`、`actor String`、`event String`。类型按别名模块分别导出，字段不会混用。当前生成目标固定为 PostgreSQL，校验与生成使用锁定的 Prisma 7.10.1；不接受自定义 datasource 或 generator。`Transaction` 模型名与封装的 `transaction` 方法冲突，需要另选模型名。

## 校验与生成

```sh
pnpm exec steamharness database init .
pnpm exec steamharness database validate .
pnpm exec steamharness database generate .
```

`database` 可简写为 `db`。`init` 创建单库模板，不覆盖已有定义；为 `package.json` 添加 `database:generate`，为已有 `dev`、`build` 脚本添加生成前置步骤，并将生成目录加入 `.gitignore`。已经手写定义的项目直接执行 `validate`、`generate`。

命令在本地执行定义文件，使用 WASM 校验模型，不连接数据库。schema 错误指向用户模型文件及行号。生成期间任意模型失败，保留上一份完整产物；重新生成会清理已移除别名的产物。并发生成会明确报错；进程被强制终止遗留的 `database.lock` 可在确认没有生成进程后移除。

## 使用生成类型

生成目录为 `.steamharness/generated/database`：

| 路径 | 内容 |
| --- | --- |
| `node/index.js`、`node/index.ts` | Node 描述符与别名索引，客户端实现按需加载。 |
| `browser/index.js`、`browser/index.ts` | Browser 描述符，不包含 Node 驱动、连接配置或客户端构造器。 |
| `node/<alias>`、`browser/<alias>` | 该库的 `Client`、模型、查询输入类型和枚举。 |
| `metadata/`、`schemas/`、`engines/` | 模型元数据、内部标准 schema、生成实现与必要运行资产。 |
| `manifest.json` | 定义及模型指纹、产物文件清单和 SHA-256。 |

源码类型检查可以解析同目录的 `.ts`；运行时使用同名 `.js`，无需 TypeScript loader。用户只维护定义与模型文件，不编辑或提交生成目录。

```ts
import type { DatabaseClient } from "steamharness/database";
import { main, audit } from "./.steamharness/generated/database/node/index.js";
import type { User } from "./.steamharness/generated/database/node/main.js";

function listUsers(db: DatabaseClient<typeof main>) {
  return db.user.findMany({
    select: { email: true, posts: { select: { title: true } } },
  });
}

function listAudit(db: DatabaseClient<typeof audit>) {
  return db.user.findMany({ where: { event: "login" } });
}
```

模型也可通过 `Models.User`、`UserModel` 引用，枚举可通过 `Enums.Status` 引用，避免与封装类型同名。关系过滤、`select`、`include`、复合唯一键及返回值沿用底层模型类型推断。`Client` 只暴露模型操作和 `transaction(callback)` 的类型，生命周期、原始 SQL 与扩展接口不属于业务客户端。`Decimal`、`DbNull`、`JsonNull`、`AnyNull` 可从 `steamharness/database` 或对应别名模块导入。Browser 使用同样的模型类型，从 `browser/index.js` 引入描述符。

描述符包含 `alias`、`target`、`provider`、`schemaHash`、`metadata`，不建立连接。此入口目前提供定义、校验、类型与生成产物；资源申请、物理数据库绑定、迁移和查询执行没有接入。

## 构建与分发

自定义构建应先执行 `database generate`，再运行 TypeScript 或前端构建。`workspace pack` 会为聚合根目录和各注册入口目录中的定义自动生成产物，并将源码、模型与完整生成目录一起打包。`.gitignore` 仅控制 Git；不要在 `.steamharnessignore` 中排除这些必需文件。

Server 只读取静态清单、源文件指纹及产物哈希，不执行项目定义文件。下载时同样检查清单和哈希，失败不留下半份项目。只有 `.steamharness/generated/database` 可以进入源码包，其余 `.steamharness` 运行数据继续排除。

本入口与 [Agent 服务端存储](/core-api/runtime-storage) 分别定义业务模型和平台 Agent 记录，不会自动替换现有 KV 或 Agent 默认存储。
