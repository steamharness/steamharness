# SteamHarness Database

`steamharness/database` 提供项目数据库的定义与类型。模型使用 Prisma schema 语法，公开文件名统一为 `steamharness.database.ts` 与 `steamharness.schema`；项目无需手写 `PrismaClient`、datasource 或 generator。

## 定义单库与多库

在使用数据库的项目目录创建 `steamharness.database.ts`：

```ts
import { defineDatabases } from "steamharness/database";

export default defineDatabases({
  main: { schema: "./database/main/steamharness.schema" },
  audit: { schema: "./database/audit/steamharness.schema" },
  archive: { schema: "./database/main/steamharness.schema" },
});
```

单库可以使用 `defineDatabase({ schema: "./database/main/steamharness.schema" })`，默认别名为 `main`。别名使用小写字母开头的字母、数字或下划线，最多 63 字符，不能使用保留词或 `databases`。路径相对于定义文件，使用 `/`，不能越出项目目录或经过符号链接。

别名只标识本地声明，不包含资源 ID、连接地址或授权。多个别名可以复用同一模型文件，此时复用生成代码，仍保留各自的描述符。不同项目或入口中的 `main` 不会因此成为同一资源。

模型文件只定义模型、枚举、关系及约束。例如 `database/main/steamharness.schema`：

```prisma
model User {
  id    String @id @default(uuid())
  email String @unique
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  authorId String
  author   User   @relation(fields: [authorId], references: [id])

  @@unique([authorId, title])
}
```

`audit` 可以独立定义另一张 `User`，例如 `id Int`、`actor String`、`event String`。类型按别名模块分别导出，字段不会混用。当前生成目标固定为 PostgreSQL，校验与生成使用锁定的 Prisma 7.10.1；不接受自定义 datasource 或 generator。`Transaction` 模型名与封装的 `transaction` 方法冲突，需要另选模型名。

## 校验与生成

```sh
pnpm exec steamharness database init .
pnpm exec steamharness database validate .
pnpm exec steamharness database generate .
```

`database` 可简写为 `db`。`init` 创建单库模板，不覆盖已有定义；为 `package.json` 添加 `database:generate`，为已有 `dev`、`build` 脚本添加生成前置步骤，并将生成目录加入 `.gitignore`。已经手写定义的项目直接执行 `validate`、`generate`。

命令在本地执行定义文件，使用 WASM 校验模型，不连接数据库。schema 错误指向用户模型文件及行号。生成期间任意模型失败，保留上一份完整产物；重新生成会清理已移除别名的产物。并发生成会明确报错；进程被强制终止遗留的 `database.lock` 可在确认没有生成进程后移除。

## 使用生成类型

生成目录为 `.steamharness/generated/database`：

| 路径 | 内容 |
| --- | --- |
| `node/index.js`、`node/index.ts` | Node 描述符与别名索引，客户端实现按需加载。 |
| `browser/index.js`、`browser/index.ts` | Browser 描述符，不包含 Node 驱动、连接配置或客户端构造器。 |
| `node/<alias>`、`browser/<alias>` | 该库的 `Client`、模型、查询输入类型和枚举。 |
| `metadata/`、`schemas/`、`engines/` | 模型元数据、内部标准 schema、生成实现与必要运行资产。 |
| `manifest.json` | 定义及模型指纹、产物文件清单和 SHA-256。 |

源码类型检查可以解析同目录的 `.ts`；运行时使用同名 `.js`，无需 TypeScript loader。用户只维护定义与模型文件，不编辑或提交生成目录。

```ts
import type { DatabaseClient } from "steamharness/database";
import { main, audit } from "./.steamharness/generated/database/node/index.js";
import type { User } from "./.steamharness/generated/database/node/main.js";

function listUsers(db: DatabaseClient<typeof main>) {
  return db.user.findMany({
    select: { email: true, posts: { select: { title: true } } },
  });
}

function listAudit(db: DatabaseClient<typeof audit>) {
  return db.user.findMany({ where: { event: "login" } });
}
```

模型也可通过 `Models.User`、`UserModel` 引用，枚举可通过 `Enums.Status` 引用，避免与封装类型同名。关系过滤、`select`、`include`、复合唯一键及返回值沿用底层模型类型推断。`Client` 只暴露模型操作和 `transaction(callback)` 的类型，生命周期、原始 SQL 与扩展接口不属于业务客户端。`Decimal`、`DbNull`、`JsonNull`、`AnyNull` 可从 `steamharness/database` 或对应别名模块导入。Browser 使用同样的模型类型，从 `browser/index.js` 引入描述符。

描述符包含 `alias`、`target`、`provider`、`schemaHash`、`metadata`，不建立连接。资源申请和迁移由下列管理命令完成。

## 申请独立数据库与授权

数据库资源按 UUID 隔离，每个资源在同一个 PostgreSQL 实例中拥有独立 database，以及迁移、只读、读写角色。A、B 项目分别申请资源后，都可以定义 `User` 表；它们的结构和数据互不影响。申请发生在显式命令中，不会因为打开项目或新建对话自动建库。不同别名使用同一模型文件，也不自动共享资源。

先通过 `steamharness workspace login` 登录目标 Server 的账号。以下命令使用保存的账号 API Key；可用 `--server`、`--token` 显式指定目标，也支持 `STEAMHARNESS_SERVER_URL`、`STEAMHARNESS_SERVER_ADMIN_KEY`。仅有系统管理密钥而没有账号身份时会被拒绝。

```sh
pnpm exec steamharness database create orders --server http://127.0.0.1:18126
pnpm exec steamharness database list --server http://127.0.0.1:18126
pnpm exec steamharness database inspect <database-id> --server http://127.0.0.1:18126
pnpm exec steamharness database grant <database-id> --user <account-id> --mode read --server http://127.0.0.1:18126
pnpm exec steamharness database revoke <database-id> --user <account-id> --server http://127.0.0.1:18126
```

创建者是资源所有者和唯一迁移所有者。共享权限为 `read` 或 `write`，共享账号不能管理授权或迁移。撤销或收窄授权会撤销已签发连接身份并终止对应连接。资源查询仅返回当前账号拥有或获授权的资源，不返回数据库地址、角色密码或管理连接。

创建记录包含 `requested / provisioning / ready / failed` 状态及失败步骤。为创建指定稳定的 `--request-id <uuid>`，可在响应丢失后查询同一申请；同一账号、请求 ID 不会重复建库。失败使用 `database retry <database-id>` 继续原资源；CLI 遇到未就绪状态返回非零退出码。

## 生成与部署迁移

资源 ID 通过命令参数指定，不写入模型或数据库定义。`--alias` 选择项目中的模型声明，默认 `main`：

```sh
pnpm exec steamharness database migrate dev . --database <database-id> --alias main --name init --draft --server http://127.0.0.1:18126
pnpm exec steamharness database migrate deploy . --database <database-id> --alias main --server http://127.0.0.1:18126
pnpm exec steamharness database migrate status --database <database-id> --server http://127.0.0.1:18126
```

`migrate dev` 比较已应用历史与当前模型，保存迁移并更新生成产物；省略 `--draft` 时同时部署。`migrate deploy` 只应用已有迁移；存在未部署迁移时先部署，再生成下一次变更。迁移写在模型旁的 `migrations/<17位时间戳>_<名称>/`，包含 `migration.sql`、`steamharness.schema` 模型快照和 `steamharness.migration.json` 校验清单，需随项目源码提交。复用同一模型文件的别名复用这份迁移历史。

Server 使用临时影子数据库重放并校验每一步模型，再在目标库逐条以事务提交 SQL 和历史。已应用的历史不能遗漏、重排或修改；实时结构与历史模型不一致时拒绝继续。失败 SQL 回滚，已完成的前序迁移保留；修正数据条件后可用同一历史重试。重复部署不会重复执行已提交步骤，进程中断后通过库内历史恢复。

删除表、删除列或部分字段重写需要审阅 SQL，并显式增加 `--accept-data-loss`。SQL 支持模型表、枚举、索引及数据变更；事务、权限、过程代码和内部迁移历史由平台管理。迁移期间撤销已有业务连接，失败或中断后需成功重试部署才能重新签发连接。

资源、绑定与宿主连接 HTTP API 位于 `/api/databases`。

## 绑定入口并使用 Core 查询

先部署模型迁移，再为使用数据库的入口绑定资源：

```sh
pnpm exec steamharness database bind . --entry main --alias main --database <database-id> --server http://127.0.0.1:18126
pnpm exec steamharness database bindings . --entry main --server http://127.0.0.1:18126
pnpm exec steamharness database unbind . --entry main --alias main --server http://127.0.0.1:18126
```

目录指向含 `steamharness.json` 的聚合项目根；`--entry` 默认使用 `defaultEntry`。`bind` 在所选入口的 `root` 目录生成并检查模型，`--alias` 默认 `main`。同一聚合项目的不同入口可以分别将 `main` 绑定到不同资源；不同项目也可以各自定义 `User`。只有显式绑定同一个资源 UUID 才共享表和数据。

宿主按当前账号、`projectId + entryId + alias` 保存绑定，不修改项目文件。关系库别名由入口目录的 `steamharness.database.ts` 声明，入口 `steamharness.json.databases` 只列别名，不在 `config.json` 保存业务资源 ID。换账号、Server 或入口后需要各自绑定。绑定只选择当前账号已经拥有权限的资源，不能授予权限；默认继承账号的读写能力，`--mode read` 可以进一步限制为只读，不能提升账号权限。

Node 工作流在运行上下文中连接生成的描述符：

```ts
import { main } from "./.steamharness/generated/database/node/index.js";
import type { RunContext } from "steamharness";

export async function createUser(context: RunContext) {
  const db = await context.databases.connect(main);
  return db.transaction(async tx => {
    const user = await tx.user.create({ data: { email: "alice@example.test" } });
    await tx.post.create({ data: { title: "Hello", authorId: user.id } });
    return user;
  });
}
```

返回值保留模型的查询与结果推断。客户端只提供模型 CRUD、关系查询、聚合和 `transaction(callback)`；没有原始 SQL、引擎扩展或关闭连接方法。事务回调抛错、查询失败、授权变化或取消时回滚；回调结束后不能继续使用该事务对象。连接池每个客户端最多 2 条连接，单条 SQL 和事务限时 30 秒，事务等候连接最多 5 秒。不要在事务中等待用户输入或长时间调用外部服务。

每次模型操作与事务提交前都重新校验宿主绑定、账号授权和模型指纹。缺少绑定返回 `DATABASE_UNBOUND`；模型与已部署迁移不一致返回 `DATABASE_SCHEMA_MISMATCH`。变更或解除绑定会终止旧连接，旧客户端返回 `DATABASE_BINDING_CHANGED`，必须显式重新 `connect()`。撤销或收窄账号授权会终止对应 SQL 会话；已撤销的客户端不会自动重新获取权限。查询错误使用 `DATABASE_QUERY_FAILED`，约束等已知错误附带 `queryCode`，例如 `P2002`，不会把连接串或底层调用内容写入报告。

默认 SQL 身份有效期为 5 分钟，到期前在后续操作时续期，保留原绑定身份；不会自动重放已发送的查询或事务。Core 在执行成功、失败、等待输入或取消时释放运行持有的连接；网络中断时停止操作，不回退本地 KV；未能通知 Server 释放的临时身份由过期清理回收。使用关系库需要连通本地 Server 和本地 PostgreSQL。

自定义 Node 宿主可从 `steamharness` 导入 `createRemoteRelationalDatabaseHost` 和 `createDatabaseConnector`，提供账号 API Key、项目和入口身份；结束时必须 `await connector.close()`。账号密钥和临时 SQL 凭据只在可信宿主保留，不传入项目参数、模型输入或 Browser。签发 SQL 凭据的 HTTP 接口仅接受账号 Bearer API Key，拒绝 Cookie 会话和带 Origin 的浏览器请求。

## Browser 表客户端

静态页面从生成的 `browser/index.js` 导入描述符，构建时打包，通过宿主连接：

```ts
import { data } from "./.steamharness/generated/database/browser/index.js";
const db = await window.steamHarnessKanban.databases.connect(data);
const page = await db.task.rows({ where: { configurationId: "default" }, orderBy: { id: "asc" }, page: 1, pageSize: 50 });
const row = await db.task.insert({ id: crypto.randomUUID(), configurationId: "default", title: "First", status: "todo" });
await db.task.update({ key: { id: row.values.id }, rowVersion: row.rowVersion, data: { title: "Changed" } });
await db.task.delete({ key: { id: row.values.id }, rowVersion: row.rowVersion });
```

入口必须声明 `databases: ["data"]` 并完成资源迁移与账号绑定。页面只传描述符、模型和结构化请求；账号密钥、SQL 凭据和数据库连接串保留在可信宿主。每次查询重新检查绑定 ID、版本、账号授权与 schemaHash；旧客户端在绑定或授权变化后失效。Browser 仅提供表级 `rows/insert/update/delete`，不提供 Node 的关系查询或事务。行更新与删除必须携带完整键与 rowVersion，冲突保留草稿并要求重新读取。

看板模板先执行 `database generate` 再构建 `dist/index.html`。任务保存在 `Task` 行中，并按 configurationId 过滤。未绑定、断连或读取失败会显示错误并禁止编辑，不切换临时本地模式。旧 KV、PersistentValue、本地 KV 和 KV 工具已移除，不自动迁移旧数据。

## 构建与分发

自定义构建应先执行 `database generate`，再运行 TypeScript 或前端构建。`workspace pack` 会为聚合根目录和各注册入口目录中的定义自动生成产物，并将源码、模型与完整生成目录一起打包。`.gitignore` 仅控制 Git；不要在 `.steamharnessignore` 中排除这些必需文件。

Server 只读取静态清单、源文件指纹及产物哈希，不执行项目定义文件。下载时同样检查清单和哈希，失败不留下半份项目。只有 `.steamharness/generated/database` 可以进入源码包，其余 `.steamharness` 运行数据继续排除。

本入口定义项目业务模型；[平台运行存储](/core-api/runtime-storage) 负责会话、运行历史和 Agent 记录，二者独立管理。声明业务模型不会自动转换现有 KV 数据。

## Server Web 表数据管理

数据库目录支持服务端分页、搜索和显式创建。资源详情提供账号授权、入口绑定、已应用模型及表行管理；Studio 和 CLI Web 的浏览操作打开该页面。行读取支持分页、字面文本搜索和标量等值过滤，修改与删除需完整稳定键和 rowVersion，schemaHash 变化后重新加载模型。冲突保留草稿。

JSON 数据中 BigInt 和 Decimal 用字符串无损传输，DateTime 为 ISO，Bytes 为 Base64，列表和 JSON 保留结构。数据库默认值及 @updatedAt 可自动应用；cuid()/uuid() 等由模型客户端生成的默认值在管理端 SQL 新增时须显式填写。此结构化表管理接口与 Browser 表客户端使用同样的请求边界，不提供关联写入、原始 SQL 或 Browser 事务。知识库使用独立的 [知识库 API](/core-api/knowledge-documents)。
