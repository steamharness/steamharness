# 用户设置与权限继承

用户设置属于执行宿主，与项目配置和每轮参数分别保存。Studio 在 **设置 → 权限** 保存用户的 Agent 权限，默认 `auto`。工作区设置不能覆盖该值。普通 Agent 仍默认 `workspace`；只有显式选择 `inherit` 才读取用户设置。

## 公开接口

```ts
interface UserSettings {
  readonly agent: {
    readonly permissionPolicy: AgentPermissionPolicy;
    readonly models?: readonly Readonly<UserAgentModel>[];
  };
}

type AgentPermissionPolicy = "read-only" | "workspace" | "auto";
type AgentPermissionPolicySetting = AgentPermissionPolicy | "inherit";

getUserSettings(): UserSettings;
parseUserSettings(value: unknown): UserSettings;
withUserSettings<T>(settings: UserSettings, run: () => T): T;
```

项目通过注入的 `steamharness.getUserSettings()` 读取当前执行的设置。宿主可以从 `steamharness` 包导入上述接口；`parseUserSettings` 与 `withUserSettings` 用于宿主注入，不加入项目运行时命名空间。

`getUserSettings()` 返回复制并深冻结的快照。没有宿主时返回 `{ agent: { permissionPolicy: "auto" } }`。`parseUserSettings` 和 `withUserSettings` 只接受三个具体权限值；缺少字段、`inherit` 或其它非法值抛出 `TypeError`。宿主传入对象后再修改它，不会改变已启动任务。

```ts
// 项目代码：读取快照，或让 Core 解析继承。
const settings = steamharness.getUserSettings();
const agent = await steamharness.createAgent({ permissionPolicy: "inherit" });
try {
  for await (const event of agent.run({ errCode: 0, errMessage: "", prompt: "检查项目", permissionPolicy: "inherit" })) {
    // 处理事件。
  }
} finally {
  await agent.close();
}
```

```ts
// 宿主代码：异步任务及其后代共享这一份快照，并发执行互不覆盖。
import { withUserSettings } from "steamharness";

await withUserSettings({ agent: { permissionPolicy: "read-only" } }, async () => {
  await runProject(); // 宿主自己的运行入口。
});
```

## 解析顺序

Core 先选本轮 `AgentInput.permissionPolicy`，再选开发者的运行时／节点 `permissionPolicy`；两处都未填写时使用 `workspace`。选中的值为 `inherit` 时，解析为当前用户快照中的具体值；无宿主时解析为 `auto`。直接调用 Agent、Agent 节点和项目参数使用相同规则。

直接调用仍可传入 `--permission-policy inherit`。参数表单通过空覆盖值保存继承关系，只有显式项目选择才保存具体值；不会将显示的系统权限写成覆盖。底层工具筛选、文件范围和运行时初始化只接收解析后的三个具体值。各模式的工具、路径及 shell 行为见 [createAgent 权限策略](/core-api/create-agent#权限策略)。

## 参数展示方式

开发者通过 `ParamDefinition.userSetting` 选择项目如何使用用户配置。支持单个 string 字段绑定 `key: "agent.permissionPolicy"` 或 `key: "agent.model"`。

- `mode: "fixed"`：只显示系统当前权限，点击打开 Studio 用户设置；忽略项目覆盖及旧会话保存的具体值。
- `mode: "default"`（省略 mode 时采用）：保留三个原始选项，以用户配置为默认选中值；手动选择后成为项目覆盖，重置恢复跟随当前用户配置。

绑定必须内联声明，不要同时填写 `defaultValue`；不支持多值、checkboxes、Mode 或 Slash 字段。`paramValues` 接收执行快照中解析出的有效值。

```ts
params: [{
  kind: "quick", id: "permission", label: "Permission", icon: "shield",
  summary: ["permissionPolicy"],
  fields: [{
    name: "permissionPolicy", flag: "--permission-policy", type: "string",
    control: "select",
    userSetting: { key: "agent.permissionPolicy", mode: "fixed" },
    options: [
      { value: "read-only", label: "Read only" },
      { value: "workspace", label: "Workspace" },
      { value: "auto", label: "Auto approve" },
    ],
  }],
}],
createInput({ paramValues }) {
  return { errCode: 0, errMessage: "", permissionPolicy: paramValues.permissionPolicy };
}
```

将示例改为 `mode: "default"` 即可允许项目单独覆盖。`createAgentProjectParams({ permissionPolicy: "inherit" })` 自动生成该可覆盖绑定。独立 CLI 可以解析宿主注入值，打开用户设置页需要 Studio 宿主。

## 用户模型与免配置 Agent

在 **设置 → 模型** 添加、编辑、删除模型，并将任意模型设为默认。模型属于用户，跨工作区生效；名称、协议、Base URL、模型 ID 和 API 密钥通过宿主传入运行时。三方密钥保存在 Studio SecretStorage，不进入项目配置、页面状态、普通会话历史或导出。编辑已有三方模型时，密钥留空会保留原密钥。

开源 Studio 仅提供三方自定义来源，支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。提供系统 AI 的宿主还可展示已授权的系统模型目录；保存的是凭据 ID 与模型 ID，执行时重新检查当前账号的授权与模型可用性，不保存系统代理令牌。

`UserAgentModel` 是以下两类记录的联合，每条记录都有稳定的 `id`、显示名称 `name` 和实际模型 ID `model`：

- 系统模型：`{ source: "system", credentialId: string }`。
- 三方模型：`{ source: "third-party", apiKind: "openai-completions" | "openai-responses" | "anthropic-messages", baseUrl: string, apiKey: string }`。

模型列表会复制并冻结。Base URL 必须是 HTTP(S) 地址，不含认证、查询或片段；模型 ID 必须唯一，最多保存 100 条。非法模型配置会被拒绝。

当用户列表非空时，Core Agent 节点与直接 `createAgent()` 可自动使用第一个允许的模型；本轮 `model` 可以指定列表中的 ID。显式开发者 endpoint、`models` 或 `resolvedModel` 保持原方式。`modelSource: "user-settings"` 明确只使用用户模型，列表为空时提示添加模型；`modelSource: "project"` 明确保留旧项目配置来源。项目的 `allowThirdParty: false` 对用户模型和显式端点同样生效，不会被用户设置绕过。

```ts
// 自动生成可覆盖的模型参数，列表和默认值来自用户设置。
const project = steamharness.createAgentConversationProject({
  modelSource: "user-settings",
  permissionPolicy: "inherit",
});

// 自定义参数入口仍可内联声明：
// userSetting: { key: "agent.model", mode: "default" }
// resolveParams: steamharness.createAgentProjectParamResolver({ modelSource: "user-settings" })
```

`createAgentProjectParams()` 默认也生成用户模型绑定；自动选用用户模型时，解析器保留空覆盖标记，后续修改默认模型仍会生效。显式传入 `modelSource: "project"` 才生成原项目模型控件。模型 ID `inherit` 按普通 ID 处理，权限继承仍使用 `permissionPolicy: "inherit"`。

复用模型连接时，三方连接保留开发者的 `modelAttributes` 默认值；系统模型目录声明的搜索能力限制仍然有效，不能用本轮属性覆盖放开。

小助手使用用户模型列表。点击模型入口先展示可用模型，**管理模型** 再打开设置；手动选择模型作为当前项目／会话覆盖，重置后恢复用户默认值。原项目模型配置 API 继续保留，小助手不使用其中的模型。

自定义模型字段使用 `mode: "fixed"` 时也先展示列表，列表只读，通过 **管理模型** 修改用户默认值；`mode: "default"` 允许在项目中选择覆盖。

模型设置变化只影响安全边界后的任务。正在执行的任务及后台工作保留原连接快照。直接创建并由宿主解析模型的 Agent，其继承权限也使用同一份创建时快照；本轮显式权限继续优先。需要采用新的宿主模型设置时，结束原任务后重新创建 Agent。中断恢复从宿主补充同一模型与同一端点的密钥；已移除或改变端点的模型会明确失败，不会把新密钥发到旧地址。

## Studio 与 CLI 会话

Studio 内置小助手使用固定用户设置绑定。权限入口直接显示实际策略（例如 **自动批准**），点击打开 **设置 → 权限**，不增加“继承用户设置”选项；固定绑定不受已保存的会话覆盖值影响。编码工具、提示词和 Studio Control 使用同一设置快照。

修改用户设置后，正在运行的任务、后台工作和子任务保留原快照。持久会话等所有工作结束且会话空闲后，重挂载原数据库并采用最新设置；新输入等待该边界，保留历史、队列和请求标识。中断恢复先使用记录的启动快照完成原任务。

CLI Web 接受宿主初始设置及能力握手后的更新。旧 CLI 不接收更新消息；需要此能力时更新项目的 Core 和 CLI。独立 CLI 本期不保存此设置；未注入时 `inherit` 使用 `auto`。
