# Agent 错误与重试

模型失败使用同一套有界重试规则，不按 HTTP 状态、供应商或错误文案决定是否重试。用户主动停止立即结束重试。

## 错误类型

| 情况 | 错误类型 | 说明 |
| --- | --- | --- |
| 缺少模型配置 | `input_validation` | 未提供 `model`，且没有可用的 provider 默认模型。 |
| 模型属性非法 | `input_validation` | JSON 形式的属性含未知键、类型不符或越界取值；不会静默丢弃该字段。 |
| 等待用户批准 | `user_input_required` | 运行暂停，宿主需要通过用户输入恢复。 |
| 压缩摘要为空 | 普通 `Error` | 模型没有产出可用的摘要。 |
| 同一运行时并发调用 `run()` | `execution` | 拒绝新调用，保留正在执行的请求、工具和观察器。 |

普通 Agent 应等待当前 `run()` 结束后再调用。持久会话运行中提交新输入时，使用[会话控制](/core-api/agent/sessions)排队或引导当前运行。

## 重试与续写

| 情况 | 处理 |
| --- | --- |
| 尚无输出的模型错误 | 最多 10 次额外请求，指数退避，单次等待最多 8 秒 |
| 已有部分正文后中断 | 保留已提交文字与工具结果，由持久运行继续；最多 10 次连接恢复 |
| 输出达到 `max_output_tokens` | 保留正文并续写，独立预算最多 2 次；耗尽后提示调整 `maxTokens` 或拆分请求 |
| 声明了工具调用却无工具块 | `lost-call` 续写，与连接恢复共用预算 |
| 用户主动停止 | 同时中断模型、工具和退避，不自动续跑 |
| 运行配置授权校验失败（`CONFIGURATION_FORBIDDEN`） | 重新读取当前权限并校验原配置，最多额外重试 10 次，指数退避，单次等待最多 8 秒；校验成功前不发送模型请求或执行工具 |
| 其他存储、工具权限、配置或宿主回调错误 | 直接报告，不作为模型错误重试 |

同步创建、流迭代、结果获取、摘要请求和延迟响应中的模型错误都在调用边界处理。错误保留上游原因及有限的 `code`、`status`、`statusCode`、`cause`，不序列化请求头或完整请求响应对象。

`This run configuration is not available to this account.` 使用配置授权重试预算，与模型请求和子工作重试分别计数。每次重新校验都使用原配置快照；权限恢复后继续原任务，持续拒绝时报告 `configuration_error` 和原错误。

同一输入的预算耗尽后不因进入下一个工具或请求边界再次校验。用户停止会中断等待，重试不会放宽权限或重放已完成工具。

## 保留哪些内容

已提交的正文、思考片段和工具结果继续使用。失败响应中未完成的工具调用不会执行。重试不能证明外部写入失败；未知副作用需先核对业务回执。

每次尝试都保留实际用量。完整成功的模型请求会重置连续失败计数；部分输出或重新打开未完成运行不会重置预算，历史中的重试记录也不会被新编号覆盖。

## 事件与界面

`retry.kind` 区分 `dropped`、`recovery`、`length`、`lost-call` 和 `configuration`，`attempt` 与 `maxAttempts` 描述对应预算。配置重校验有独立文案；CLI Web 与 Studio 在正文中显示网络重试，其他续写及配置校验保留在 Trace 与导出中。

超过预算后显示最终失败原因。失败与取消保留待发输入，只有成功的用户轮次才继续推进队列。

后台进度与完成报告不会恢复失败的父轮次。项目用 [submitAgentNotification](/core-api/agent/work-queue) 保存通知，明确继续时再读取结果，避免持续故障期间反复启动同一任务。
