# createAgent

用 `steamharness.createAgent()` 创建可编程调用的 Agent，提交 prompt 并处理事件。运行时负责模型与工具循环，支持思考强度、上下文压缩、计划审批和持久会话。

运行时使用 Pi Durable 1.2.0 作为唯一执行后端，要求 Node.js `>=22.19.0`。

Core Agent 内置 [i-have-adhd](https://github.com/ayghri/i-have-adhd) 沟通技能，完整指南随包分发，并在每轮系统提示词中直接加载，无需安装、执行 `/i-have-adhd` 或配置 `skill` 工具。默认回答行动优先、分步简短、减少旁支；普通模式、plan 模式、自定义 `systemPrompt` 和持久会话都适用。用户的语言、格式和详细解释要求优先，也可以说 `stop adhd mode` 或 `normal mode` 停用这种风格。技能只调整表达方式，执行任务、plan 模式与工具权限继续遵守各自约束。

## 示例

```ts
const agent = await steamharness.createAgent({ workdir: ".", provider: "anthropic", effort: "high" });

for await (const event of agent.run({ prompt: "总结这个仓库", errCode: 0, errMessage: "" })) {
  if (event.type === "text_delta") process.stdout.write(event.delta);
}
```

在 workflow 里跑完整流程时，用 [createAgentNode](./create-agent-node.mdx) 或 [defineBot](./define-bot.mdx) 会更省事。

## 签名

```ts
const agent = await steamharness.createAgent({
  storage?: AgentStorageFactory,
  workdir?: string,
  systemPrompt?: string,
  provider?: string,
  model?: string,
  baseUrl?: string,
  apiKey?: string,
  apiKind?: "openai-responses" | "anthropic-messages" | "openai-completions",
  webSearch?: boolean,
  modelAttributes?: AgentModelAttributes,
  effort?: AgentEffort,
  permissionPolicy?: AgentPermissionPolicySetting,
  mode?: AgentMode,
  tools?: string[],
  toolDefinitions?: ToolPermissionDefinition[],
  allowedDirectories?: string[],
  extraTools?: AgentTool[],
  sessionId?: string,
  session?: AgentSessionOptions,
  models?: MutableModels,
  resolvedModel?: Model<Api>,
}): Promise<AgentRuntime>
```

返回的运行时提供：

| 成员 | 说明 |
| --- | --- |
| `run(input, host?)` | 执行一次运行，逐条产出 `AgentStreamEvent`。 |
| `close()` | 关闭 Harness 并释放拥有者锁；未完成工作保留，供同一存储的下次运行恢复。使用完必须调用。 |
| `getContextUsage()` | 读取当前上下文占用 `{ used, total }`，包含仍在流式生成的消息；模型窗口不可用时返回 `undefined`。 |
| `updateContextUsage({ used, total })` | 提交当前上下文的绝对测量值；运行中的 `context_usage` 事件立即发送该更新，不计入计费用量。 |
| `sessionId` | 本次运行使用的会话 id。 |
| `reset()` | 清空上下文投影，下一轮提交新的模型上下文；须先结束所有活动任务。 |
| `restoreTranscript(messages)` | 指定下一轮从哪段记录接着跑；只在运行时还没建起 agent 时生效，见「上下文记录」。 |
| `readTranscript()` | 读取模型可见上下文的投影，供检查或导出。执行历史以 Harness 存储为准。 |

## 选项

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `storage` | `AgentStorageFactory` | 显式注入的独占后端工厂；本地持久化可使用运行存储提供的 `agentStorage(...)`。 |
| `session` | `AgentSessionOptions` | 启用持久输入、任务/计划快照和后台执行，见下方。 |
| `workdir` | `string` | 工具解析相对路径的目录，默认 `process.cwd()`。 |
| `systemPrompt` | `string` | 覆盖默认角色提示词；运行时仍附加内置沟通技能。 |
| `provider` / `model` | `string` | 模型提供方与模型 id；自建端点需要同时提供 `baseUrl`。 |
| `baseUrl` / `apiKey` | `string` | 自建网关或兼容端点的地址与密钥；缺省时从对应环境变量读取。 |
| `modelAttributes` | `AgentModelAttributes` | 自建端点上该模型的属性声明，见下方「模型属性」。 |
| `apiKind` | `string` | 自建端点的请求协议；OpenAI 原生搜索须用 `openai-responses`。 |
| `webSearch` | `boolean` | 默认跟随模型的搜索能力；`false` 关闭，`true` 显式开启。见下方「联网搜索」。 |
| `effort` | `AgentEffort` | 默认思考强度。 |
| `permissionPolicy` | `AgentPermissionPolicySetting` | 默认权限策略。 |
| `mode` | `AgentMode` | 默认运行模式。 |
| `tools` | `string[]` | 收紧可用工具；不能放宽策略已经禁用的工具。 |
| `allowedDirectories` | `string[]` | 允许读写根目录，默认只有 `workdir`。 |
| `extraTools` | `AgentTool[]` | 内置工具之外再加的工具，见下方「自带工具」。 |
| `models` / `resolvedModel` | pi 类型 | 需要复用自建 provider 集合或直接指定模型时使用。 |

通过 Server 与 PostgreSQL 保存 Agent 记录时，注入 [`createServerAgentStorage`](/core-api/runtime-storage)。

## 输入（`AgentInput`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `prompt` | `string` | 本轮输入。本轮带图片时可以为空字符串：一轮只有附件的运行是合法的一轮，运行时会把图片本身作为消息内容发出去，而不是先报「缺少 prompt」。 |
| `requestId` | `string` | 逻辑提交身份。同一输入的恢复、重发使用原值；真正的新输入使用新值。同一存储内重复提交返回原提交，不再次调用模型或工具。 |
| `images` | `AgentImageInput[]` | `{ data, mimeType }` 形式的图片。 |
| `imageFiles` | `FileReference[]` | 宿主文件引用形式的附件，由运行时的输入节点通过工作流文件存储解析。不可读或不是图片的引用会让本轮以命名到具体文件的错误结束，而不是静默丢掉附件。解析后它会变成 `images`，下游看不到引用这一步。 |
| `modelAttributes` | `AgentModelAttributes` | 覆盖运行时选项里的同名项，见下方「模型属性」。 |
| `webSearch` | `boolean` | 默认跟随模型的搜索能力；`false` 关闭，`true` 显式开启。见下方「联网搜索」。 |
| `workdir` | `string` | 覆盖运行时的工作目录。 |
| `allowedDirectories` | `string[]` | 覆盖工具可访问的根目录；相对路径按本轮的 `workdir` 解析，省略时只有 `workdir`。 |
| `systemPrompt` | `string` | 本轮的系统提示词，逐轮生效并覆盖运行时选项里的同名项。 |
| `provider` / `model` / `baseUrl` | `string` | 覆盖运行时的模型配置。 |
| `effort` | `AgentEffort` | 见下方「思考强度」。 |
| `agent` | `"build" \| "plan"` | `build` 直接执行，`plan` 只调研并给出计划。 |
| `permissionPolicy` | `"read-only" \| "workspace" \| "auto" \| "inherit"` | 见下方「权限策略」。 |
| `contextWindow` | `number` | 上下文用量分母。缺省时取模型声明的窗口，没有声明时使用运行时兜底窗口。 |
| `compact` | `boolean` | 为 `true` 时把本轮变成一次上下文压缩。 |
| `hostInput` | `unknown` | 本轮由宿主输入驱动（OpenAI / Responses 网关）；带它的一轮不写 workflow conversation，也不读不写上下文记录。 |
| `planResume` / `askResume` | 审批或问答恢复载荷 | 编程式宿主提供计划决定或用户回答；节点宿主通过 `userInput` 提交原请求的答案。 |

## 事件

`run()` 逐条产出以下事件：

| 事件 | 说明 |
| --- | --- |
| `text_delta` | 回答正文增量。 |
| `thinking_delta` | 推理内容增量。 |
| `tool` | 工具调用的 start / update / end。 |
| `web_search` | 原生搜索活动快照，包含 `search: { id, status, query?, sources, error? }`。 |
| `sources` | 本次 assistant 响应返回的来源，包含 `sources: { url, title?, citedText? }[]`。 |
| `plan` | plan 正文的 start / end。 |
| `compaction` | 压缩的 start / end，结束事件会带上摘要。 |
| `retry` | 回答中途断流、撞上模型输出上限、或工具调用丢失后继续本轮的尝试，带上 `attempt` / `maxAttempts` / `reason` / `kind`（`dropped` / `length` / `lost-call`）。 |
| `context_usage` | 运行开始、流式消息、工具结果和压缩后的当前上下文占用。 |
| `approval` | plan 审批结果。 |

## 宿主钩子（`AgentHost`）

不传 `host` 时不会发生任何暂停。传入后可以接管：

| 钩子 | 说明 |
| --- | --- |
| `approveToolCall(input)` | 返回即放行；抛错即拒绝，错误信息会作为工具错误回给模型。抛 `user_input_required` 则暂停运行。 |
| `approvePlan(input)` | 请求计划批准；抛 `user_input_required` 则暂停运行。 |
| `reportUsage(usage)` | 提交模型响应后上报用量，含稳定 `recordId`；宿主应按它 upsert，恢复可能重放同一记录。返回 Promise 时等待完成。仅计入实际返回 usage 的尝试，强杀前尚未返回的上游用量无法推算。 |
| `abortSignal` | 中断运行。 |

### 实时上下文

`run()` 在请求模型前就发送 `context_usage`，因此首次对话开始即可展示圆环。消息的正文、reasoning、工具调用参数和工具结果进入上下文时会更新占用；流式增量最多每 100 毫秒发送一次，消息结束与压缩后的更新立即发送。失败或取消也会保留已经产生的更新。

与 Pi 的上下文估算方式一致，Core 优先使用最近一次有效模型响应的 usage（包含缓存 token），再加上后续消息的估算值；不把多次请求的计费用量相加作为上下文大小。没有有效 usage 时估算实际上下文中的系统提示、命名提示段、工具定义和消息文本，CJK 按字符计，图片使用近似值。压缩后保留的旧响应不再参与校准，恢复记录后也遵循此规则。

程序可以在流式运行期间查询 `agent.getContextUsage()`。外部计量器获得更准确的当前用量时，调用 `agent.updateContextUsage({ used, total })`；`used` 必须是非负有限数，`total` 必须是正有限数。后续估算在这个测量值上增长，直到有效模型 usage 或实际压缩重新校准；`total` 不修改模型配置，下次模型校准使用本轮 `contextWindow` 或模型窗口。`reset()` 同时清除该测量值和恢复记录。

节点自动把这些事件转换成 [标准圆环输出](./create-agent-node.mdx)，宿主无需额外读取 Agent 字段。仅需计算一份 transcript 的上下文大小时，也可以使用 `steamharness/agent` 导出的 `estimateAgentContextTokens(messages)`。
