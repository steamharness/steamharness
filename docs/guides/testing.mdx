# 自动化测试

SteamHarness 的各仓库独立安装依赖并执行自己的质量门禁。默认测试以离线可复现为第一层保障，不连接生产 PostgreSQL、真实 OSS、LLM、GitLab、Electron 或远程服务器；Server 的 PostgreSQL 集成测试使用一次性的隔离 PostgreSQL 15 容器。真实环境验证应由对应仓库显式启用。

以下命令都从对应仓库根目录执行。所有仓库都维护 `dev`、`alpha`、`main` 三条分支，日常开发在 `dev` 上进行；分支差异不改变本地门禁，只有发布态的引用规则不同（见[兼容性](releases/compatibility.mdx)）。

## 测试分层

| 仓库 | 命令 | 用途 |
| --- | --- | --- |
| Core | `pnpm typecheck && pnpm test && pnpm test:scripts && pnpm coverage && pnpm build && pnpm test:agent-dist` | 检查 Core API、脚本、npm 构建和构建产物；普通测试覆盖运行时与最小临时夹具。 |
| CLI | `pnpm typecheck && pnpm test && pnpm test:scripts && pnpm coverage && pnpm build` | 检查本地 CLI 与 `steamharness workspace`。发布前再执行 `pnpm pack --pack-destination .release`。 |
| Studio | `npm run check && npm run build:extension` | 检查工作站扩展、类型和离线测试。 |
| Server | `pnpm typecheck:all && pnpm test && pnpm coverage && pnpm build:all` | 同时检查 Server API 与仓库内 `web/` 管理端。 |
| Shared | `pnpm typecheck && pnpm test && pnpm test:scripts && pnpm coverage && pnpm build` | 检查共享源码包和可供宿主同步的源码产物。 |
| Docs | `node scripts/validate-docs.mjs && node --test scripts/__tests__/*.test.mjs` | 检查双语导航、链接和 OpenAPI 内容。 |
| 每个内置项目 | `pnpm typecheck && pnpm test && pnpm coverage && pnpm build` | 独立检查 Bot、Codex、OpenCode、Developer Assistant。 |

## 给新代码补测试

- 修改 Core 仓库 `src/**` 时，优先补 Core 单元测试和 npm exports/pack 回归测试。
- 修改 Server 仓库 `src/**` 时，优先补 routes、storage、权限和错误码测试，并用 stub storage 保持离线。
- 修改 CLI 仓库 `src/**` 时，把参数解析、路径处理、输出格式和错误码拆成可 import helper，再补 Vitest。
- 修改 Server 仓库 `web/**` 时，覆盖 API client、路由、loading、empty、error、disabled 和关键组件交互。
- 修改 Shared 仓库 `run-workspace-input/**` 时，覆盖输入、conversation、附件、Markdown/output item、图片预览、Enter 发送、菜单、标题锁定和响应式状态。
- Core 节点与运行时行为使用 `src/__tests__/*.test.ts` 和 `node:test`，纳入常规测试及覆盖率；结构分析直接使用代码片段。
- 修改任一内置项目时，在该项目自己的 `__tests__/` 中覆盖入口参数、运行结果、错误路径和结构快照。

## 测试夹具

通用能力直接构造节点、Workflow 定义和内存上下文。等待与恢复、流式取消、知识库共享和授权必须有明确行为断言，不依赖实际业务工程。

加载器、入口发现、Kanban HTML、打包和 CLI 执行需要文件系统时，在系统临时目录生成最小清单与源码，测试结束后清理。使用现有夹具工具和仓库依赖，不保留常驻测试工程、独立 lockfile，也不为夹具执行安装。CLI 命令测试归 CLI 测试套件。

外部依赖默认 mock：LLM 使用测试 provider，文件输入使用临时内容；真实 SDK、远程服务或外部进程只能通过显式启用的专项测试验证。

## 跨仓改动

Shared 变化需要在 Shared 自身通过门禁后，再在实际消费它的 Server、Core 或 CLI 仓库执行对应门禁。Core API 变化还应验证 CLI、Server 和相关内置项目的消费者测试；CLI 变化应验证 Studio 与 CLI 的命令回归。每个仓库通过同级目录或提交的 `vendor/shared` 准备共享源码，但 CI 不依赖外层多仓目录存在。

真实 Server、数据库、LLM、Electron 窗口或浏览器验证只在明确启用时执行，不代替上述离线测试。若环境仍无法完成应跑门禁，应记录阻塞原因、影响范围和替代验证。
