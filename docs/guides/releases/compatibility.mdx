# 版本兼容性

项目在 `devDependencies.steamharness` 中固定精确 SemVer，用于记录开发和验证版本。运行时按 `major.minor` 比较兼容线。

## 判断是否兼容

| 声明 | 含义 |
| --- | --- |
| `0.2.7`、`0.2.7-20260826001` | 精确依赖声明示例 |
| `0.2.0`、`0.2.99`、`0.2.4-beta.1` | 同属 `0.2.x` 兼容线 |
| major 或 minor 不同 | 在用户模块执行前拒绝运行，并提示所需兼容线 |

patch 和预发布标识不用于兼容线先后比较。需要新兼容线的破坏性 API 变更应提升 minor，不能放入 patch。

## 本地运行与服务器存储

1. 安装项目声明的 Core 和 CLI。
2. Studio 从项目目录解析 CLI，并使用对应 Core 检查和运行。
3. CLI 核对实际 Core、自己的精确绑定和项目声明；不匹配时更新到已验证组合。

CLI 的 peer 范围限定同一 minor，例如 `>=0.2.0 <0.3.0`。`run`、`json`、`structure` 和 `resolve-params` 都执行兼容检查。

Server 只验证静态声明和源码快照；下载后仍由本地 CLI 检查运行兼容性。

## 内置项目快照

Studio 使用锁定的内置小助手快照，Studio Control 随同一聚合项目提供受权限控制的编辑器操作。两者共用身份、依赖和分发。

旧发布索引中的 `components.core`、`components.cli` 和 `minDesktopVersion` 保留为历史发行信息。Studio 源码启动方式见[安装与启动](/guides/studio/installation)。
