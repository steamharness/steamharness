# 管理项目配置

Workflow、Bot 和 Kanban 都支持配置字段与命名配置。先打开对应入口，再选择或编辑它的配置。

## 修改一次配置

1. 打开项目运行界面，选择目标入口。
2. 选择要使用的命名配置，修改允许编辑的字段。
3. 保存后开始下一次运行。

配置按项目和入口隔离。正在运行的任务使用启动时的快照，后续修改不会改变本次任务。

## 保存、导入与导出

Studio 与本地 CLI 共用本地存储；Server 按项目和账号隔离配置。官方模板和个人配置的可编辑字段由项目角色与模板规则决定。

配置支持完整导入、导出与 JSON 操作。发生版本冲突时先读取最新版本，再重新提交修改；不要把旧快照覆盖到新配置上。字段声明、附件和快照规则见[项目配置](/concepts/project-configuration)。

## 项目归属与身份

| 情况 | 处理方式 |
| --- | --- |
| 尚未注册项目身份 | 在运行界面申请应用 ID，完成注册后再上传 |
| 要在组内创建 | 使用具有开发者或更高角色的账号；创建不会自动提高组内角色 |
| 权限被撤销 | 重新取得授权后重试 |
| 重新申请了项目 ID | 为新身份重新授权并绑定数据资源 |

上传不会替已有项目改变归属。私有项目的版本分享链接可用于申请访客访问，详情见[项目管理](/guides/server/project-management)。

## 连接哪个 Server

在账号入口登录、验证或退出，通过 `studio.workflow.serverUrl` 选择 Server。凭据由 SecretStorage 保存，不写入项目源码。

dev 构建默认连接 `http://localhost:7126`，alpha 与 main 使用各自部署地址；你在设置或登录页明确选择的地址优先。CLI 的实际连接目标可用 [`workspace status`](/cli/workspace/status) 检查。
