# 上传、下载与版本

一个聚合项目对应一个版本、上传归档和安装目录。发布会包含全部注册入口；Server 保存静态源码，不安装依赖或执行项目。

## 上传并发布

1. 完成本地修改，更新根项目版本。
2. 安装依赖，构建 Kanban 等静态入口，再运行 `steamharness check .`。
3. 确认已登录正确的 Server，项目身份已注册且账号有发布权限。
4. 点击 **上传项目**，等待准备和发布完成，再到版本面板核对结果。

只想打包或分开执行上传、发布时，使用 [Workspace CLI](/cli/server-workspace)。版本快照不可变，同一版本不能重复发布。

## 下载版本

1. 打开 **版本**，选择目标项目版本，或从开始页进入下载。
2. 等待源码下载和校验完成。
3. 选择在当前窗口或新窗口打开。
4. 在项目终端安装依赖，并检查资源授权与入口绑定。

下载保留全部入口的相对路径，默认保存到用户目录下的 `Documents/steamharness-projects/<项目名>-<版本>`。目录重名时追加序号，不覆盖已有文件。

归档保留资源声明，但不携带宿主凭据和业务数据。关系库的账号绑定由 Server 管理，下载后需要用当前身份重新检查。源码下载本身也要求项目成员或已批准的访问权限。

## 导出运行内容

导出对话、单条消息或工作流记录时，Studio 打开原生保存窗口，默认位置是 Downloads。选定路径后，成功写入才会提示保存位置；取消不显示成功，写入失败会提示错误。

## 常见问题

| 问题 | 检查项 |
| --- | --- |
| 上传提示项目未注册 | 先在运行界面申请应用 ID |
| 版本已存在 | 更新项目版本后重新上传发布 |
| 下载后无法运行 | 安装依赖，检查入口文件和资源授权 |
| 数据库不可用 | 检查当前账号的资源授权、绑定及 Server/PostgreSQL 连通性 |

上传和下载需要 Node 扩展宿主。项目标签、最近项目和资源面板展示本地版本，版本面板用于查看服务器历史。
