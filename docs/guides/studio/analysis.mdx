# 查看本地运行统计

执行 **Workflow: 打开 Studio 分析**，或点击开始页的 **打开 Studio 分析**，查看本机项目和运行历史。

## 查看与筛选

| 区域 | 内容 |
| --- | --- |
| 总览 | 项目数量与类型、状态分布、近 14 天趋势 |
| 活动任务 | 运行中、等待输入和排队输入 |
| 结果统计 | 成功率与平均耗时 |
| 项目表、运行表 | 时间、类型、项目、状态筛选，搜索、分页和 CSV 导出 |

页面默认每 5 秒刷新，可以关闭自动刷新。成功率只使用所选时间范围内已结束的记录；未知、运行中和等待输入不进入分母。

## 统计哪些项目

统计包含当前工作区和 Studio 已导入的 Workflow、Bot、Kanban 项目，按目录与入口去重。未导入的磁盘目录不参与统计。

即使项目使用 Server 数据库，分析页也只读取本机运行历史。它不读取服务器任务，不监控 CPU、内存或远程 Runner。内置 `build-in-analysis` 也可以作为普通 Kanban 项目打开。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 实时活动状态 | 安装的 CLI 支持活动记录时，跨窗口同步 |
| 未知 | 旧 CLI 的历史无法确认当前运行状态 |
| 不可用 | 声明、权限、项目身份或历史读取出现错误 |

数据来自项目 CLI 的本地存储，读取失败不会填充示例数据。独立浏览器和没有 Studio 连接的 CLI 不提供此分析接口。

## 项目消失或读取失败

已导入目录被删除后，最近记录及导入登记会自动清理。目录不再含独立 `steamharness.json`，或变成另一个聚合项目的子入口时，不再单独计数。

当前工作区的目录缺失、清单损坏、权限错误、身份变化和历史读取失败仍显示为不可用，不影响其他项目计数。分析过程只读声明和历史，不解析部署绑定，也不迁移旧版 `package.json` 声明。
