# 全新聚合声明

当前模型要求全新声明和数据，不提供旧项目模型的兼容读取、自动迁移或数据导入。

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "name": "workspace-example",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "steamHarness": {
    "defaultEntry": "agent",
    "entries": [
      {
        "entryId": "agent",
        "type": "conversation",
        "name": "Assistant",
        "root": "agent",
        "entry": "index.ts",
        "databases": []
      },
      {
        "entryId": "database",
        "type": "workflow",
        "name": "Database operations",
        "root": "database",
        "entry": "index.ts",
        "configuration": "configuration.json",
        "databases": [
          {
            "alias": "data",
            "host": "server",
            "permissions": {
              "kv": {
                "read": {
                  "mode": "all"
                },
                "write": {
                  "mode": "all"
                }
              },
              "knowledge": {
                "read": {
                  "mode": "all"
                },
                "write": {
                  "mode": "all"
                }
              }
            }
          }
        ]
      },
      {
        "entryId": "map",
        "type": "kanban",
        "name": "Map",
        "root": "map",
        "entry": "dist/index.html",
        "databases": []
      }
    ]
  }
}
```

保留业务代码目录，将其注册到根 entries；移除子模块的 SteamHarness 身份。executor 的 `projectType` 仍描述该入口的运行契约，根 package 不声明单一类型。

用 `context.entries.get(entryId)` 调用聚合内 Workflow；用 `context.databases.get(alias)` 访问获批空间。每个入口分别申请新空间，需要共享时额外申请已有空间的访问授权。

删除旧项目身份的数据时只清理相应旧模型记录，不清空宿主其他业务数据。新项目不会读取旧数据。详见 [Workflow 模型](/concepts/workflow-model) 和 [数据库空间](/concepts/data-storage)。
