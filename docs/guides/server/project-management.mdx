# 项目管理

项目管理员可以在 Server Web 中管理成员、邀请、源码访问和相关项目。Server 只保存项目元数据、权限和版本快照，不执行上传的项目代码。

## 项目头像

项目列表、详情和设置使用 `projectCard.icon`、`iconColor` 和 `iconBackgroundColor` 展示头像。未提供头像的新项目使用项目类型图标，并随机生成和保存图标色与背景色，两种颜色的对比度至少为 4.5:1。刷新页面或重新绑定已有项目不会重新随机配色。

旧项目缺少头像时按项目类型展示默认图标和配色；`iconUrl` 仍可读取，但这些界面统一使用图标与配色。

点击项目列表的头像进入项目详情；详情中的头像可放大预览。成员、上传用户等位置的用户头像可打开当前可见的用户资料；账号菜单头像保留账号菜单入口，个人资料页头像可直接选择上传图片。弹窗支持键盘关闭并将焦点返回原入口。

## 成员与邀请

成员角色为 `owner`、`manager`、`writer` 和 `viewer`。角色决定项目设置、成员、版本和数据操作权限；源码下载权限与数据权限分别校验。

邀请链接只允许使用一次并在短期内有效。被邀请用户在接受页面设置密码；撤销邀请后链接立即失效。Server 不会替项目发送邮件。

## 源码与版本

上传任务会解包并做静态检查，失败时保留已有草稿和历史版本。发布会创建不可变版本快照并更新 `latest`；重复版本返回 `409`，不会覆盖现有版本。

源码下载需要项目的独立下载权限。版本归档不包含 KV、PersistentValue、SQLite、环境文件或 CLI 凭据。

## 关联项目

关联项目包含 alias、目标项目 UUID，以及对目标数据的读写授权。双方声明必须互相指向；规则支持 `none`、`all` 和 `prefixes`。撤销关系立即生效，不会递归转授权限。

关联写入同时检查消费方的数据写权限和目标方的写授权。源码下载和项目管理权限保持独立。

## 项目组与审计

项目组发布前会静态校验归档和哈希，并把依赖锁定到精确版本。下载时逐项目检查源码权限并返回跳过原因。

账号、权限、API Key、设备登录、上传、发布和数据管理会写入审计记录。读取审计日志需要 `audit.read`，凭据字段始终脱敏。

## 项目配置

字段可直接编辑，修改后统一保存；使用重置图标恢复默认值或清除未声明默认值的字段，无需额外勾选启用。

三种项目类型均支持字段、命名配置及完整导入导出。文件字段直接选择文件并上传到服务器项目文件存储；上传成功后保存引用，沿用项目文件写入权限。Studio 与本地 CLI 共用本地存储，Server 按项目和账号隔离。面板关闭时 Studio Control 仍能查询和管理配置。JSON 操作、版本检查和运行快照规则见[项目配置](/concepts/project-configuration)。
